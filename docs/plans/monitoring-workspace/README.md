## 本地使用

直接用桌面浏览器打开 `demo.html` 即可。页面使用本地 HTML/CSS/JS 和仓库共享 design tokens，不依赖 CDN、外部字体或业务 API。也可在仓库根目录启动 `python -m http.server 8766 --bind 127.0.0.1` 后访问 `/docs/plans/monitoring-workspace/demo.html`。

所有对象、数据、示例 Key、采集检测和 Kubernetes 操作均为明确标注的示例，只写入当前浏览器的 `argus.monitoring-workspace.demo.v3`。认证输入只在当前向导内暂存，密码、Token 和认证用户名不进入 localStorage、配置预览或审计；这里只模拟凭据托管元数据。主题和语言使用同一独立 key。底部“重置示例”恢复初始数据；顶部切换中文/英文、浅色/深色和管理员/应用只读视角。

正式组件仍应复用 `@argus/ui`；这里的 HTML 渲染辅助函数只用于独立原型，不作为第二套生产组件库。目录遵循[现有列表规范](../frontend-redesign/resource-lists-and-host-inventory.md)。新建类型选择器采用紧凑选项网格，业务实体目录仍为表格。

## 2026-10-18 新建流程调整

### 应用与服务选择

- 应用、服务选择统一使用列表弹框：名称/负责人或所属应用/环境等字段、搜索、分页、已选数量、取消和确认。多选跨页保留，搜索不清空选择。
- 业务 Trace 和业务日志选择单个应用及服务；其他服务监控可关联多个应用，并可选限定到具体服务。没有限定服务时表示关联整个应用。
- 选择不同应用后，清除不属于所选应用的服务。取消弹框或 Escape 不提交暂选结果，不丢失父表单的连接与认证草稿。
- 同一选择器复用到资源关联、仪表盘应用/服务过滤、日志/Trace 探索和 Kubernetes 创建资源的应用关联。示例目录提供 14 个应用展示分页，正式实现应使用服务端授权分页和搜索，避免把整个企业应用目录加载到浏览器。

### 环境自动归属

- 新建和编辑监控均不提供“生产/测试”选择。环境在应用/服务中维护，监控根据关联计算，不产生独立可编辑的环境副本。
- 指定服务时，使用服务的环境；仅关联应用时，使用该应用的环境集合。共享资源关联多个应用/环境时保留完整集合，不能任意选择第一个。
- 未关联应用的独立服务目标保持未关联环境，不默认生产，也不从执行 Collector 的环境推断目标环境。基础设施自身数据可沿用其所属主机/集群已有的环境元数据。
- 列表、配置预览、资源详情和仪表盘共用环境归属解析；查询应用 A 的某环境时，不借用同一共享资源关联应用 B 的环境扩大范围。
- 归属变化用于后续配置、候选和范围解析；正式数据面仍须保留观测时的归属/环境和版本，不回写历史。SDK Key 的绑定环境与其服务一致，变更应触发对应版本和授权失效机制。

### 自动建立监控对象

- 普通新建直接填写连接目标，系统随采集配置创建稳定的资源对象。删除原型中的“监控对象：新建/已有资源”下拉框。
- 已有资源需要增加采集内容时，从资源详情的“新增采集”进入，目标 ID 和地址自动带入并显示为固定上下文。编辑采集也保留原目标 ID，避免重复创建对象。
- 资源归属和 Collector 执行位置仍分别记录。凭地址相同不能擅自合并不同资源，正式重复目标识别应结合引擎、实例/Service、网络域与可信身份提示用户处理。

### 监控专用凭据

- 用户在新建监控内填写用户名/密码、Token，或选择无需认证/采集器运行身份。无需先到“凭据与密钥”创建，也无需选择 SecretRef。
- 正式实现继续复用现有加密存储、凭据代用/租约、权限和审计机制；内部保留 SecretRef，但自动以 `purpose=monitoring`、采集对象所有者和明确用途托管。
- 平台用途凭据和监控专用凭据是逻辑用途域，平台“凭据与密钥”默认目录不混入大量监控记录。隐藏目录不是权限边界，读取、代用、替换、撤销仍须服务端校验用途与归属，后台任务只能获取绑定目标的凭据。
- 编辑时显示已配置状态，留空沿用；输入完整认证信息则替换，切换无需认证或删除采集释放其专用关联。不能通过默认值、占位符或预览回显原始密码。
- 监控采集凭据与 SDK 上报 Key 分别管理：前者用于访问目标，后者用于应用向平台写入遥测。原型只保存托管状态，不实现或宣称已实现生产凭据存储。

原型模拟精确相同路径/工作负载的重叠检测。正式实现还必须处理通配路径、标签选择器覆盖、容器范围和多规则交集。原生 SkyWalking/Jaeger 的认证需要按协议实现适配，不能直接假设支持 OTLP 的 Header 配置。

## 拟议领域模型

1. `Application` 表示业务归属，包含负责人、环境和服务。环境不是新的租户边界，`enterprise_id` 继续是企业隔离边界。
2. `Service` 是稳定逻辑服务；运行实例由遥测或可信工作负载映射发现。不能用服务显示名合并不同应用/环境的服务。
3. `MonitoredResource` 表示数据库、中间件、主机、集群等稳定目标。应用使用资源是多对多依赖关系。执行 Collector 所在主机不代表目标所在主机。
4. `IntegrationDefinition` 声明配置 Schema、信号、版本/平台、运行依赖、目标基数、能力、默认查询/仪表盘与校验器。
5. `CollectionInstance` 绑定目标、执行者、范围、凭据引用、期望状态和版本；运行状态与最近样本是独立观测。
6. `TelemetrySource` 保留 Collector/Receiver 安装代次和配置版本等来源。它不能替代稳定的应用服务身份。
7. `IngestCredential` 绑定企业、应用、服务、环境与允许写入信号；地址可共享，凭据不授予读取和管理权限。轮换/撤销需要落实到接收链路与缓存失效。

业务 Trace/SDK 日志/业务文件与容器日志必须有应用及服务归属；系统/审计/组件日志归属基础设施。数据库运行日志归属数据库资源，应用关联可选。应用指标接入也应使用相同服务身份。

日志业务归属来自受控采集配置和工作负载映射。SDK 自报的应用 ID、名称或标签不能直接成为授权依据。主机/集群关联保留为部署和诊断维度；业务遥测按应用数据权限读取，基础设施和共享依赖数据单独授权。

关联应用只能支持归类和范围查询。精确日志/Trace 关联需要 Trace ID / Span ID；缺少 ID 时仅提供明确标识的同服务/实例时间范围检索。一条 Trace 可以包含不同应用的 Span，跨应用展开需再检查当前授权。

## 仪表盘筛选契约

### 层级与类型

`有效范围 = 当前企业与主体授权 ∩ 时间/环境 ∩ 应用与明确依赖 ∩ 显式目标集合 ∩ 类型/服务/对象条件 ∩ 来源能力 ∩ 面板局部条件`。

| 条件 | 语义 |
| --- | --- |
| 应用 | 默认应用自身服务；是否包含关联依赖由显式开关控制 |
| 服务 | 已登记服务 ID；依赖扩展需要服务与资源的明确关系，不能按名称猜测 |
| 资源类型/子类型 | 业务目标的语义类型；Receiver 名称另作来源维度 |
| 目标资源 | `all_authorized` 与显式 ID 集合是不同模式；空 ID 集合表示空范围 |
| 环境 | 从应用/服务关联推导；可以是多个环境或未关联。独立主机/集群自身数据沿用资源元数据；筛选不修改对象身份 |
| 集群/Namespace/工作负载/Pod | 集群授权下的对象维度；按稳定 UID/Owner 链解析。集群面板查询相应子集，外部数据库不因采集位置匹配而纳入 |
| 采集来源 | 集成、采集实例、来源安装代次和配置版本；停止采集仍可查看保留期内历史 |
| 面板局部条件 | 在全局授权与范围上继续收窄；不覆盖或扩大全局条件 |

### 多种服务模式

- 应用总览、数据库、主机、Kubernetes、混合面板可以共用范围解析器，但每个面板必须声明支持的资源类型、信号、来源和维度映射。
- Kubernetes 控制面指标通常是集群范围。Namespace/工作负载筛选不适用时应明确提示，不能偷偷忽略约束。节点/容器与工作负载面板需要正确解析下级对象。
- 共享数据库在应用页面展示的是共享实例状态，不能标为某应用独占用量。精确业务归因依赖额外测量。
- 执行 Collector 不参与默认业务对象筛选。“选择主机”不会自动包含它远程采集的所有数据库。
- 切换上层条件后，先前服务/目标不再匹配时保留可见提示与空结果，不能静默扩大范围。原型保留失配的显式目标选择。
- 区分未授权、条件为空、不适用、未配置、配置未生效、尚无样本、采集失败和已停采。正式 API 必须有明确状态，不使用 0 或演示值代替未观测。
- 查询执行冻结资源成员、来源版本、关系映射与授权版本；范围进入缓存 Key、查询指纹、导出和 Agent Workspace 来源。执行中撤权需在返回前复核。
- 应用页、资源页、Dashboard、告警和 Agent 工具使用同一解析器，避免前端选项存在但后端仍只支持 Host/Cluster。

### Grafana 适配

逐个集成建立“采集项 → 指标语义 → 查询 → 图表 → 默认告警”对应表。参考社区模板的布局、指标选择、变量和下钻，同时核对 exporter、指标名、标签、单位、Counter/Gauge、Histogram、Recording Rules 与版本。

Prometheus 格式抓取保留为内部接入能力，不单独成为监控目录里的服务类型；用户无需额外搭建 Prometheus Server。Grafana 模板中 LogQL/Tempo/厂商数据源的查询要分别映射到 Argus KQL/Trace 契约，不因为 UI 类似就引入另一套后端。

## Kubernetes 在线管理边界

这一部分扩展了现有资源查询与 Collector 生命周期能力，需要独立领域操作契约：

- 列表/watch、对象详情、事件、日志、YAML 读取使用统一集群访问适配器和受控字段投影。
- 创建/变更/删除应有服务端 dry-run、差异预览、目标 UID 与 resourceVersion 校验、幂等提交、执行状态及审计；不得依赖浏览器提供的 YAML 决定授权。
- 副本、滚动重启、回滚、Namespace/PVC 等分别建模。DaemonSet 的副本由节点调度决定。PVC 扩容不能等同缩容，删除需显示依赖和后果。
- `pods/log`、`pods/exec`、端口转发、Secret 查看等属于独立敏感动作；终端需要单独的短期会话/授权与审计。读取集群不自动获得这些动作。
- 当前基线的 Kubernetes 数据授权仍是 Cluster；Namespace 筛选不等于新增 Namespace 级授权。若要加入 Namespace 级 RBAC，需要另外确认并更新授权 ADR。
- 参考 KubeSphere 的资源信息架构与操作流程，不引入它的 Workspace/Project 租户体系，也不把“应用”混同于 Helm Release。
