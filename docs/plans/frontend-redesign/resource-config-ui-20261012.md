日期：2026-10-12。范围：用户提出的五项桌面门户调整。现有进行中的会话、主机清单、告警后端及其他改动保留。

## 采集能力与操作顺序

- 按 2026-10-13 用户补充要求，主机「组件与采集」按 Connector → OTLP 收集器排列。数据推送路由的「修改路由」「路由测试」进入 OTLP 收集器标题右侧的共享「…」菜单，选择后在弹窗中展示当前路由、测试结果或变更预览。删除独立的数据推送路由和生命周期操作卡片。
- 采集器升级、修复、卸载及主机卸载统一进入主机列表行末的共享「…」菜单，明确区分「卸载采集器」「卸载主机」。详情页不再提供生命周期或右上角卸载入口。菜单展开不生成预览，选中操作后读取当前采集器、Claims、路由和版本；变更继续由 PendingAction 预览与确认执行。
- 采集能力复用 `@argus/ui` 的 `SettingCard`：名称、描述、具有可访问名称和描述的开关；桌面三列展示。开关仍是草稿，配置通过 Diff → Preview → 用户确认提交。
- Kubernetes 卡片对应真实目录中的 `k8s-node-container`、`k8s-cluster`、`k8s-otlp-gateway`。节点指标和容器日志属于同一个 Profile，统一显示为「节点与容器采集」，不再提供提交后无效的独立日志开关。
- Kubernetes 草稿从该 Collector 的当前 Claims 推导，忽略其他 Collector、已释放和到期 Claims。关闭节点采集不再被固定的 `k8s-daemonset` 标记重新开启。至少保留一项采集能力；关闭整个 Collector 继续走卸载预览与确认。

## 主机与 Kubernetes 临时查询（历史布局）

2026-10-28 起，以下查询布局由 [Plan10 观测查询](../../plan10/README.md) 替代：主机和集群详情只提供跳转，三信号在 `/observe` 内使用独立资源范围的临时面板。采集配置、关联仪表盘、终端和 Pod 实时日志会话保留。

三信号统一复用仪表盘的 `QueryTargetEditor`、`TelemetryQueryEditor`、原生语言转换服务和 `ObservationPanel`。2026-10-13 按用户反馈调整为查询工具栏 → 查询条件 → 结果，主机与 Kubernetes 共用这一布局；Builder/DSL 条件位于结果上方，DOM 与键盘浏览顺序一致。条件使用内存状态，进入其他资源或离开页面后不会生成或保存 Dashboard 草稿、Revision 或发布操作。

点击执行时冻结查询定义、当前资源 ID、时间范围、步长和结果预算。指标支持区间/瞬时查询与自动/固定步长，日志支持检索与计数等现有聚合，链路使用现有 GraphQL 查询；结果可以切换图表、统计值或表格。Builder/DSL 必须无损转换，失败保留原文，不用浏览器近似解析代替正式 Go 编译器。

`convertDashboardPanel` 只处理请求中提供的查询定义，不读取遥测或写入业务配置。转换入口要求当前企业主体具备 `host.read`、`kubernetes.read`、`telemetry.dashboard.manage` 中至少一项能力；浏览器会话仍校验 CSRF。真正取数继续由原资源查询服务检查 Host/Cluster 读取能力、显式对象授权、来源和查询预算，并在返回前复核撤权。

指标目录和字段发现继续使用已有 `telemetry.dashboard.read` 门禁；无此权限时提供手工输入，并关闭目录发现。快速查询不暴露仪表盘变量、行参数或发布配置。指标候选读取使用当前资源与时间范围，不扩大为全部资源。

Mock 仅提供明确的简单指标、无过滤日志 records/count 与链路 list 转换夹具；其他原生查询转换交由真实服务。Mock 浏览器通过不代表真实遥测存储取数已验收。

## 告警策略

配置分为四个区块：

1. 名称与监控范围：策略名称、显式资源多选/全部已授权资源、多规则触发模式、说明。
2. 查询与告警条件：每条规则独立的简单构建器/高级 PromQL、比较、触发阈值、恢复阈值、单位、等级，以及只读规则试算。
3. 评估与恢复：评估间隔、触发持续时间、恢复持续时间；NoData/Error 处理放在可展开配置中。
4. 通知目标：渠道卡片、已有通知路由和策略标签。

复杂 PromQL 不能无损进入简单构建器时保留高级查询。试算结果绑定当时的策略定义，修改条件后不继续展示旧试算。默认通知渠道仍只在新建时预选；编辑、复制和取消预览后保留草稿。正式变更继续一次预览、一次用户确认，不改变领域、审计或通知执行边界。

交互参考 [Grafana 的查询、条件、评估、通知分区](https://grafana.com/docs/grafana/latest/alerting/alerting-rules/create-grafana-managed-rule/) 和 [Prometheus Alertmanager 的路由、分组与重复通知配置](https://prometheus.io/docs/alerting/latest/configuration/)，沿用 Argus 组件和主题。
