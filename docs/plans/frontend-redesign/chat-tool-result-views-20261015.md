# 会话工具结果：按需展开与业务视图

后续用户已确认工具分类与管理门户视图统一，且草稿只读、修改交给 AI。新实现与验收状态见[会话业务视图与管理门户统一](./chat-business-views-20261015.md)；本文“后续建议/未实现”描述的是最初的折叠宿主阶段。

## 本轮实现

根据 2026-10-15 用户提供的总览会话截图，先完成明确的宿主交互调整：

- 一次调用显示一个摘要入口；已绑定模板的工具记录不再与卡片标题重复展示。
- 默认收起，显示工具名称、状态、现有公开摘要和耗时，右侧“查看”；无业务摘要时保留状态，不解析任意对象凑出名称/条数。
- 点击才请求展示元数据并启动 iframe；收起销毁 iframe/MessageChannel，缓存仍由已有查询策略管理。重新打开相同 ToolCall/Attempt，刷新默认收起。
- 展开后使用主内容区宽度，上限 `--chat-result-width: 1600px`；正文和输入区保持原宽度。2026-10-16 后续调整取消原有 2000px 上限，所有展开内容随会话纵向滚动，宽表保留横向滚动；见[置顶摘要与滚动验收](./chat-summary-scroll-20261016.md)。
- 顶部/底部均可收起，底部收起后返回摘要按钮焦点；键盘 Enter 操作、加载占位、错误重试、双语和主题沿用共享控件。
- 参数及返回投影仍在次级调用详情。确认、审批和文件交付仍独立展示。

实现只修改显示投影和共享宿主，没有变更模板源码、历史 Hash、权限、读取协议或业务数据。本轮不将下面的业务视图建议记作已实现。

## 哪些调用值得提供业务视图

“绑定模板”不等于“每次自动展开”。保留可查看的结果，是否需要复杂视图由业务任务决定，避免用返回 JSON 的大小来判断。

| 工具类别 | 默认摘要中的理想事实 | 查看后的视图 |
| --- | --- | --- |
| 指标查询 | 资源/业务对象、指标、实际时间、返回序列数、部分结果标记 | 趋势、统计、图例和系列表；单点、聚合、未知单位明确区分 |
| 仪表盘查询结果 | 仪表盘名、实际条件、面板成功/失败数 | 冻结布局与全部现有图型；实际条件置顶、面板独立展开 |
| 主机/Kubernetes/Connector/Collector 列表 | 实际查询条件、已返回数量、截断/分页状态 | 共享列表工具栏、类型化列、状态、分页、名称详情入口 |
| 资源详情 | 名称、类型、状态、采集时间 | 概览与分区/标签页；资产、关联对象、采集及版本信息 |
| 告警事件/历史 | 级别、状态、实际范围、已返回条数 | 列表与事件详情；当时策略/规则、资源指标、触发依据和时间线 |
| 告警策略/通知/配置 | 名称、启用状态、返回条数 | 分别提供策略、渠道和通知结果字段，不能强行套事件表 |
| 日志/调用链 | 资源/服务、实际时间、匹配条数及限制 | 日志列表/行详情；调用摘要、瀑布/拓扑、Span 详情 |
| 仪表盘目录/草稿 | 名称、发布状态、定义/校验结果 | 目录表、定义摘要、校验问题；定义没有数据时不画假图 |
| 工具搜索/工具详情 | 类别、匹配数量/工具名 | 紧凑列表/说明，通常无需大图表或后台整页 |
| 预算、条件解析、运行状态、取消/恢复 | 结果或执行状态 | 紧凑步骤，默认不增加业务卡片 |
| 文件操作 | 文件名、大小、交付状态 | 复用文件交付入口 |
| 变更预览/操作状态 | 目标、影响、待确认/执行状态 | 差异与校验详情；宿主确认独立且不随折叠隐藏 |

目前摘要使用已有公开字符串和耗时；表中“理想事实”仍需工具提供方生成统一的轻量摘要契约，再由宿主通用展示。不能为了摘要而加载整个模板，也不能让门户按工具 ID 推导业务字段。名称、数量、单位和时间必须来自已授权的当次结果；“已返回 25 条”不替代未知的总数，历史事件不使用当前策略名称/规则覆盖快照。

## 复用管理后台的方式

可以复用列表和详情的视觉与业务字段定义。提取不依赖路由、全局页面状态或直接 API 请求的视图模块，模板负责业务编排；基础 DataTable、分页、状态、空态和图表继续进入 `@argus/ui` 并由 Runtime 预打包。管理后台通过正常 API adapter 供数，模板通过声明的只读 Bridge adapter 读取封存结果。

不直接嵌入整个后台页面：后台外壳、导航和实时增删改语义会与历史卡片冲突，也会破坏 iframe 的网络隔离。行内资源入口只使用授权引用，编辑/删除/提交仍进入既有预览与确认流程。

## 过滤必须表达作用范围

建议每个列表分开显示两层信息：

1. **本次查询条件**：只读条件标签，来自服务端实际生效参数。包括资源范围、时间/时区、级别/状态等；默认值也应展示，不能只显示模型传入字段。
2. **在本次结果中筛选**：用户交互的搜索、状态、级别、排序。筛选封存结果，不扩大查询和授权范围；清空只恢复这份结果。

例如原查询只返回“未恢复告警”，结果内筛选不能凭空得到已恢复告警；空态应写“本次结果无匹配”，并明确查看其他状态需要新查询。筛选后的条数、已返回条数、已知总数和业务截断分别展示，不能把已加载页数当作全局总量。

当前 `result.page` 只有封存集合和分片读取，不提供通用过滤。因此跨页过滤需要新增或扩展声明的只读操作，按模板数据类型白名单校验字段、操作符和排序；在整个授权封存集合上执行，游标绑定筛选/排序、主体、授权版本、Presentation、Attempt 和数据版本。不能在前端只过滤当前 25 条却声称过滤了全部结果。结果过大时应建立受控索引，不每次下载完整文件到浏览器。

改变原查询的时间、资源或超出封存结果的条件，继续由 AI 发起新查询、新卡片，旧结果保留。如后续提供“按这些条件重新查询”入口，它只产生明确的新查询意图，不能通过只读 Bridge 偷偷执行业务工具。

## 后续交互优化顺序

先将资源/告警/日志列表整理为“标题与概览 → 本次条件 → 结果内筛选 → 表格与分页 → 行详情”，长名称可展开完整查看，复杂列不强行压缩。详情采用概览加分区/标签页；指标突出趋势和实际时间，统计/系列明细按需查看；仪表盘保留冻结布局和面板状态。视图不应同时嵌套表格、面板、iframe 三层纵向滚动，宽表的横向滚动保留在表格自身。

随后补统一工具摘要契约和封存过滤能力，再逐组抽取管理后台/模板共享视图。与本轮宿主改造分开验收，不能因宿主已变宽就称所有业务模板已完成上述改造。
