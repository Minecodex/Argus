# 主机列表指标趋势与渐进加载

用户确认 2026-11-13：主机列表去掉“最近心跳”，“控制路径”移入详情；新增与 Kubernetes 资源列表相同风格的 CPU、内存、磁盘迷你曲线，异步读取。

## 展示与口径

- 保留名称/主机名、地址、连接状态/接入进度、环境、系统/架构、采集状态及原有 `…` 操作。列表不再展示控制路径或心跳；详情概要明确展示完整路径、连接方式和心跳。
- CPU 采用 hostmetrics 的整机汇总忙碌比例 `1 - avg(idle)`。汇总序列数量不能当成 CPU 核数，比例分母 1 表示整机 100%，不是一个核。没有历史实际核数时不伪造 mCPU/核数用量。
- 内存按实际 used / 各状态总容量计算，悬浮显示使用量、容量和使用率。不用 PostgreSQL 的当前资产快照容量填充历史分母。
- 磁盘读取各文件系统的 used / capacity，选定最新有效使用率最高的一项，并显示该项完整时间线。悬浮展示具体挂载点、设备、类型、使用量/容量；不将 bind mount 或同盘多挂载点相加，也不在每个时间点悄悄换盘。
- 默认最近 30 分钟、30 秒步长。比率参考线为 100%，缺少容量时只显示实际用量。用量或同时间分母缺失保留断点，不填零；真实零值正常画图。
- 实际采样时间用 PromQL `timestamp()` 独立返回，避免把查询评估时间冒充采样时间。超过 5 分钟的样本标为过期；不完整查询结果不画精确总量。
- Docker/共享内核环境按实际可见主机范围解释，容器内存上限不等于整机容量。无样本、无已授权来源、无权限、读取失败、过期、不完整分别展示。

## 数据与生命周期

沿用已有 `telemetry.queryMetricsRange`、已生成的 PromQL 契约、`host.read`、显式资源授权、固定 `hostmetrics` 来源及原查询预算，不新增后端接口、数据库表或访问边界。PromQL Tool ID 不是额外 RBAC 权限，普通主机读者无需增加工具权限。表达式固定在代码中，只有当前列表显示的主机 UUID 进入显式范围，服务器每次查询仍校验权限和来源。

页面统一发起 CPU、内存、存储三个批量请求。独立主机、堡垒机和成员表复用同一批结果，不为每行或每张分组表发请求。各指标独立完成/失败，主机基础列表不等待它们。维持有限查询预算，超过预算显示状态，不无限拉取或重试。

可见时每 60 秒更新，手动刷新及操作后立即更新；列表的既有连接状态轮询不反复触发指标请求。筛选、会话变化、刷新、卸载或浏览器后台会取消旧请求；重新显示时创建新查询上下文，不重用上次筛选的无限新鲜缓存。请求携带 AbortSignal，范围改变后的迟到结果不能回填当前列表。
