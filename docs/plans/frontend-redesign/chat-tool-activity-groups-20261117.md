## 展示契约

- 统一ToolActivity投影：调用身份、来源、真实生命周期、输入/输出、耗时、可选文件/命令语义。原生tool.invoke保留外层身份并使用已验证实际目标展示；外部MCP不会因同名read/write获得内部文件语义或操作能力。
- 连续工具活动进入轻量批次，同一会话/Run内合并，模型可见文字、审批、用户问答和文件交付形成边界。已完成默认折叠，运行中显示进度，用户展开状态保留；顺序不按计划ID、工具名或完成时间重排。
- 行展示使用共享@argus/ui组件，无逐项外层大卡片。文件行支持操作/路径、实际增删行与历史Diff；命令行展示摘要、退出码、耗时及输出；其他工具展开通用输入/输出和可选原有业务视图。
- history/live共用投影与归一，调用开始/完成更新同一身份，通用展示与业务展示不重复。未知结果、取消和命令非零退出单独呈现；待确认/审批保持显著。
- 普通文件发布保留预览/下载，活动中的自动文件展示收紧；原文件内容、原始参数和审计不改写。

## 执行事实补充

在现有租约和工具边界内发出真实tool_call_started事件；不由模型自报开始时间。Workspace提供可选受控activity元数据，读取范围与文件变更来自实际IO；Diff按有界前后版本计算，过大/二进制明确不可完整预览，不伪造+/-。元数据不进入模型数据，不增加模型调用；外部工具不能伪装原生展示。

### 已实现的数据边界

- 声明调用时记录服务端 `tool_sources`，真实 dispatch 与 `tool_call_started` 在同一个租约保护的 READ COMMITTED 事务提交；原有 Run 版本检查、外部 MCP 实际发送前的 dispatch、崩溃后不重放写入均保留。开始/完成通过同一 `tool_call_id` 原位更新，完成时间不改变调用位置。
- `ToolCallTrace` 是统一视图：`argus`（含 Gateway 包装和实际目标）、`sandbox`（直接进入模型 tools 的工作区工具）和客户 MCP 都使用相同轻量行；来源仍决定语义和展示权限。仅已知可信内建语义或服务端 activity 能启用文件/命令专用视图，外部 `write` 等同名工具保持通用详情。
- 可选 `argus.tool_activity/v1` 记录 file_read/file_change、实际路径、工作区及变更事实。变更包含操作、前后 hash、实际增删行、有限 diff、完整性与原因。按同一 workspace lease 读取前后文件，校验写后 hash；每次快照最多 64 KiB、512 行，LCS 有界。大小、二进制、读取失败或快照变化不会制造创建状态和行数，也不会把已经成功的写入变成可重试失败。
- 文件证据存于原调用结果事件，不读当前文件冒充旧版本。旧调用未记录差异时明确提示；外部 provider 的 activity 在 Agent 持久化前清除。`activity` 和 `tool_sources` 不进入模型结果或压缩 payload；文件证据在授权指纹变化后从历史及 SSE 响应移除。
- 运行结束时仍未返回的已 dispatch 调用显示结果未知，仍排队的调用显示取消，不把 Run 结束推断成工具成功。命令 API 成功但真实退出码非零时，活动仍显示失败。
- 视图分组为纯投影，不增加模型调用、不指定模型工作流，也不凭空生成进度文字。原有业务视图进入轻量行内的按需详情；自动文件使用紧凑文件行，最终交付仍能直接预览/下载。
- `AgentEvent.step_id` 补齐为可选契约字段，并同步生成 Go/TypeScript 客户端；无数据库迁移，正式 schema 仍为 54。
