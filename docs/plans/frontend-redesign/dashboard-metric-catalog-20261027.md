# 仪表盘指标候选查询修复

2026-10-27。问题：统计图编辑器的指标下拉框显示“候选获取失败，当前选值保持不变”。实际 `POST /dashboards/catalog/query` 返回 HTTP 503 / `DASHBOARD_UNAVAILABLE`；ClickHouse 记录 `TOO_MANY_BYTES`，扫描量超过 256 MiB。

已部署 `local-20261027-catalog-fix-v2` 到本机 `https://argus.dev`。标准健康检查 **20/20**，真实中英 × 深浅主题选择/保存/查询回归 **4/4** 通过。

## 原因和实现

目录接口同时存在两个读取问题：

1. 查询指标元数据时，没有先按资源、指定指标和实际存在的序列裁剪，并且对不含 Namespace 的主机来源也读取 `resource_attributes` 大 Map。
2. 确认时间窗口内是否存在样本时，子查询读取 `resource_id`，无法使用现有 `argus_numeric_source_time` 投影，因而扫描大量历史样本。仅优化元数据不能解决实际部署中的失败。

`internal/telemetry/data_catalog.go` 统一构造三个目录入口的读取条件：资源、指标及序列主键放入 `PREWHERE`；可变的来源、Namespace 与标签仍在 `FINAL` 去重之后校验。`chscope.SelectedPredicate` 对完整来源使用精确来源集合，包含 Namespace 或混合选择时保留原有范围校验。字段目录、候选值和已选值成员检查复用该链路。

样本存在性子查询只读取来源、时间和序列 ID，复用已有来源/时间投影。Writer 的 `metricSeriesID` 将企业和资源身份纳入序列 ID，外层元数据查询继续执行资源与来源/Namespace 约束。没有新增表、放宽查询预算、扩大用户授权或用静态指标替代实际观测。日志和 Trace 的时间边界保持原样。

`FINAL` 前仅使用排序键的约束，避免旧版本元数据因提前过滤来源而重新出现；参考 [ClickHouse PREWHERE 文档](https://clickhouse.com/docs/reference/statements/select/prewhere)。接口与前端组件契约不变。

## 指标下拉滚动分页

同日后续按用户要求，将共享 `@argus/ui` ComboBox 的“加载更多”按钮改为接近列表底部时自动加载下一页。复用 React Aria `ListBoxLoadMoreItem`，鼠标滚轮、滚动条和键盘移动导致的列表滚动走同一入口；不足一屏且有下一页时自动补齐。滚动限制在候选列表内，加载中显示双语状态。失败保留已有页和当前选值、停止自动重试，用户点击“重试”后继续失败的游标。请求进行中不重复加载，搜索或范围变化取消旧请求并从第一页开始，旧响应不能覆盖新列表。

新搜索等待第一页期间保留已有候选，列表标记为加载中；新结果返回后整体替换上一轮候选，后续分页再追加。允许手输值时，输入中的文本不作为已提交的 `selectedKey`，避免每次文字更新都触发选中逻辑并关闭弹层；实际选中和外部值更新仍同步当前值。

指标编辑页与通用 QueryTargetEditor 共享 `useMetricOptions`：同一次搜索的所有分页和失败重试复用第一页确定的绝对时间区间，避免相对时间每次重新计算导致已签名游标失效。新搜索、时间或资源范围变化重新冻结条件，默认每页上限仍为 100。

分页交互测试位于 `e2e/combobox-pagination.spec.ts`，使用独立开发测试页和明确的受控候选，覆盖中英/深浅、三页滚动、重复请求、失败重试、迟到响应、短页补齐与静态选择。真实部署测试继续使用已有采集数据，通过仅将请求页大小减为 15 来触发第二页，响应不伪造，同时检查第一页和第二页时间完全相同。证据单独保存在 `artifacts/combobox-scroll-20261027/`。

Web 构建基于已部署 B04 Web 源码快照，只叠加共享 ComboBox、列表滚动样式、分页查询辅助函数及两个指标编辑入口这五个生产文件；其他工作区改动不进入本次 Web 制品。后端复用上一轮目录修复的镜像摘要。

最终已部署 **`local-20261027-catalog-scroll-v3`**。`browser-complete.log` 记录 **8/8** 交互测试通过；`real-browser-v3.log` 记录中英 × 深浅主题 **4/4** 真实分页、搜索、保存、查询和刷新恢复通过，第二页 HTTP 200 且与第一页使用相同时间边界。`deployment-v3.json` 记录标准健康检查 **20/20**。类型、样式、国际化及相关 lint 检查通过，分页时间冻结单元 **2/2** 通过。早期搜索收起问题和测试页/定位失败保留在同目录对应日志中，不以最终成功覆盖失败证据。
