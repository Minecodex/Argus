# Kubernetes 资源工作台重构实现计划

日期：2026-11-12
状态：2026-11-13 已完成二次复核所列 C01～C05 的补齐、真实验证、部署和清理，整体计划关闭。以 [剩余项补齐验收](./kubernetes-workbench-closure-20261113.md) 及保留的前轮验收为依据。
目标：让用户从资源运行状态直接进入常用操作，并在同一上下文中看到实际结果。
首轮交付：Pod、Deployment、CronJob、PVC 四条完整流程；完整交付覆盖当前资源目录中的其余类型。

## 1. 背景与现状

本计划承接用户“资源列表界面的操控过于难用”的反馈，以及 Rancher、Lens、Headlamp 的官方文档调研。

当前实现已有资源查询、清单编辑、预览确认、异步执行、日志和终端能力。重构的重点是把这些能力组织成日常操作流程：

| 当前实现 | 使用上的问题 | 重构目标 |
| --- | --- | --- |
| 各类型基本共用名称、Namespace、控制器、resourceVersion 列 | 用户看不到 Pod Ready、可用副本、PVC 容量等判断依据 | 按资源类型展示状态和关键字段 |
| 查看对象主要展示元数据与 JSON | 需要阅读对象结构才能定位问题 | 状态概要、关联对象、事件和配置分区 |
| 常用动作集中在“管理对象”的操作选择框 | 扩缩容、重启、暂停等入口难发现 | 资源专用动作和参数表单 |
| 编辑已支持 YAML/JSON，但许多日常修改仍依赖完整清单 | 用户需要理解字段路径和原生对象结构 | 常见修改表单化，完整清单作为高级编辑 |
| 提交后自动打开操作记录弹窗 | 打断当前资源操作，难区分提交与实际生效 | 原位置反馈进度，按需打开操作详情 |
| 日志、终端、资源详情分别打开弹窗 | 难连续查看资源、容器和关联对象 | 明确目标的详情区与排障工作区 |

### 3.2 首轮不纳入

- 新的 Project/租户体系、集群部署管理系统或资源状态数据库。
- 自动 watch、无界后台轮询、跨集群全局搜索。

- 任意多资源批量写入、临时调试容器、普通 Pod 终端以外的新远程能力。
- 为缺失指标生成零值、用演示数据代替实际采集。
- 将详情重构与全局侧边栏或门户整体布局改版捆绑发布。

首轮之外的既有资源仍可通过共享框架中的通用详情和高级编辑使用已有能力；完整计划完成前必须逐项覆盖资源矩阵，不能以通用兜底代替全部专用交互。

## 4. 目标操作模型

### 4.1 页面与导航状态

资源工作台维持“范围选择 → 类型化列表 → 详情/动作 → 结果”的结构。

- URL 保存可分享的资源类型、Namespace 范围、已提交的名称/标签条件，以及当前详情对象的定位信息。
- 浏览器返回恢复原列表类型、筛选、分页和滚动位置；游标过期时说明原因并重新读取，不静默扩大范围。
- 对象定位内部包含 Cluster、资源类型、Namespace 身份和对象 UID；用户主要看到资源名称与 Namespace。
- Namespace 更换或资源删除重建后重新校验 UID，不把同名新对象当作旧对象。
- 翻页、刷新和操作期间保留当前编辑；旧请求结果不能覆盖新范围。
- 首轮排序只开放后端支持的键。当前页排序或过滤不能伪装成整个授权范围的排序或搜索。

### 4.2 列表和动作

- 资源名称作为详情入口，取消重复的“查看对象”行按钮。
- 名称和状态为常用固定列；其余列由类型配置提供。
- resourceVersion、UID、generation 等移入“技术信息”，不作为默认业务列表列。
- 所有资源的行操作统一放入共享“更多”菜单，包括 Pod 日志、终端和复制资源链接；详情顶部不重复提供操作条。
- 动作名称使用“扩缩容”“滚动重启”“暂停调度”“扩容”等具体意图。
- 权限不足时不提供写入口；具备权限但对象状态不允许时，禁用并给出具体原因。
- 尚需检查的动作在菜单顶部统一说明执行前校验权限、状态和版本，不逐项重复“待检查”；状态不被乐观标记为可用，预览、确认和执行仍继续实际校验。
- 未采集、无权限、读取失败、已删除、未知和真实零值分别表示。

### 4.3 详情

同一套详情内容在普通和加宽抽屉中复用，不切换为另一页。右上角提供放大/恢复和关闭图标，点击左侧遮罩关闭；保存中的表单仍保护关闭。此行为复用共享 DrawerPanel，适用于同类详情抽屉：

| 分区 | 内容 |
| --- | --- |
| 概览 | 运行状态、异常原因、该类型关键参数、最近观测时间 |
| 关联资源 | 受控 Pod、所属控制器、Service 后端、PVC/PV、挂载关系等 |
| 事件 | 授权范围内与该对象身份相关的事件，展示原因和时间 |
| 监控 | 已有观测能力、指标摘要及仪表盘入口；缺失时说明来源状态 |
| 配置 | 类型化配置摘要；编辑动作统一从列表“更多”菜单进入 |
| YAML / 技术信息 | 投影后的完整对象、UID、版本等；Secret 继续脱敏 |

仅展示适用分区。关联查询懒加载、可分页，有预算和不完整状态。没有授权时不泄露关联对象名称、UID、数量或配置。

### 4.4 日志与终端工作区

- 默认打开即读取日志，底部跟随最新；向上滚动暂停跟随，回到底部恢复。
- 日志与终端使用可调整大小的工作区；容器选择、Shell、操作原因等复用既有会话流程。
- 顶部持续展示 Cluster、Namespace、Pod、容器与会话状态。
- 同一集群中切换详情时，已经打开的会话仍绑定原目标，并明确显示该目标，不自动连接新选中的 Pod。
- 关闭工作区、切换集群、退出登录或离开工作台时按既有协议关闭会话；对象 UID/容器代次变化、撤权、过期继续终止。
- 无权限、容器未运行、已确认无 Shell、连接失败分别解释；不能仅凭镜像名称猜测支持情况。
- 首轮以一个活动排障工作区为默认，避免同时创建大量后台连接；多会话 Dock 另行扩展。

### 4.5 操作与结果

~~~mermaid
flowchart LR
  A[资源行或详情动作] --> B[带当前值的参数表单]
  B --> C[原生校验与变更预览]
  C --> D[确认后提交]
  D --> E[原位置显示执行与观察进度]
  E --> F[实际生效后刷新资源]
  E --> G[失败或结果未知的明确说明]
~~~

- 表单、预览和确认在同一个操作承载区内逐步完成，避免多层弹窗。
- 提交后关闭输入区或转为紧凑进度区，不自动强制打开全局操作历史。
- 行内或详情顶部提供“查看操作详情”，全局操作记录仍保留。
- 服务端执行成功与资源目标生效按现有状态机判断；前端不能收到 HTTP 成功就提前展示“已生效”。
- 结果未知时提供观察、读取对象和查看记录入口，不盲目重放写入。
- 被后续操作取代的记录说明原因；Job 启动/就绪和 Job 最终完成分别展示。
- resourceVersion 冲突保留用户输入，重读对象并展示差异，重新预览后再确认；不自动覆盖远端，也不默认丢弃编辑值。
- 操作状态的有界查询仅服务于执行反馈，不恢复资源列表全局 watch。

## 5. 资源类型矩阵

表中动作均以现有后端能力、授权和实际前件为准。P0 必须确认当前支持范围；不能因为前端列了入口，就宣称后端已经支持。

| 类型 | 默认核心字段 | 详情重点 | 动作与编辑方式 | 阶段 |
| --- | --- | --- | --- | --- |
| Pod | 状态/原因、Ready、重启次数、节点、所属工作负载、创建时长 | 容器、事件、控制器、挂载 | 日志、终端、删除；受控 Pod 删除前提示控制器可能重建 | P3 |
| Deployment | 可用/期望副本、镜像、更新状态、创建时长 | Pod、ReplicaSet、历史、HPA | 扩缩容、重启、镜像/资源配置、回滚、高级清单 | P3 |
| CronJob | 周期/时区、暂停状态、活动任务、最近调度 | Job 历史、模板、并发策略 | 暂停/恢复调度、立即运行、修改计划 | P3 |
| PVC | 状态、申请/实际容量、StorageClass、PV | 使用中的 Pod、绑定、扩容条件 | 新建、扩容、删除、高级编辑；拒绝缩容 | P3 |
| StatefulSet | Ready/期望副本、镜像、更新状态 | Pod 序号、Service、卷、修订 | 扩缩容、模板编辑、重启、回滚；解释数据和更新策略影响 | P4 |
| DaemonSet | 期望/就绪/可用节点数、镜像 | 节点分布、Pod、修订 | 重启、模板编辑、回滚；不提供副本扩缩容 | P4 |
| ReplicaSet / ControllerRevision | 副本与控制器 / 修订与所属对象 | 所属工作负载、Pod、历史关联 | 按后端能力提供高级操作，优先引导操作所属控制器 | P4 |
| Job | 活动/成功/失败数、条件、开始时间、耗时 | Pod、日志、创建来源 | 未结束时按能力暂停/恢复；高级编辑、删除 | P4 |
| HPA | 当前/期望副本、上下限、目标与当前指标、条件 | 目标工作负载、指标来源 | 副本范围与指标目标表单，不伪造缺失指标 | P4 |
| PDB | 健康/期望数、可中断数、选择器 | 受影响工作负载、节点维护关系 | minAvailable/maxUnavailable 与选择器表单 | P4 |
| Service | 类型、ClusterIP、端口、选择器 | EndpointSlice、后端 Pod | 端口/选择器表单；分配字段按现有服务端约束处理 | P4 |
| Ingress / IngressClass | Class、主机/路径、地址 / Controller | Service、TLS 引用、事件 | 路由/TLS 引用表单及高级编辑 | P4 |
| NetworkPolicy | 选择范围、入站/出站规则摘要 | 授权范围内匹配对象、规则 | 选择器、来源/目的、端口表单；不把存在策略等同实际网络阻断 | P4 |
| ConfigMap | 键数量、创建时长 | 键值、授权范围内的引用对象 | 键值/文件编辑、高级清单 | P4 |
| Secret | 类型、键名/数量、创建时长 | 脱敏配置与授权引用 | 受保护输入；明确新增、替换和删除键的意图 | P4 |
| Node | Ready、调度状态、角色、资源情况 | Pod、Conditions、事件、指标 | 禁止/恢复调度、排空及影响预览 | P4 |
| PV / StorageClass | 容量/状态/回收策略 / Provisioner/绑定与扩容能力 | PVC 关联、参数 | 本轮按既定只读边界展示；不提供无效写按钮 | P5 |
| Namespace | 状态、创建时长 | 已授权资源、配额、限制 | 既有创建/编辑/删除能力；删除影响单独预览 | P5 |
| Role / ClusterRole | 权限规则摘要 | API 组、资源、动词 | 规则表格与高级清单 | P5 |
| RoleBinding / ClusterRoleBinding / ServiceAccount | 绑定角色与主体 / 关联关系 | 权限引用、授权主体 | 明确主体与角色引用的编辑；禁止展示 token 原值 | P5 |
| ResourceQuota / LimitRange | 配额使用/上限 / 默认与约束 | 作用 Namespace、资源维度 | 类型化参数表单与校验 | P5 |
| EndpointSlice / Event | 地址、就绪端点 / 原因、对象、时间 | Service 关联 / 事件详情 | 优先只读与跳转；写操作严格按现有能力 | P5 |
| CRD 与扩展实例 | 类型、范围、版本 / 可证明的通用状态 | Schema、实例、投影后的对象 | Schema 支持时校验高级清单；无通用运行状态时明确未知 | P5 |

CPU、内存等观测列按已接入的数据能力提供，首轮不为每行独立发起指标查询。容量、时长、CPU 单位和百分比使用共享格式化规则。Pod 的 Running 与 Ready、创建时长与容器运行时长分别处理。

## 6. 首轮四条完整流程

### 6.1 Pod 排障

列表识别 Pending、未 Ready、CrashLoopBackOff 等实际原因 → 点击名称 → 查看容器与事件 → 打开指定容器日志 → 在权限与运行条件允许时进入终端。

验收：状态有原生依据；多容器选择正确；切换详情不改变已打开会话目标；容器终止、重建、缺 Shell 和权限拒绝均有可理解反馈。

### 6.2 Deployment 扩缩容、重启与更新

行菜单选择动作 → 显示当前副本/镜像/更新策略 → 输入目标 → 预览确认 → 在当前资源位置观察可用副本和更新状态。

验收：初始值来自真实对象；存在关联 HPA 时解释副本受自动伸缩管理并提供跳转；不把 Pod Running 当作全部 Ready；失败、被后续操作取代和回滚结果明确。常用镜像/资源字段用表单，其余字段可进入高级清单。

### 6.3 CronJob 暂停与手动运行

“暂停调度”确认说明只停止后续调度，不终止已经运行的 Job；恢复按原生调度规则执行，不承诺补跑全部错过的周期。

“立即运行”显示来源 CronJob、Namespace、新 Job 名称和相关策略，确认后提供新 Job 的直接入口。暂停期间仍可按原有能力手动运行。源对象发生变化时保留输入并重新预览。

验收：核对原生 suspend、实际 Job 创建及日志/完成结果；Job 被历史策略回收后展示“已回收”和保留的执行记录，不出现无法解释的空白页。

### 6.4 PVC 扩容

显示申请容量、实际容量、StorageClass 扩容能力和使用关系 → 填目标容量 → 预览确认 → 显示已提交、扩容中、等待文件系统扩容或实际完成。

验收：不允许缩容；支持能力未知/无权读取/不支持时给出原因；实际容量达到目标且条件收敛才完成。真实测试写入文件并校验扩容前后内容。没有卷使用率指标时显示不可用，不以申请容量或宿主文件系统指标替代。

## 7. 前后端实现组织

### 7.1 前端

采用“共享框架 + 类型配置 + 有限的专用表单”，避免不断扩大当前 workbench.tsx。

建议职责划分（新文件名为规划，不表示已经存在）：

| 模块 | 责任 |
| --- | --- |
| 资源页面容器 | Cluster/Namespace/类型/过滤和路由状态 |
| 资源视图注册表 | 各类型的列、详情分区、动作顺序与适用性 |
| 资源列表 | 共享 DataTable、加载/错误/分页、名称入口 |
| 详情容器 | 侧栏与完整页共用内容，关联和事件懒加载 |
| 动作注册表 | 业务意图到现有预览接口的映射，不承担授权判断 |
| 类型化表单 | 副本、镜像、调度、容量、端口、配置项等 |
| 操作反馈 | 统一操作状态、进度、错误和历史入口 |
| 排障工作区 | 日志与终端的呈现、目标标识及关闭生命周期 |

复用 @argus/ui 的 DataTable、ActionMenu、Drawer、Dialog、Field、输入控件及 StructuredDocumentEditor；可复用的新通用能力放入共享包。业务样式使用 .argus-* 和 design token。每个前后端文件保持低于 2000 行。

### 7.2 状态、关联与能力

现有 Inventory Object 已有 Data、Owners、CreatedAt、ObservedAt。先盘点这些投影数据可直接支持的字段，再补齐缺项，不重复请求相同对象。

推荐在现有 Kubernetes 领域中形成统一、受预算约束的摘要和能力投影：

- 状态摘要：状态类别、原因、必要消息和类型字段；保存原生依据与观测时间。
- 动作能力：该类型是否支持、当前用户是否允许、当前状态是否可用，以及稳定的原因码。
- 关联引用：资源类型、名称、Cluster、Namespace 身份与 UID；关系类型区分拥有、选择、挂载和引用。
- 分页/完整性：当前返回范围、后续游标、观测时间及不完整原因，禁止把第一页当作全集。

这些是拟议契约，不是现有 API 字段声明。P0/P1 确定精确结构和版本策略，先更新 OpenAPI，再生成 Go/TypeScript；内部命令有变动时同步 protobuf 及 Direct/Connector 两条路径。生成文件不得手工维护。

授权与当前前件由服务端统一判断，前端 capability 只用于呈现；预览、确认和实际执行仍需重新校验。列表不能按行执行完整 dry-run、Secret 读取或无限关联查询。重成本前件检查在打开具体动作时有界完成。

关联关系只在当前授权范围内解析；匹配 Service/NetworkPolicy 的标签关系不等同 ownerReference，也不等同实际流量路径。详情和列表使用统一状态解释，避免同一对象同时显示互相矛盾的健康状态。

### 7.3 写入与高级编辑

- 不创建第二套写入通道，继续使用现有 Preview → Confirm → Operation → Observe。
- “暂停调度”“PVC 扩容”等 UI 意图可编译成现有 patch；只有现有契约确实无法表达时才新增领域操作。
- 表单生成受控字段变更，保留未编辑字段；不能用不完整的表单对象覆盖整个原生对象。
- 表单与高级编辑共享原始快照和待提交变更。无法无损映射到表单时保留高级编辑状态，不能静默丢弃未知字段。
- Secret 脱敏占位不视为原值；沿用受保护输入与服务端保留机制，新增、替换、删除明确区分。
- UID、Namespace 身份、resourceVersion 和相关来源对象保持绑定，确认后对象变化继续走既有失效/冲突规则。
- 提交结果、字段错误、执行错误分别呈现；错误保留 request reference，但内部标识不占据日常列表。

### 7.4 数据与权限边界

企业仍是唯一租户边界；管理权限不自动授予 Shell、Secret 原值或生产执行权限。标签仅用于筛选，不能扩大授权。

资源状态以原生 API 观测为依据，指标复用现有遥测查询与授权裁剪。浏览器不直接访问 Kubernetes API、kubelet 或 Secret；不建立平行资源真相库。会话票据不写入 URL、浏览器持久化配置或测试 trace。

### 9.2 首轮真实场景与判定

| 场景 | 通过标准 |
| --- | --- |
| 异常 Pod → 事件 → 日志 | 列表原因与原生状态对应，日志来自所选容器；未知数据不显示为健康 |
| Pod 终端 | 在有 Shell 的实际业务容器执行只读命令并见输出；无权/未运行/缺 Shell 明确说明；关闭后会话结束 |
| Deployment 扩容、重启、更新、回滚 | 正常预览确认；实际副本、Pod UID、镜像或修订变化；UI 区分提交与生效 |
| HPA 管理的 Deployment | 展示实际 HPA 关联，人工修改前说明自动控制关系 |
| CronJob 暂停、恢复、手动运行 | 核验原生调度状态、实际新 Job、日志和完成结果；并发更新触发重新预览 |
| PVC 扩容 | 有能力的 CSI 实际扩容，status/文件系统符合目标且原文件保留；缩容和不支持组合拒绝 |
| 冲突及后续覆盖 | 用户输入保留；失效请求不写入；原操作被取代的结果明确 |
| 已删除/同名重建 | 原 UID 详情提示已变化，不继续操作同名新对象 |
| 关联授权 | 只能查看已授权关联，无跨 Namespace/企业名称、UID、数量泄漏 |
| 操作历史与刷新 | 提交不自动抢占为全局历史弹窗；列表范围保留，操作结束刷新实际结果 |

### 9.3 真实测试环境和证据

- 优先使用本轮拥有的临时 Namespace；CSI、CNI、资源指标等前件不足时使用独立测试集群，不改动正式集群的存储驱动或 CNI。
