# Kubernetes 资源列表用量趋势与渐进加载

用户已确认：精简副本/镜像列，为适用的资源加入 CPU、内存、存储迷你曲线，列表先显示，指标随后独立渐进加载。

## 展示与口径

- Pod、Deployment、StatefulSet、DaemonSet、ReplicaSet、Namespace、Node 提供 CPU/内存；Job/CronJob、ControllerRevision、配置/网络/RBAC 等无对应概念的列表不添加。
- 有完整 limits 时显示上限利用率，有完整 requests 而无完整 limits 时显示申请利用率；部分缺失时只显示绝对用量并说明。申请参考线不冒充上限，比例不裁到 100%。Node 按容量计算，Pod 请求量和可分配量在悬浮信息中分别说明。
- 默认最近 30 分钟，使用量和同时刻的历史申请/上限对应；缺失历史分母不拿当前值计算过去的百分比。明确标注当前成员范围，按 UID/Owner 关联，Pod 同名重建不继承旧数据。
- 节点本地文件系统、Pod 临时存储和 PVC 卷分开标注；卷按身份去重。只有原生采集实际给出占用时才画曲线；缺失、不支持、预算不足、过期、无权限和零值分开。
- 有副本语义的列表只保留一个副本状态列；镜像与更新策略等移至名称悬浮摘要，详情继续保留完整字段。名称点击仍打开详情，摘要支持键盘和复制。

## 数据与渐进执行

扩展现有 Kubernetes 领域只读能力，不新增服务或数据库表。新增当前页指标上下文准备及分指标读取接口，通过 OpenAPI 生成客户端；不在浏览器拼接跨权限的资源聚合。

1. 原有资源列表完成即可显示名称、状态与操作，指标单元格独立占位。
2. 页面在列表稳定后准备一次上下文：服务端重读当前页，核对请求中的 UID，按实际 Namespace 与控制器归属读取有界 Pod 集合，冻结公开身份和配置摘要。
3. 上下文绑定企业、用户、授权版本、集群、当前范围与时间，签名且短期有效，不含凭据；CPU/内存/存储分别请求，独立成功/失败，不串行等待最慢项。
4. 每次读取均重验当前资源/遥测授权、Namespace UID 与来源；用户或范围撤权时不返回缓存。范围改变、翻页、刷新、隐藏页签、浏览器后台会取消旧请求，结果不能回填新列表。
5. 沿用手动刷新；只查询当前页，禁止逐行指标请求。Pod 归属读取和结果大小均有预算，达到上限时标明不完整，不把部分和当精确总数。

Telemetry 继续通过现有授权来源解析和查询引擎读取实际指标。默认来源固定为 kubeletstats/k8s_cluster，界面不能指定任意 URL 或凭据。与资源列表的 native RBAC 和数据授权分层保持一致。

## 验证

覆盖当前页批量读取、Pod/控制器归属、部分 requests/limits、申请利用率超 100%、资源替换、过期/无权限/查询失败、存储缺失与去重；证明延迟或失败的指标不阻塞列表和操作。真实部署检查 Namespace/Node/Pod/工作负载、名称悬浮、既有会话及中英明暗桌面页面，保留正式数据和 B10c 环境。
