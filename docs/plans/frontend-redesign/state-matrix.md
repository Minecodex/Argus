## 数据页面的状态

`planv2-portal-states-real.spec.ts` 使用临时 Kubernetes 的正式镜像、实际登录和初始 API 响应，在浏览器中分别注入请求延迟、空集合、503、403，再移除拦截验证恢复。覆盖中文/英文×浅色/深色，并检查页面结构、溢出及 Axe。它验证前端的状态处理；真正的撤权、发布并发、查询失败、取消及任务恢复由完整 PlanV2 领域/运行时回归另行验证。

| 门户 | 页面 | 主查询 |
| --- | --- | --- |
| 企业 | 主机、K8s、仪表盘目录 | Hosts、Clusters、Dashboards |
| 企业 | 任务、审批、远程会话 | Executions、PendingActions、RemoteAccessSessions |
| 企业 | 组织、模型、MCP、凭据、审计 | Users、Models、MCPConnections、Secrets、AuditEvents |
| 平台 | 企业、管理员、Sandbox、审计、PKI | Enterprises、EnterpriseAdmins、Backends、AuditEvents、PKI |

空集合场景只清空原响应中的数组和分页字段，PKI 对应无 Bundle；不伪造缺失的必填对象。无权限场景只证明 UI 正确处理 403，不代替服务端对象授权测试。

详情和编辑任务的“空”指无样本、找不到对象或缺少配置，不统一成空列表。仪表盘的真实单图预览、迟到响应、无数据、冲突、撤权、归档恢复和资源入口由 `planv2-*.spec.ts` 覆盖；认证/MFA/初始化失败、接入/卸载重试、审批拒绝、模板 Bridge 和表单反馈由业务回归及现有相关单元测试覆盖。账号依赖已认证身份，不能用清空用户对象伪造一个成功响应。

## 候选与指标、图型

- `candidate-filters.test.ts` 与真实编辑候选用例验证完整定义、来源、信号、参数映射和前置值；`ValueSelector` 测试验证分页/失败保值、准确消失证据、取消及迟到响应。
- `use-metric-metadata.test.tsx` 验证异步元数据与切换指标的迟到保护，类型不从前一个指标继承。常见与高级查询编辑器使用相同逻辑。
- `observation-chart-capabilities.test.ts` 验证十一类图型、快照/范围、全部查询、累计分桶、负值与显示计算、Logs/Trace 形状、未执行与部分结果。图型切换保持查询不变。
- 共享 `QueryBoundary` 区分加载、错误、403 和真实空集合，支持重试；列表反馈不包裹编辑弹层，避免查询状态变化丢失表单。
