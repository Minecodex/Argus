# Kubernetes 资源菜单与详情抽屉修订

日期：2026-11-13。本轮按用户截图调整列表与详情交互，覆盖早期计划中的 Pod 直接按钮和展开独立页面约定。

## 交付行为

- 状态筛选使用紧凑尺寸，保留 Namespace、名称/标签筛选和右侧操作区间距。
- 全部资源使用同一个行操作组件。日志、终端、复制资源定位链接及写操作统一进入“…”；资源名称继续作为详情入口。只读资源仍可复制定位链接。
- 菜单顶部只显示一条执行前校验说明，移除逐项重复的“待检查”。服务端能力和状态保持原值，已知不可用的动作继续禁用并展示具体原因，预览、确认和执行仍校验权限、对象身份及资源版本。
- 详情取消顶部操作条，右上角放大/恢复图标在同一个抽屉内切换宽度，默认 760、加宽 1120，均限制在视口内并保留可点击的左侧遮罩。当前分区、对象 UID、Namespace 和已编辑内容保持。
- 复制定位链接保留列表范围、过滤、页序与对象身份。操作结果对应对象已回收时仍在底部保留“查看原操作记录”，避免失去原结果上下文。
- 共享 DrawerPanel 修正外层内容覆盖整屏的点击区域，Kubernetes、告警等同类详情抽屉都能点击外侧关闭；保存中的表单仍阻止关闭。
- 操作列固定在表格右侧，横向滚动时“…”始终可见；长资源名称使用省略并保留完整文本提示，表头不逐字折行。所有资源类型复用这一列表框架。

## 实现边界

复用 `@argus/ui` 的 DrawerPanel、ActionMenu、Dropdown 和 DataTable。没有增加并行组件库或写入通道，没有改变后端授权、动作校验、会话协议和数据库 schema。`full` 路由字段现在表示抽屉加宽，打开和关闭详情继续恢复原列表上下文。
