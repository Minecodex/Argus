## 仪表盘目录筛选

2026-10-26：仪表盘目录的「已发布 / 我的草稿 / 已归档」复用 `@argus/ui` 的 Tabs 栏，与其他管理页面保持一致，支持键盘切换。Tab 下方复用共享 FilterBar，名称搜索与紧凑分组下拉相邻，分组控件按内容占宽、上限使用 `--field-width-compact`，不再铺满整行。

三个页签均对当前 API 返回的可访问条目应用名称和分组的交集筛选；名称按包含关系匹配、忽略大小写和首尾空白，仅搜索名称。切换页签保留筛选条件，清空搜索或选择「全部分组」即可分别取消条件；无匹配结果时提示调整筛选。中英文、浅色/深色和桌面宽度均纳入浏览器验收，不改变 API、数据权限、发布与归档确认边界。

共享 Tabs 的未选中悬停文字使用 `--text-primary`，避免浅色主题继承组件库弱对比度颜色；选中和禁用状态保留各自语义。

## 列表操作入口

2026-10-13：实体列表的次要操作与破坏性操作统一使用 `@argus/ui` 的 `ActionMenu`，行末只展示一个「…」入口。编辑、复制、测试、启停、安装进度、重试、授权、卸载和删除等操作进入该菜单；名称保留直接打开详情的入口。新增、筛选、刷新、批量操作与弹窗内的预览/确认按钮继续位于各自工具栏或操作区。

菜单复用双语可访问名称、键盘交互、禁用状态、危险操作样式及设计 token。破坏性操作仍保留原领域服务的预览、审批、确认、执行与审计边界；展开菜单不创建 PendingAction 或执行操作。主机列表的升级/修复/卸载采集器在选中时读取当前配置与版本，避免以旧列表数据构造变更。

主机详情移除独立的生命周期卡片及右上角卸载按钮；OTLP 收集器卡片右侧「…」提供修改数据推送路由和路由测试，结果及配置预览在弹窗中展示。主机、Kubernetes、仪表盘、关联仪表盘、告警、企业设置、远程会话及平台管理员/Sandbox 列表使用同一菜单组件。实现与验证见[菜单验收记录](./row-actions-20261013.md)。

主机概览展示本机 Connector 采集的结构化资产快照：OS/内核/架构、主机名、机器 ID/硬件 UUID、CPU 型号和核数、内存/Swap、文件系统/容量、网卡/IP/MAC/MTU、GPU、虚拟化/容器范围、云厂商/实例 ID/区域。字段缺失和采集失败必须明确展示；不根据名称猜测云厂商，不制造 GPU 或机器 ID。Docker 主机的 CPU、内存和 uptime 是其可见内核视角，文件系统和网卡是容器可见范围，必须展示该范围说明。

资产快照随 Connector 心跳上报、由 PostgreSQL 保存，自动定期更新；“重新采集”发起只读的类型化 Connector 命令并等待实际结果，失败不显示刷新成功。该动作检查 host.read、显式资源授权、当前 Connector 身份及 epoch，保留命令与审计事实，不获取 SSH 凭据、不执行任意 Shell。高频 CPU/内存/磁盘指标仍由 Collector→OTLP→ClickHouse→查询引擎负责；资产快照不替代遥测链路。

正式 real 构建只使用真实 API；mock 仅用于独立 UI 开发测试。概览删除页面内伪随机指标、由创建时间推算的 uptime 和示例账号。无采集或没有样本时显示具体状态，不能回退种子数据。Kubernetes Collector 使用已有真实安装/配置服务，列表和详情必须同时开放该能力。

本地监控对象为持续保留的 Docker Linux 主机与 Docker 驱动的 Minikube 集群。正式低阈值告警若只用于演示应停用，保留历史事实，常规监控使用实际策略；历史会话/告警不改写成新的事实。验收同时检查双语/主题/桌面列表、真实硬件对比、重新采集、Collector 收敛、资源查询及真实样本；临时测试 Namespace 完成后清理。

Kubernetes 节点/版本统计由集群 Connector 实际访问 Discovery/Nodes 后随心跳上报，保存独立 statistics_observed_at。尚未采集时不展示初始化的 0；角色、企业、集群 Connector ID 和连接 epoch 必须匹配，统计不修改资源配置版本。

## 现有隧道的安全恢复

凭据资源版本变化会阻止旧版本控制/遥测隧道重新建立。executor_tunnel 主机概览提供“恢复隧道连接”：服务端只验证既有目标、账号与当前绑定凭据，重新检测固定 SSH Host Key 和平台回连，再生成 Preview；确认时再次校验 Host/Connector/凭据/测试版本与明确资源授权，递增隧道 epoch/fence 后重新建立。保留 Host ID、Collector、历史数据及关联；不放宽凭据版本校验。该动作使用 host.manage + host.test，沿用审批、Step-up 与 PendingAction 提交边界。

集群采集组件的就绪副本从 argus-telemetry 中实际 DaemonSet 状态读取，资源查询的 Direct 和 Connector 两条路径共用白名单健康/容量投影；不交付完整 spec、注释、环境或 Secret。删除固定 60% 进度，采集分发版本与绑定/冲突失败状态分别来自真实查询。

待接入堡垒机同样使用紧凑列表，行内展示待审批、命令领取、安装进度及操作，避免未完成接入的多个大分区遮住已接入资源。
