# 产品与界面

## 菜单与 Tab

拟新增企业门户 `/alerts`，放入既有资源/可观测性菜单组。告警中心只有六个业务 Tab，Tab 使用路由查询参数保存选择，返回列表时保留筛选、分页和滚动位置。

| Tab | 列表和界面 | 需求 |
| --- | --- | --- |
| 当前告警 | 等级/通知状态/处理状态筛选；按服务合并视图；详情、确认、认领、评论、快速屏蔽 | D01、D07 |
| 告警历史 | 时间、资源、策略、指标与生命周期筛选；恢复现场值、版本快照、时间线和导出 | D02、D07 |
| 通知记录 | 渠道、状态、尝试次数、失败原因、通知内容、事件关联与受控补发 | D03 |
| 告警策略 | 多指标策略列表、评估健康、人工创建/编辑/复制/启停/删除、规则试算 | D04、D06 的人工配置入口 |
| 屏蔽与抑制 | 临时静默与依赖/等级抑制两个子视图；范围、原因、起止时间与命中事件 | D06 的人工配置入口 |
| 通知配置 | 四类渠道、多目标路由、消息模板、分组与重发间隔、测试通知 | 原始通知需求、D03/D06 支撑 |

2026-10-13 列表展示约定：当前告警与告警历史的「告警事件」单元格只展示可打开详情的告警名称和等级标识，不附带指标名、PromQL 表达式或服务标签；普通列表与合并视图遵循相同规则。资源、现场值/阈值、通知和处理状态、持续时间及负责人继续各列展示。完整指标表达式、规则快照和标签在详情中查看，搜索与指标筛选、历史导出仍使用原数据。

## 会话工作台与 Tool Hub

D04/D05/D06 由已有会话工作台提供。用户像查询主机一样输入自然语言，模型自行通过已有 Tool Hub 使用告警业务工具：

```text
用户在会话工作台提出告警需求
→ 模型调用 tool.search（工具查询）发现告警工具
→ 模型调用 tool.describe（工具详情）读取 Schema、前件与结果语义
→ 模型调用 tool.invoke（工具调用）使用只读工具或变更 Preview
→ 只读结果在会话中展示；变更由会话宿主显示 PendingAction
→ 用户确认一次，Action Executor 调用隐藏 Commit
```

告警工具注册在自有 Registry / Tool Hub 内部，模型侧继续只暴露三个元工具；工具检索、详情和调用按当前授权裁剪。会话不要求切换到告警模式或手动选择具体告警工具。原型中的示例问题属于自然语言输入，工具记录是确定性交互演示；正式版本复用 Agent Loop、会话消息、Tool Trace、ToolPresentationFrame 与 PendingActionCard。

## 组织与权限

D08 的告警能力配置加入现有 `/settings/org` 角色权限矩阵，显式资源授权复用现有资源授权页。告警操作审计作为「组织与权限」下的筛选视图，读取现有企业审计服务并限定告警领域与当前授权范围；不另建角色、授权或审计存储。告警中心不设置权限或审计 Tab。

原型侧栏中的「组织与权限」展示告警能力权限、显式资源摘要和操作审计，用来评审放置位置。正式界面延续现有组织设置页面的组件与布局。

## 规则与事件

- 策略统一持有资源/来源范围、指标规则和通知配置引用。
- 多规则有「各规则独立」「任一满足 OR」「全部满足 AND」三种明确模式。复合条件按相同 resource_id/source_id 和指定维度匹配；不同主机或不同来源不能自动拼接。
- 简单构建器生成 PromQL；高级查询只保留一个有效编辑来源。转换必须无损，失败保留原编辑内容。
- 人工配置按「名称与监控范围 → 查询与告警条件 → 评估与恢复 → 通知目标」分区；每条规则集中设置触发/恢复阈值、单位和等级，高级范围、异常处理与路由标签可展开。当前交互与验证见[2026-10-12 资源配置记录](../plans/frontend-redesign/resource-config-ui-20261012.md)。
- 创建/编辑先预览规则、范围、通知目标和启用行为，再确认；一次提交策略及其规则，不逐指标重复确认。
- 通知渠道可通过已有通知配置的预览/确认设置 `default_for_new_policies`。新建门户策略在渠道读取成功后一次性预选当前租户已启用的默认渠道，允许多个；无默认时保持空选。编辑、复制、取消预览后保留原目标，默认变更不修改已有策略或打开的草稿。API/工具仍使用明确的 `channel_ids`；默认属性不产生隐式发送或提交。
- NoData 与 Error 是评估健康；确认/认领是处理状态；静默/抑制是通知状态。三个维度分别显示。
- 静默、抑制和通知合并继续保留事件与历史。取消静默后重新计算当前状态和路由，不补发已恢复的旧触发通知。
- 人工确认不表示指标恢复；处理记录保存操作者、时间与备注，历史详情仍可评论。

## 确认体验

新增、修改、启停、删除策略、屏蔽规则、通知配置、补发/测试等外部副作用先形成公开影响预览。AI 路径固定沿用宿主 PendingAction。权限变更复用现有 IAM 流程。人工确认、认领与评论使用明确操作和现有授权/审计，不强制多一轮模型预览。

预览包含规则和对象版本、当前权限、影响范围、是否马上启用、通知目标；私有一次性 Token 和渠道密钥不进入页面或模型。取消/过期不执行，重复确认返回同一执行事实，版本冲突要求新预览。

## 原型覆盖

原型包含告警中心六个主 Tab、搜索/筛选/分页、按服务合并视图、详情时间线、确认/认领/评论、多指标增删与试算、统一预览确认、静默/抑制管理、四类渠道与路由和模拟通知测试/补发。会话工作台展示自然语言请求、工具查询/详情/调用记录、只读结果和宿主确认；组织与权限展示角色配置、资源授权摘要和告警审计。支持中英文、深浅色、键盘 Tab/方向键和对话框 Escape。

原型明确标记演示数据，所有状态只影响本地原型；渠道测试不发送 HTTP/SMTP，AI 不连接实际模型，原型参数不成为生产 Token。详情中的趋势为示例观测曲线。
