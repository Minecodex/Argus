## 全局完成定义

- 单文件不超过 2000 行，高内聚领域边界，前端通用控件只进入 @argus/ui。
- Enterprise 的 mock/real 显式配置；未知模式和缺少真实 URL 时 fail closed。
- 所有业务文案中英文，light/dark，三个桌面视口与键盘/读屏支持。
- OpenAPI/JSON Schema、客户端、权限注册表、SQL 与设计一致，无凭据原值进入模型/公开结果。
- 新写入覆盖幂等、撤权、版本冲突、取消/过期，查询覆盖完整性和复合范围。
- 多副本 Worker 的重复领取、陈旧 fence、重启、Redis 清空和任务恢复不丢唯一状态。
- 真实查询、通知适配器、会话工具、人工确认及数据库事实能通过共同 trace/event/execution 标识关联。
- Kubernetes E2E 用临时 Namespace，按所有权清理，并恢复被暂停的正式服务；保留其他项目/PVC/Secret/业务数据。
- 真实模型与真实渠道的验收分别追踪；模拟接收器或固定 Agent 回复不能替代它们。

## 状态与变更

`progress.json` 的 production_tasks 初始全部 todo。每次更新需附提交/测试/证据路径和未通过门禁；只有满足任务验收才改 complete。原型单独用 prototype 状态表达，不计为生产任务完成。

未纳入扩展若后续被用户确认，先调整 README 范围、架构影响、任务依赖和验收矩阵，再实现。

## 2026-10-08 实施授权与验收取向

用户已要求实施全部任务并确认：资源在已有评估账号的明确授权范围内动态匹配，新资源符合条件后自动纳入；本轮四类通知以真实 HTTP/SMTP 接收器完成协议验收，外部测试群/邮箱联通单独记录；临时 K8s E2E 通过后更新现有本地 Argus；告警业务区、表单和消息卡片对齐 Demo，现有会话/组织外壳及已有功能保留。

通知 Worker 增加专用凭据租约接收身份，绑定持久投递任务与渠道，不借用 MCP Adapter 身份。原型证据只作为视觉基线，正式完成必须有领域、协议、浏览器、真实模型、K8s 与本地发布的分别记录。
