## R17：自有工具目录缺少业务描述和关键词，中文检索漏掉已有工具（P2）

计划 [P5-T02～T04](./task-02-tool-discovery-and-gateway.md#p5-t02tool-manifest-与-catalog) 要求 Manifest 承载业务标题、描述、关键词，Search 对这些字段进行确定性检索，Describe 返回完整描述、结果语义与示例。当前 `mcp.Metadata` 没有可维护的标题/描述/关键词字段，`toolgateway.Manifest` 没有关键词/示例字段；Gateway 将标题拼成分类标签和工具名，描述再附加一次内部 Tool ID。

源码：[Registry 元数据](../../internal/mcp/registry.go#L36)、[Manifest 与构造](../../internal/toolgateway/gateway.go#L26)、[描述拼接](../../internal/toolgateway/gateway.go#L70)、[检索评分](../../internal/toolgateway/gateway.go#L272)。当前检索只匹配名称和这一拼接描述，没有独立的业务关键词来源。

同一正式 Registry、同一 `host` 分类、同一具有 `host.read/host.manage` 权限的主体，实测如下：

| 查询 | 目标工具 | 命中结果 |
| --- | --- | --- |
| `create` | `create.preview` | 1 项，正确命中 |
| `创建` | `create.preview` | 0 项 |
| `list` | `list` | 1 项，正确命中 |
| `列表` | `list` | 0 项 |
| `delete` | `delete.preview` | 1 项，正确命中 |
| `删除` | `delete.preview` | 0 项 |

同次 `tool.describe(host, create.preview)` 的描述为 `主机 Host / create.preview. host.create.preview`，不能解释该工具的业务用途与操作前件。英文对照命中证明工具确实存在且可发现，中文空结果不是权限或目录缺失造成的。

影响：模型把中文业务关键词直接传给 Search 时，会得到空结果；无关键词的列表和英文工具名仍可工作，不能据此声称所有中文对话都会失败。现有 Replay 使用已知工具名/确定性步骤，500/1000 目录测试证明大小与边界，不证明业务检索质量，因此可以在本项尚未实现时继续通过。

收口要求：在正式工具注册层补齐可维护的业务元数据及版本/Hash，Gateway 消费这些字段做确定性检索和 Describe；覆盖中英文业务词、合理同义词、排序、权限过滤、缓存失效和目录规模。不得恢复 Agent 的英文关键词候选选择器，也不应仅给当前三个测试词增加特殊分支。
