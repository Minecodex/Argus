## R12：导入来源失去授权后，离线 Workspace 访问入口仍放行（P1）

`workflow.import_result` 将受授权控制的业务结果写入目录，并在 WorkspaceFile 中保存 `source_result_refs`。结果读取、文件下载与交付发布都会重新检查来源的当前授权；离线 `read/write/edit/bash` 共用的 `service.access → ensure` 只检查 Workspace 使用权限、会话/Run 归属及生命周期，没有检查留存来源。通过访问入口后，`read` 直接调用文件 RPC，`bash` 可以读取目录中的任意工作文件。

复现步骤：

1. 在独立数据库建立当时可读取的 ToolResult 和对应导入文件元数据，内容 Hash 与来源 Scope 均合法。
2. 更新用户授权版本使来源 Scope 失效，保留 `workspace.use`；结束原 Run，以最新授权版本创建下一 Run。
3. 正式结果接口、`ReadFile` 和发布来源检查都返回 `TOOL_RESULT_FORBIDDEN`。
4. 同一最新主体、同一下一 Run 调用共用访问入口 `ensure`，仍成功返回原 Workspace，状态为 `ready`。

本轮实际复现到**领域访问入口放行**，没有分配 PVC、启动 Sandbox 或在其中读取字节。离线读取可以绕过文件接口来源检查的判断，依据该入口之后到 IO/Execute RPC 的完整源码路径；不把这项数据库复现描述成已完成真实 Sandbox 越权读取测试。

源码：[导入来源与校验](../../internal/workspace/import.go#L56)、[文件接口校验](../../internal/workspace/files.go#L164)、[共用访问入口](../../internal/workspace/service.go#L55)、[离线工具执行](../../internal/workspace/tools.go#L93)。

收口要求：让离线执行和文件交付遵循一致的当前来源授权策略。在挂载/执行前验证整个可读取目录的受控来源，覆盖任意路径读取及复制派生文件，避免只给 `read` 增加单路径判断而留下 `bash` 旁路。拒绝访问不能自动删除留存文件；仍须遵守明确删除前持久保留的决策。补充来源授权变化后下一 Run、热复用、直接读取和脚本读取的正式回归。

## R13：压缩缺少 Provider 用量仍被计为完整真实 Token（P2）

两条路径合并形成错误的验收结论：

1. Chat Completions 仅在 `request.Tools` 非空时加入 `stream_options.include_usage`；压缩请求不带工具，实际序列化请求没有该选项。
2. Compactor 未收到 usage 时，用字节数估算输入/输出，直接写入 `model_calls.input_tokens/output_tokens`，没有保存“估算/缺失”身份。P5 `usage_complete` 只检查调用成功及这两个值大于零，因此估算值也可被认作完整用量。

本轮调用正式 `Compactor.generateSummary`，使用本地确定性 SSE 服务返回成功摘要、**零 usage 事件**，并读取真实 PostgreSQL 落库结果：

```text
request_stream_options = nil
provider_usage_events = 0
persisted_input = 49
persisted_output = 10
usage_complete = true
```

其中 `usage_complete` 使用与正式 P5 统计 SQL 完全相同的判断条件。该复现没有调用真实模型或产生外部模型费用。它证明当前门禁可能误把缺失用量视为完整，不能据此宣称现有六个真实任务已经产生错误评测结果——真实评测还没有运行。

源码：[请求构造](../../internal/integration/modelprovider/provider.go#L150)、[压缩估算与落库](../../internal/agent/compaction.go#L298)、[评测完整性条件](../../internal/app/argusdev/e2e_p5_real_model_results.go#L65)。当前 [运维手册](./operations-guide.md) 明确承诺 Provider 用量缺失时 `usage_complete=false`，该承诺尚未在压缩路径兑现。

收口要求：无工具的流式调用也请求用量；持久化区分 Provider 实报、估算和缺失，评测门禁依据来源完整性。覆盖缺 usage、部分 usage、失败调用和含压缩调用的统计，确保估算值不会作为真实 Token 通过验收。用量结算也应保留同一来源信息。
