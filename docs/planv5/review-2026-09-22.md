## R06：Preview 恢复后丢失待确认状态（P1）

`Loop.Handle` 每次进入均将 `pendingActionRef` 初始化为空。它只接收当前进程执行工具返回的 `ActionRef`，没有从已持久化的 Preview/ToolResult/PendingAction 恢复。已成功的工具也不会进入 `ListUnfinishedRunToolCalls`。

触发窗口：Preview 及其工具结果已提交，Worker 在下一轮模型总结或进入 `waitForAction` 之前退出。恢复后模型正常输出“请确认”，代码因本地引用为空而将 Run 标为 `succeeded`。数据库里的动作仍是 `awaiting_confirmation`，且没有 `pending_action_created` 事件；宿主通过该事件收集待确认引用。后续执行验证任务也会碰到 Run 终态提前返回。

本轮数据库复现结果：`run_status=succeeded`、`action_status=awaiting_confirmation`、`pending_action_events=0`，恢复期间模型请求一次。复现已保存 ToolCall、Artifact、ToolResult 与原生配对事件。

源码：[循环恢复](../../internal/agent/loop.go#L135)、[完成判断](../../internal/agent/loop.go#L310)、[已持久结果分支](../../internal/agent/loop_execution.go#L95)、[宿主引用消费](../../web/apps/enterprise/src/components/chat/event-reducer.ts#L121)。

收口要求：以数据库动作状态恢复等待/验证阶段，明确处理成功 Preview 后各个崩溃窗口；不能依靠模型重新 Preview 或终态 Run 重新执行提交。补齐 Worker 重启后宿主仍可单次确认、执行并进入只读验证的回归。

## R07：预检与运行阈值不一致，接受了必然无法推进的 Run（P1）

`Preflight` 用 `estimated > usable` 拒绝；Agent 在 `estimated >= 85% × usable` 时就停止推理并要求压缩。工具 Schema 与必要输入不可压缩，因此二者之间存在预检成功、创建 Run/Task 后立即失败的区间。

本轮空会话复现：32,768 上下文、1,024 输出预留，usable 为 27,648，运行硬阈值为 23,500。完整请求估算为 25,485，预检返回 `ready=true`、消息创建成功；Agent 进入 `waiting_system`，随后因没有可压缩历史而以 `CONTEXT_COMPACTION_FAILED` 失败，模型请求为零。

这违背运行前明确拒绝、容量不足不创建 Run/Task 的要求。复现使用加长工具说明模拟不可压缩工具集合，与客户 MCP Schema 扩大时进入同一条正式容量路径。

源码：[预检](../../internal/conversation/preflight.go#L99)、[阈值](../../internal/agent/context.go#L93)、[运行时压缩判断](../../internal/agent/loop.go#L175)、[无可用边界时失败](../../internal/agent/compaction.go#L89)。

收口要求：预检与运行使用同一预算规则，并区分不可压缩的固定内容与可压缩历史；补齐硬阈值前后、无历史、大工具集合及完整消息接受接口的边界测试。

## R08：Compactor 失败只写 Run，未追加 SSE 终态（P2）

`Compactor.fail` 只更新 `runs.status=failed`，没有像 `Loop.finishRun` 一样在同一事务追加 `run_state_changed`。事件流只扫描 ConversationEvent，靠终态事件结束；不会通过查询 Run 自动补出失败。

上述容量复现中，数据库 Run 已失败，而对应终态事件数量为 **0**。因此正在消费 SSE 的客户端无法收到这次 `run_failed`，流仍可能只发送 heartbeat，界面持续等待。相同缺口也适用于调用此函数的压缩失败/重试耗尽路径。

源码：[Compactor.fail](../../internal/agent/compaction.go#L386)、[正确的普通完成路径](../../internal/agent/loop.go#L493)、[SSE 读取与终止](../../internal/transport/httpapi/conversation_handler.go#L222)。

收口要求：统一事务性、幂等的 Run 终态及事件写入；测试压缩无边界、供应商错误、重试耗尽与并发取消，保证恰好一个终态事件且浏览器停止等待。
