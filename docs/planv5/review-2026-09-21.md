## 四项明确实现缺口

### R01：全部正式 Preview 尚未进入 Tool Gateway 与同包模板（优先级高）

- 实际组装 ResourceTools 和 Telemetry Tools 的 Registry 后，模型可见的 Preview 只有六个：Host 与 Kubernetes Cluster 的 create/update/delete，均有模板。
- Collector 安装、配置、升级、修复、卸载等正式 HTTP Preview 已存在，但 Telemetry Registry 只注册查询工具。堡垒机、卸载等其他正式 Preview 同样不能据现有六项 CRUD 宣称已全部迁移。
- 因此后台 HTTP 业务回归成功，不代表 Agent 能经 `tool.search/describe/invoke` 发现、预览并展示这些变更。
- 源码：[资源注册](../../internal/toolgateway/resources.go#L27)、[遥测注册](../../internal/telemetry/tools.go#L20)、[实际装配](../../internal/app/server/app.go#L174)、[Collector HTTP 入口](../../api/openapi/argus.yaml#L404)。
- 复现：`preview-coverage.log` 列出六个注册项，针对“全部正式 Preview”的 Collector 覆盖断言失败。
- 收口要求：列出正式 Preview 的完整清单，为每项补齐 Manifest、Schema、授权、同包 Presentation Builder/模板与隐藏 Commit 路由，并通过 Gateway/宿主确认的回归；不能仅复用 HTTP 测试代替。

### R02：Sandbox 快照没有约束实际执行时的运行环境（优先级高）

- `BuildTools` 的版本只有 `Profile.Revision:Backend.Version:Image.Digest`，没有 Profile/Backend 身份。
- Invoke 闭包只捕获工具名；`builtin → access` 在真正执行时再次调用 `SelectWorkspaceRuntime`，并未将 Run 中冻结的运行环境身份和版本用于执行前对比。
- 可触发场景：模型生成期间平台修改 Profile/Backend/镜像，或将旧 Profile 停用并启用另一个。实际调用可能选到新环境，而非按旧快照明确失败。不同 Profile/Backend 拥有相同 revision/version、相同镜像时，现有版本字符串也无法区分身份。
- 这是静态调用链确认的缺口，本轮未以 Kubernetes 并发修改复现。
- 源码：[版本与 Invoke 闭包](../../internal/workspace/tools.go#L63)、[实际重新选择](../../internal/workspace/service.go#L165)、[选择规则](../../internal/storage/postgres/queries/sandbox.sql#L53)。
- 收口要求：冻结并校验 Profile ID/revision、Backend ID/version、Image ID/digest；实际执行使用固定身份，失效返回明确错误，新 Run 再使用新配置。

### R03：SSE 已开始后的 MCP 取消缺少协议通知（优先级中）

- 当前只在 `HTTP.Do` 返回错误且 Context 已取消时发送 `notifications/cancelled`。
- 响应头已收到、正在 `readSSE` 读流时取消，返回的是流中断/结果未知，不经过发送取消通知的分支。
- 结果未知和禁止重放的保护仍存在；缺失的是向上游发送明确的取消意图，不能把关闭本地响应流等同于完成 MCP 取消协议。
- 源码：[请求阶段取消](../../internal/integration/remotemcp/client.go#L164)、[SSE 分支](../../internal/integration/remotemcp/client.go#L190)、[流结束处理](../../internal/integration/remotemcp/client.go#L245)。
- 复现：`sse-cancellation.log` 的真实 HTTP/SSE 用例在进入响应体读取后取消，收到 **0 条**取消通知，断言失败；业务 POST 未被重复发送。
- 收口要求：统一请求、读流、恢复阶段的取消处理，保留原请求 ID/Session，使用独立且有界的取消 Context，未知写结果仍不得重放。

### R04：纯模型文件的 Workspace 无法通过页面明确删除（优先级中）

- 删除按钮条件为 `busy || disabled || !files.data?.length`。
- `listFiles` 读取 `workspace_files` 元数据表；`write/bash` 写出的普通工作文件不会自动新增该表记录，发布产物也使用独立的 delivery 记录。
- 因此无需上传、由模型直接创建工作文件的会话，可能已经拥有 PVC、文件和产物，但页面仍显示零文件并禁用“删除 Workspace”。后端删除 API 已实现，UI 入口未闭环。
- 本轮按前后端调用路径确认，未新增浏览器复现。
- 源码：[按钮禁用条件](../../web/apps/enterprise/src/components/chat/conversation-workspace.tsx#L139)、[文件列表来源](../../internal/workspace/files.go#L132)、[基础工具写入](../../internal/workspace/tools.go#L122)。
- 收口要求：依据 Workspace 是否存在及其生命周期/授权决定能否删除，区分未创建、空目录、纯模型文件、仅交付记录和已删除等状态。

## 一项需要对齐的实现偏离

### R05：当前是每次操作结束销毁实例，不是空闲 15 分钟复用

`access` 先撤销已有工作负载，`Access.Close` 又无条件撤销当前工作负载。下一次 read/write/edit/bash 或文件 IO 会重新创建实例。15 分钟配置仍用于遗留实例的清理，不是正常计算实例的空闲复用窗口。

该方案确实保护旧后台写入者撤销和目录持久化，也已写入运维手册；但与按正常空闲窗口保留实例的策略不同，当前没有热实例复用路径及对应预算。这不代表目录持久化失败，也不要求恢复进程内存；需要明确 15 分钟是否仅为异常兜底，并对齐实例复用及冷/热启动预算，不能混用两种生命周期描述。

证据：[进入时 Retire](../../internal/workspace/service.go#L158)、[关闭时 Retire](../../internal/workspace/service.go#L245)、[预算要求](./task-06-e2e-and-documentation.md)。
