## R09：审批拒绝和执行失效后，Run 没有收尾或继续任务（P1）

两条正式路径已复现：

1. 模型 Preview 进入等待，用户确认后由独立审批者拒绝。`action.Service.Decide` 写入 Approval/PendingAction 的 `rejected` 并记审计，但没有更新 Run 或创建 Agent 继续任务。
2. 用户确认后、实际提交前授权版本失效。`action.Executor.Handle` 正确拒绝变更，写入 Execution `failed/ACTION_INVALIDATED`，然后返回成功处理；该分支没有安排 Run 的后续收尾。

结果：两条路径中的 Run 都保持 `waiting_input`，待处理任务为 **0**。审批拒绝路径的 Run 终态事件也为 **0**；`GetActiveRunForConversation` 仍将它视为活动 Run，因此后续消息会被 `ErrRunAlreadyActive` 拒绝，用户需要额外手动停止 Run 才能继续。

正常提交成功和显式取消的既有回归不能替代这两个异常分支。当前动作 Reconciler 只扫描 `result_unknown` Execution，不会自动补处理这些已拒绝/失败的状态。

源码：[审批拒绝](../../internal/action/service.go#L174)、[执行失效](../../internal/action/executor.go#L75)、[现有 Reconciler](../../internal/action/executor.go#L575)、[活动 Run 限制](../../internal/conversation/service.go#L182)。

收口要求：把动作终态变更与 Run 收尾/继续任务纳入同一可靠流程，覆盖拒绝、执行前失效及相关竞争窗口；保证终态事件一次、会话可继续，并保留拒绝实际变更的安全检查。

## R10：Run 读取和手动压缩缺少会话归属校验（P1）

会话读取、结果读取和 Run 取消均校验会话所有者；`GetRun` 只按企业 + Run ID 查询，`RequestCompaction` 也没有比对当前 actor 与 Run/Conversation 所有者。HTTP 路由只检查 `conversation.read/use` 权限，未补齐资源归属判断。

复现使用同一企业的另一个活跃成员，明确授予这两个路由所需权限：读取原用户会话被拒绝，取消原用户 Run 被拒绝，但手动压缩请求成功，并为原 Run 创建了 **1 个 compaction 任务**。任务保留原始 Run 所有者；后续压缩仍按该 Run 的上下文和计费主体执行。本次未调用真实模型或产生外部费用。

`GetRun` 的公开响应仅含运行元数据，本轮没有将其描述为完整聊天内容泄漏。此问题发生在同企业不同成员之间；查询的企业条件仍然存在。

源码：[GetRun](../../internal/conversation/service.go#L245)、[RequestCompaction](../../internal/conversation/service.go#L270)、[HTTP 入口](../../internal/transport/httpapi/conversation_handler.go#L169)、[取消的正确归属检查](../../internal/conversation/service.go#L249)。

收口要求：所有 Run 对外入口使用一致的主体/会话归属策略，并在创建任务的事务中重新验证；增加同企业不同成员、跨企业及删除会话后的读写拒绝测试。

## R11：Workspace 删除状态没有进入实际模型上下文（P2）

Task 01 明确要求：恢复时关联持久 Workspace 身份，已明确删除的目录不能从旧摘要恢复为存在。当前 `loop.messages` 按授权 Scope 恢复旧摘要和附件路径，`loop.context` 的权威 checkpoint 仅含 `actions`；没有 Workspace 当前身份、生命周期或文件失效事实。`Snapshot.WorkspaceID` 虽有定义，Workspace Provider 未赋值。

复现建立合法的旧摘要，内容为 Workspace ready、`/workspace/input.csv` 可继续使用；调用正式 `Workspace.Delete` 后，将隔离夹具的元数据置为清理完成，再创建下一 Run。比较 ContextAssembler 实际提供给 Provider 的 `Messages`：删除前后**完全相同**，旧的 ready/文件可用说法保留，删除事实不存在。

本项复现只操作数据库元数据，未分配 PVC；既有 P5 的文件清理和旧写入者撤销证据继续有效。确认的缺口是上下文未同步当前状态，不能据此断言物理文件被恢复。

源码：[历史摘要](../../internal/agent/loop_history.go#L38)、[历史附件](../../internal/agent/loop_history.go#L69)、[权威 checkpoint](../../internal/agent/loop.go#L361)、[实际 Provider 输入](../../internal/agent/loop.go#L169)、[Workspace 工具贡献](../../internal/workspace/tools.go#L24)。

收口要求：向每次实际模型投影注入当前 Workspace 身份/状态和失效文件引用，覆盖删除中、删除完成、新目录创建和跨 Run 恢复；保留原始 ConversationEvent，不靠改写历史来掩盖状态变化。
