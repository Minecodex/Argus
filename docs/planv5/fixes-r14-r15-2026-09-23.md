## R14：凭据返回边界

Remote MCP 在解码 JSON-RPC 信封时检查本次 Authorization 的已知认证值，包括 Bearer 值、Basic 编码值、解码后的用户名/密码组合和密码。JSON、SSE 及 SSE 结束前最后一帧共用同一入口，检查解码后的字符串、对象键及嵌套值；目录描述、Schema、结果、错误和通知均先经过检查，之后才能交给业务适配器。

命中时拒绝整个信封，返回不含认证值的 `MCP_RESPONSE_CREDENTIAL_EXPOSED`，不通过替换 Schema 默认值/枚举来掩盖问题。目录拒绝不会保存不安全工具快照；业务请求已经发送而结果被拒绝时记录 `result_unknown`，停止自动推进，不重发写调用。中英文错误提示已接入现有错误契约。

策略仅针对平台持有的本次已知认证值，不声称识别任意编码后的秘密。匹配采取保守拒绝，极短或与业务文本相同的认证值可能导致拒绝；应检查上游返回和认证配置，不关闭检查。Basic 用户名本身不是单独的秘密匹配项，完整认证组合及密码仍受保护。

正式回归覆盖 Bearer/Basic × JSON/SSE/EOF 帧 × 描述/Schema/文字/结构化/对象键/错误；另通过加密凭据服务、普通成员授权、目录刷新、结果持久化及读取验证不安全值未进入 Artifact 或模型投影。

## R15：缓存用量与摘要来源

- Chat 的 `prompt_tokens_details.cached_tokens` 与 Responses 的 `input_tokens_details.cached_tokens` 统一解码到缓存输入用量。缺失和明确零分别记录为 `missing/provider`；缓存是输入总量的子集，不重复相加，不擅自套用供应商折扣价。字段依据 [Chat 用量示例](https://developers.openai.com/api/docs/guides/predicted-outputs) 与 [Prompt caching 文档](https://developers.openai.com/api/docs/guides/prompt-caching)。
- ModelCall 保存缓存用量及来源；公开统计、前端和真实模型统计单独返回 `cached_input_tokens/cached_usage_complete`。缓存细项未报告不伪造零，普通输入/输出完整性与缓存覆盖率分别表达。
- `ContextSource` 与组装后的消息一起传递，保留实际读取的摘要对象和事件范围。ModelCall 在创建时记录 `context_snapshot_id/context_snapshot_hash`；派发只更新实际请求 Hash，不再用当时的活动摘要或最新事件计数覆盖来源。
- 后续工具结果按实际持久事件的序号推进来源范围。压缩调用也记录其实际使用的上一摘要身份。数据库用 ID、企业和 Hash 联合外键约束摘要引用，空引用与空 Hash 必须同时出现。

回归验证：组装 A 后激活 B、再追加新事件，调用仍使用并记录 A 及原范围，下一次组装才读取 B；不匹配的摘要 Hash 被数据库拒绝。另覆盖双协议缓存缺失/零/命中/非法值、压缩的缓存落库和输入总量不重复累计。
