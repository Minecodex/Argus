## 执行隔离与租约

新增 `argus-workspace-supervisor` 只存在于离线计算镜像，管理 UID 10001，仅保留 SETUID/SETGID/KILL。用户命令使用独立 UID >=100000，清空 capabilities、设置 no_new_privs，不继承管理环境。管理 TLS 在 0700 父目录后隔离，用户不能读取管理密钥或 `/proc/1/environ`。

Supervisor 使用 pidfd 撤销全部用户 UID 进程，包括脱离进程组的后台写入者；文件角色只注册固定文件 RPC。复用换绑等待旧 RPC 退出，不依赖 Redis TTL 或 RWO。中断上传经原子写入回滚临时文件，保留旧目标；旧 fence 与已释放 fence 均拒绝。

证据：`build/p5-supervisor-linux-proof-final-20260921.log`、`build/p5-fix-targeted-20260921-final.log`、`build/p5-workspace-renewal-20260921-final.log`。跨月轮换沿用原有按实例创建月份结算规则，不迁移历史数据。

## 2026-09-22：取消闭环与业务入口回归

M10 b 轮通过 M3、M4 和 p5-native，并成功从模型 Gateway 生成首个 Collector Preview、模板和来源 Run；用例把取消 Run 的 HTTP 200 误写为 202，按失败清理。校验后确认原有 9 个 PVC、27 个工作负载和就绪数均未改变。

继续沿取消链路发现，动作取消原先不会结束其等待中的 Run，也没有 SSE 终态。现已修复：

- 取消当前正在等待的 Preview，在同一事务中取消 Run 并追加终态事件；取消其他动作不终止当前等待，幂等重放不重复追加事件。
- Preview 在模型最终回调前已取消时，Loop 不再把 Run 置回等待；已经终态的 Run 不会被晚到回调复活。
- 显式取消 Run 校验发起者并同步追加终态事件；模型流和 Tool 请求共同观察持久取消状态。
- 只有创建 Preview 的调用会产生确认等待；读取或取消动作不会再次要求确认，保证提交后的只读验证能完成。
- 前端把对应终态显示为取消；M7 新用例仅调用一次动作取消，直接验证 Run 和 SSE 终态，移除了额外取消 Run 的测试补救步骤。

真实 PostgreSQL 和相关 Go 测试通过：`build/p5-preview-cancel-20260922-final.log`；14 项前端定向测试通过：`build/p5-cancel-ui-tests-20260922.log`。最新完整 Go、前端类型/单元/lint、契约一致性分别见 `build/p5-go-all-20260922-cancellation.log`、`build/p5-web-*-20260922.log`、`build/p5-final-contracts-20260922.log`。d 轮与 M10 完整复测仍待通过。

## 空闲回收并发收尾

e 轮在自然空闲回收时遇到 PostgreSQL `40001`，导致旧 Pod 撤销后的元数据收尾延迟。现在会话结算使用明确的“配额行 → 会话行”锁顺序和 Read Committed 事务；用量原子累加、同一会话只结算一次，结算月份与预留的创建月份一致。已终止会话不能被迟到状态或续期写入复活。

Workspace 仅在确认旧工作负载已撤销后，才允许元数据失败释放清理租约供下一轮重试；物理撤销失败仍保留保护租约。8 个并发结算者、月份归集和终态不复活连续三轮通过，见 `build/p5-finalization-concurrency-20260922.log`；最新完整 Go 通过见 `build/p5-finalization-go-all-20260922.log`。e 轮保留失败记录并完成清理，f 轮继续相同期限的完整验收，没有通过放宽时限掩盖问题。
