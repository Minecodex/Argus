## 最终聚合校验与失败行为

- Provider 在流结束时验证整次聚合用量，覆盖先报缓存、后报输入、重复更新、输入回退及后续更正。负值和同一帧内明显矛盾仍在解析入口拒绝。中途断流且已接收的聚合值矛盾时，同样返回 `MODEL_USAGE_INVALID`。
- 推理必须等完整流通过后才执行工具。用量异常时保存失败 ModelCall、结束 Run，不调用已生成的工具，不自动重试。压缩不保存新摘要；硬限制压缩结束等待中的 Run，手动/软限制压缩使任务永久失败，保留既有合法摘要及已结束 Run 的状态。
- 合法解析的非负原始观察值作为诊断保存，三个来源全部标记 `invalid`，完整性为 false。被解析入口拒绝的非法帧不继续转发，不将负数写入数据库。
- 金额保留调用前预留估算，额度结算来源为 `invalid`，不从矛盾的 Token 数重新计算。该金额不是供应商实际账单。
- 数据库只允许失败/取消记录具有完整的 invalid 来源组；Provider 缓存必须同时具有实报输入总量且不超过它。公开用量、真实评测和 Replay 合计均排除 invalid Token。
- 新错误码和双语错误提示已进入统一契约。直接修改开发期数据库基线并生成 SQLC；不增加旧数据迁移或兼容包装。
