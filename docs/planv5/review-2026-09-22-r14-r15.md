## R14：客户 MCP 反射认证值时，凭据进入模型定义和结果（P1）

计划要求 MCP 凭据仅由适配器使用，不能回显给模型/普通用户，也不能写入 ToolResult、Artifact 或 Workspace，见 [Task 04 凭据边界](./task-04-opensandbox-and-mcp.md#L113)。管理接口已经做到凭据只写，通用 Secret API 也拒绝读取 MCP 托管 Secret，但这些保护没有覆盖 MCP 返回数据。

复现建立管理员配置的 Bearer 连接，将连接授权给普通成员；该成员具有会话读写权限。测试服务器将收到的 Authorization 头原样放入 `tools/list` 的工具描述及 `tools/call` 的文本返回值。随后执行正式 BuildTools、Invoke、`persistToolOutcome` 和 `ReadToolResult`，得到：

```text
generic_secret_api_denied = true
granted_member_result_read = true
model_tool_description_contains_credential = true
raw_artifact_contains_credential = true
model_projection_contains_credential = true
```

这说明同一份本应只供适配器使用的凭据，可以通过目录描述进入模型工具定义，也可以通过工具正文进入持久 Artifact、成员结果读取和模型投影。普通字段名过滤不能解决它：这里的字段是正常的 `description/text`，值也不带 Argus 私有令牌前缀。清空适配器局部授权变量不会删除返回数据中的副本。

源码：[直接拼接客户描述](../../internal/enterprisemcp/tools.go#L53)、[直接返回客户结果](../../internal/enterprisemcp/tools.go#L137)、[完整结果序列化](../../internal/agent/loop_execution.go#L170)、[Artifact 写入](../../internal/agent/loop_execution.go#L204)、[模型结果投影](../../internal/agent/projection.go#L18)。

本次已复现到模型工具定义、持久结果和模型投影，没有向真实模型发送凭据，也没有启动 Sandbox 导入这些内容。不能据本测试声称发生过真实客户凭据泄漏。

收口要求：在 MCP 返回数据进入目录快照、ToolResult、Artifact 和模型之前，建立能够识别本次托管认证值的处理边界；覆盖工具描述、Schema 中的值、文字/结构化结果及错误诊断。Schema 无法安全处理时应明确拒绝，不静默改坏契约。补充 Bearer、Basic 及 JSON/SSE 返回路径的正式回归。此要求针对平台持有的已知认证值，不宣称能识别任意客户服务器编码后的秘密。

## R15：ModelCall 的缓存用量和摘要来源关联未补齐（P2）

[Task 01](./task-01-agent-core-and-context.md#L92) 与 [主设计](../16-agent-harness-and-context-management.md#L111) 要求 ModelCall 保存实际使用的 ContextSnapshot ID，并记录缓存 Token。

当前源码与迁移后数据库显示：

- Provider 的 usage 解码、`TokenUsage` 和 `model_calls` 仅保留输入/输出总量及各自来源，没有缓存 Token 的解码、存储或统计字段。
- ModelCall 保存实际请求 Hash、工具快照 Hash、能力 JSON 和事件范围，但没有记录当次使用的会话 ContextSnapshot ID。`loop.messages` 读取活动摘要后仅返回消息、当前输入和授权 Scope，所用摘要身份没有传到 ModelCall 写入路径。

`tool_snapshot_hash` 关联工具集合，不能替代历史压缩摘要的身份。缺少显式关联时，后续摘要替换或并发压缩后，无法直接从 ModelCall 定位当次采用的摘要版本。源码：[摘要读取与返回](../../internal/agent/loop_history.go#L40)、[ModelCall 创建](../../internal/agent/loop.go#L381)、[派发记录](../../internal/storage/postgres/queries/planv5.sql#L224)、[用量结构](../../internal/integration/modelprovider/usage.go#L7)。迁移后列清单保存在审计目录的 `model-call-columns.txt`。

本项是明确的计划缺项，不是 R13 修复失效：输入/输出实报与估算的区分已经实现并验收，缺少缓存细项也不能据此推断已记录的总 Token 数值错误。收口应补齐缓存用量来源、实际摘要身份的传递/持久化及相应恢复/统计回归，避免用“当前活动摘要”推断历史调用。
