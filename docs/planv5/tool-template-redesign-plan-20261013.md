# 工具绑定模板与内部展示闭环：改造清单

2026-10-13 用户明确希望：每个工具绑定一个 Template，Template 内完成布局、图表、展示状态和交互；遇到缺失或低效的数据查询，可增加专用接口。本文件保留已授权的改造范围与布局，v2 协议和模板已开始实现，验收及发布状态统一见[实施记录](./template-v2-implementation.md)。

## 分工与现有边界变化

工具注册声明一个固定模板入口；相近工具可以复用模板包内的代码。模板包持有 HTML/CSS/JavaScript、展示逻辑和所需的固定版本依赖。企业门户只保留通用宿主，不按工具名称维护业务渲染分支。Runtime 处理隔离、主题/语言、模板生命周期及通用数据通道。

模板从 Tool Result 获得初始数据，负责组织界面；需要补查时通过限定能力的数据通道调用工具对应的只读接口。后台仍负责数据真实性、授权和查询预算，模板不能自行从 UUID 推断名字或单位。

这会扩展当前 v1 的“只接收一次展示快照、Bridge 无查询”的边界。拟增加的能力先限定为已生成结果读取、名称与业务上下文批量补全、详情补充及已有结果分页。接口按 Presentation/Query/Attempt 绑定访问范围；不开放任意 URL、任意工具调用或凭据。具体协议、接口 Schema、缓存和幂等规则需随实施更新，而非在讨论阶段放开 CSP。

当前保留的“参数由 AI 决定、用户用对话纠正”规则继续适用。改时间/资源产生新查询，新结果保留独立历史。结果完成后自动进入展示，模板不依赖模型再次调用进度查询；这需要同步完善后台完成事件。

操作预览的业务详情可在模板内组织；确认、审批、授权及执行仍与现有确定性机制衔接，不能由展示代码决定业务提交。

## 优先补齐的只读接口能力

以下是能力清单，尚未确定具体路由名称；优先复用已有高效接口，再新增缺失能力。

1. **资源及业务对象批量上下文**：一次返回授权资源名称/类型、采集来源、实际识别的服务/数据库/设备信息；避免每条序列调用一次接口。
2. **指标序列展示上下文**：序列与资源/来源关系、真实指标说明和单位、聚合范围；无法识别的字段明确 unknown，派生表达式不继承错误单位。
3. **告警关联详情**：事件、当时策略/规则快照、授权资源名称、触发值/阈值、处理/通知记录；当前配置与历史触发依据分开。
4. **仪表盘封存结果视图**：冻结定义全部显示配置、执行范围、面板/目标状态、已封存样本、分片引用；按 Attempt 读取，不能混合恢复前后的数据。
5. **大结果游标与分片读取**：继续读取同一封存结果，保留来源、时间、完整性和截断标记；查询新数据属于新执行。
6. **安装/采集运行摘要**：合并当前版本、配置收敛、心跳、进度及错误等事实，避免模板轮询多个细粒度接口。

Template 请求数据使用通用受控通道，由服务端按当前登录主体与该展示绑定范围重新检查。数据请求的结果/分片可以被缓存，但不能绕过授权；冻结事实与后续加载的当前信息应标明各自时间。增加模板依赖时同步固定 Runtime/资产版本与历史兼容策略。
