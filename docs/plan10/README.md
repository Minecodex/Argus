# Plan10：观测查询（统一临时工作台）

状态：2026-10-28 已实现正式企业门户与资源查询接口，保留第三版 HTML 原型作为界面参考。正式实现与验收记录见 [实施记录](./implementation-status.md)；本次不替换现有正式部署。

[打开交互原型](./demo.html)。可直接用浏览器打开 `demo.html`；保留相邻 JS/CSS 文件及仓库中的 design tokens 路径。原型不依赖 CDN，不请求业务 API。

## 1. 当前方案

左侧通过 **观测 → 查询** 进入“观测查询”页面（2026-10-28 导航分组调整）。指标、日志、链路合并在一个临时工作台中，每个面板独立选择查询类型，可以同时排列 CPU 曲线、错误日志与慢调用链路。合并的是入口与交互，三个现有查询引擎和各自的结果结构保持独立。

页面只有 **查询工作台 / 指标与字段目录** 两个 Tab。查询工作台顶部不提供全局资源范围，资源范围通过每个面板的按钮独立选择；目录中的资源范围按钮放在指标搜索筛选行内，通过同款弹窗选择资源，仅筛选目录；时间筛选也放入该栏。工作台每个面板都提供 **构造器 / 语句** 两种模式，默认构造器；语句模式提供上下文补全。目录内以“指标 / 日志 / 链路”切换数据发现视图，这只是目录筛选，不切走或替换正在使用的查询面板。

所有查询仅在当前页面内存中存活：没有查询组实体、保存按钮、已保存 Tab、查询历史、自动恢复或持久化 API；不写 localStorage/sessionStorage/数据库。页面内切换目录、配色、语言或面板类型可以保留临时输入，刷新、关闭页面或离开工作台并销毁页面状态后清空。原型刷新会回到两张初始示例图，它们不是恢复的用户查询。

主机、Kubernetes、监控目标和应用详情继续保留概览与正式仪表盘，用“查询指标 / 查看日志 / 查看链路”快捷操作携带资源身份、来源和时间跳入同一个观测查询工作台。“监控采集”负责接入配置，“观测查询”负责临时排查，“仪表盘”保持独立的正式配置生命周期。

## 2. 当前页面的问题与 Prometheus 参考

从用户截图与当前源码看：

| 现状 | 使用成本 | 新方案 |
| --- | --- | --- |
| 只能从主机/集群详情进入三信号查询 | 不知道应该先选哪台资源，跨资源分析要来回切页 | 独立入口，进入后明确选资源范围；详情只提供带上下文跳转 |
| 时间、结果上限、运算、指标、模式等分为多块大表单 | 输入一句表达式前需要浏览大量配置，结果在首屏之外 | 顶部只保留共享时间和执行全部；每个面板独立选资源，语句紧邻结果；高级参数折叠 |
| 现有 Builder 表单冗长，DSL 为普通文本框 | 两种使用习惯都缺少高效路径 | 三类查询都默认紧凑构造器，可无损切换语句模式并使用智能补全 |
| “读取候选值”独立按钮 | 每个条件都要手工发现，缺少输入上下文 | 随光标给指标、函数、标签、标签值和窗口建议 |
| 单资源、单次临时查询状态 | CPU 与内存、主机与容器难以同屏对照 | 多独立临时面板、共享时间、联动十字线，允许三类信号同屏对照 |
| 有指标下拉框，没有完整目录 | 指标存在、集成支持、实际已采集容易混淆 | 资源维度的指标目录与版本化查询示例分层展示 |

Prometheus 的 Expression Browser 明确用于临时查询和调试，输入表达式后可看表格或时间曲线；这正适合这里的“排查工作台”。Prometheus 3.0 重写 UI，强调减少杂乱并加入查询树视图。参考的是语句与结果紧邻、快速反复查询的工作方式；Argus 还需要自己的多租户授权、资源身份、采集来源和目录解释。[Expression Browser](https://prometheus.io/docs/visualization/browser/)、[Prometheus 3.0 公告](https://prometheus.io/blog/2024/11/14/prometheus-3-0/)。

Prometheus 的查询页不替代 Argus 的仪表盘生命周期，也不意味着要额外部署一个 Prometheus 服务。当前 PromQL 已直接复用上游 Engine，由 Argus 适配 ClickHouse。

正式路由为 `/observe`。不需要再增加三个独立菜单或三个独立页面；目录中的信号分类不会影响工作台已建立的混合面板。原型新建面板默认指标，在名称后面的类型下拉框切换为日志或链路；从目录新建时自动带入对应类型和构造器条件。

首次正式访问没有上下文时，先选有权资源或从目录新建查询，不自动执行企业全部资源。默认相对时间为最近 1 小时，执行时冻结绝对起止时间。原型预置 CPU/内存结果仅用于评审布局。

从资源详情进入时带 `ResourceRef {kind,id}`、来源选择、时间、返回路径和预选 signal；资源名称只负责展示，不作为授权身份。Namespace、工作负载带 UID 和所属 Cluster，上下文不能从标签推断权限。

原型左侧“主机/Kubernetes”只演示带入范围。“仪表盘/应用/监控采集/告警中心”为导航定位示意，不模拟资源管理页面。

## 4. 多查询与上下对照

### 4.1 临时面板与构造器

工作台在内存中维护共享时间与多个有稳定 ID、独立资源范围的临时面板；A/B/C 是展示序号，调整顺序不改变查询身份，不创建“查询组”业务对象。

每个面板至少包含：标题、signal/language、resource_scope（mode 与资源引用集合）、来源快照、表达式、instant/range、step policy、图表/表格偏好、独立运行状态、最后一次执行快照。支持新增、复制、上移/下移、删除、执行/取消。清空所有面板后仍保留新建入口。

首期采用“一条查询一个面板”，同一表达式可以返回多个序列；面板之间允许混合 signal。暂不引入同图多语句、跨面板公式或无限布局网格。新增、复制、排序、删除、执行和取消都是临时操作。

| 类型 | 默认构造器 | 语句模式 | 结果 |
| --- | --- | --- | --- |
| 指标 | 指标、推荐计算/原始值/聚合/Counter rate、聚合分组；资源范围由面板按钮独立选择，后续扩展标签条件与窗口 | PromQL | 时间曲线 / 即时表格 |
| 日志 | 服务、级别、正文包含、记录/计数、记录上限 | Argus KQL | 日志记录 / 聚合表格 |
| 链路 | 入口服务、调用状态、最短耗时、Trace ID、记录上限 | 固定只读 GraphQL | Trace 列表 / 调用详情 |

构造器实时生成唯一查询定义，可展开“查看生成语句”。默认常用条件紧凑呈现，参数与高级选项按信号显示，不能把三类构造器强行塞进同一个通用大表单。指标 rate 仅对 Counter 提供，Gauge 不显示此选项。正式版扩展字段条件时复用已有 Builder 能力，不能拿原型支持范围缩减现有能力。

构造器 → 语句保留完整定义；语句 → 构造器必须通过现有服务端无损转换。无法表示的语法、聚合、投影、过滤条件必须留在语句模式，提示具体原因；不丢弃条件、不恢复上一次旧 Builder 来冒充转换成功。原型只对生成过的有界样例做精确往返识别，未实现真实解析器。每个 signal 的临时输入可在同一面板切换类型时保留，返回时清除旧执行状态并要求重查。

### 4.2 对照规则

- 面板只共享冻结的时间窗口，各自持有独立资源集合与来源快照。按一次“执行全部”只解析一次 `now`，但每条请求使用各自的 ResourceRef/来源范围；并发有界，单面板失败不阻止其他面板显示自己的状态。
- 面板表达式可在授权范围内进一步过滤主机、Namespace、设备等；不能通过标签扩权。同屏混合资源类型要标明实际来源与单位。
- 某面板资源范围变化只作废该面板的旧结果与在途请求；其他面板的条件、结果与在途请求保持原样。共享时间变化才统一作废所有面板。执行中编辑、切范围、删除或取消时，旧请求返回不得覆盖新状态。
- 图表联动同一时间位置的十字线；保留各自单位与 Y 轴，不把 CPU 百分比、CPU 核数、内存字节强制合并。
- Range 显示曲线；Instant 以统一结束时间显示表格。Range 表格需要注明展示原始点、最后值还是统计值；原型明确使用最后值。
- 步长默认自动，考虑时间跨度、图宽和采样周期；高级选项允许调整。结果序列上限、采样预算和查询超时是不同参数，不再放一个含义不清的“结果上限”在所有信号顶部。
- 自动刷新默认关闭，P1 可提供关闭/30 秒/1 分钟等受控间隔；刷新中不叠加未完成请求，页面隐藏时暂停。不把后台轮询伪装为实时流。

### 4.3 面板资源选择与目录筛选

标题行顺序为：序号 → 名称 → 指标/日志/链路下拉框 → 语言提示 → 资源范围按钮。按钮展示“全部有权资源”或已选资源摘要，完整名称可在弹窗中查看。三种 signal 和两种编辑模式都使用同一个面板级范围，不再在指标构造器中重复放“资源条件”下拉框。

正式版复用现有 [DashboardScopeFilter](../../web/apps/enterprise/src/components/dashboards/dashboard-scope-filter.tsx) 与共享 [ResourcePickerDialog](../../web/packages/ui/src/resource-picker.tsx) 交互：

1. 点击面板按钮打开居中弹窗，标题说明仅应用于哪一条查询。
2. 按主机、集群、Namespace、应用、监控目标切换类型，支持名称/所属资源搜索、多选、查看已选项。
3. 搜索和类型切换不清除其他分类已选项。提供“全部有权资源”和“清空选择”；二者是不同模式。
4. 弹窗内修改只更新临时选择。取消、Esc、关闭或点击遮罩均放弃本次修改；只有“确认选择”提交给所属面板。
5. 确认后只清除该面板结果，表达式保持不变并等待重新执行。复制面板时深拷贝资源集合；后续修改彼此独立。
6. `all_authorized` 表示按服务端重新鉴权后的全部可读范围；`explicit` 配合空集合表示无资源，绝不回退全部。原型也保留这一差异。
7. 切换面板类型时保留该面板当前资源集合，若所选资源没有对应信号则明确显示无数据，不自动扩展范围。

目录使用独立的 `catalog_scope`。资源范围按钮通过共享弹窗支持多选，与指标名称搜索、资源类型、来源、已观测状态和时间放在同一筛选栏并取交集；修改目录范围不会改动或使任何已有面板结果失效。从目录新建指标查询时，仅新面板继承当前目录范围。

资源详情快捷入口追加一条带该资源范围的新查询，保留已有面板。日志关联链路同样追加面板并继承原日志面板范围，不改变其他查询。

### 4.4 临时状态生命周期

- 页面内切换工作台/目录、语言、主题，保留临时面板及当前输入。
- 切换面板的 signal，保留该面板各 signal 在本页的临时输入，切回时重新执行；不将 PromQL 文本直接当 KQL 或 GraphQL。
- 修改语句、构造器条件、资源、来源、时间时使对应结果失效；取消、切类型、删除后迟到的响应不得回写。
- 刷新或关闭后清空，不提供查询组命名、保存、列表、历史、分享定义或恢复机制，不引入持久化字段/API/表。
- 目录中的“复制语句”只复制文本，“新建查询”只追加继承目录范围的临时面板；不保存面板、不转仪表盘草稿，也不触发发布。

## 5. 指标目录：三层事实，不是一张硬编码清单

### 5.1 支持目录、观测目录、语句模板

| 层级 | 来源 | 能回答什么 | 不能说明什么 |
| --- | --- | --- | --- |
| 集成支持定义 | 版本化 IntegrationDefinition/采集器 metadata 与维护的指标说明 | 某组件和版本可能采什么、单位与类型约束 | 不代表目标已启用、配置正确或已有样本 |
| 实际观测目录 | 当前授权范围、来源版本和时间范围下的 Catalog 查询 | 本次范围实际出现的指标、字段、标签值、最后样本与覆盖范围 | 不能由配置或模板反推样本存在；分页/失败不能说“全部” |
| 推荐语句模板 | 版本化模板，绑定来源类型、指标签名、维度与单位约束 | 怎样查询吞吐、利用率、P95、Top N 等 | 不保证每个目标都有所需指标，也不能忽略不同 receiver 的命名和语义 |

默认勾选“仅看已观测指标”；取消后可查看当前集成支持但未观测的指标，并明确标注未观测/元数据未知。请求失败单独显示“目录读取失败”；不得显示为空清单并暗示无指标。

不同来源的同名指标如果类型、单位或语义冲突，要按来源拆项，或提示冲突并要求选来源。不能仅按 metric name 合并。目录身份至少包含 `source_type + integration_version + metric_name + type/unit signature`。

### 5.2 列表与详情

“指标与字段目录”通过指标/日志/链路分类切换；指标分支保留完整指标目录，其他分支显示各自字段、候选值和查询示例。切分类不改变工作台内容。

保持项目统一的 DataTable 与紧凑 FilterBar。名称/说明搜索、资源类型、来源类型、仅看已观测等筛选取交集，切 Tab 保留条件。数据量大时必须服务端分页和搜索。

列表字段：指标名、中文/英文含义、类型、原始单位、资源类型、采集来源、观测状态。正式版补齐授权覆盖资源数、最后样本时间、目录完整性；不要为凑齐列而填假值。

侧边详情包括：

1. 指标语义、单位、类型与来源版本；实际无法获取的 HELP/TYPE/unit 标为未知。
2. 适用资源与授权覆盖范围，不仅限于 Host/Cluster，也包括 MonitoringTarget、Application/Service、Namespace 等 Plan8 身份。
3. 已发现标签、标签类型与候选值。候选值可分页搜索，并显示发现范围及截断/失败状态。
4. 推荐语句与解释、参数、所需指标、适用条件、结果单位、缺样本策略。一键复制或新建查询；不直接覆盖当前正在编辑的面板。
5. 采集状态与“查看采集配置”入口。采集配置读取仍遵循原权限，不因可查询数据就获得采集管理权限。

### 5.3 典型查询示例

以下名称取自当前仓库模板，只表示已知查询定义；实际是否可用要由当前 Catalog 与来源版本确认。

| 意图 | PromQL | 结果口径 |
| --- | --- | --- |
| 主机 CPU 忙碌率 | `1 - avg by (argus_resource_id) (system_cpu_utilization{state="idle"})` | 0–1 比例，展示时格式化百分比；不是所有 state 求和 |
| 主机内存使用率 | `system_memory_utilization{state="used"}` | 比例；操作系统统计口径需在说明中保留 |
| 主机网络吞吐 | `sum by (argus_resource_id, direction) (rate(system_network_io[5m]))` | 字节/秒；先 rate 后聚合，保留收发方向 |
| Pod 内存 | `k8s_pod_memory_usage` | bytes；分组维度取当前字段目录 |
| 容器 CPU | `container_cpu_usage` | cores，不能因名字含 cpu 就自动加 rate 或改成百分比 |
| Redis 内存 | `redis_memory_used` | bytes；没有有效总量/上限就不计算使用率 |

Counter 才提示 rate/increase。Gauge 不套用 Counter 配方。经典 Histogram 的 P95 需要 bucket + le + rate；Native Histogram 使用不同的表达式模板。缺少分母、单位不一致、样本不足或来源冲突时禁止自动生成貌似正确的结果。

这轮原型只放 7 个代表性指标。正式目录应覆盖项目已支持的全部集成，而不是把这 7 个条目硬编码为产品能力。

## 6. 编辑器智能提示

智能提示首期是确定性的上下文补全，不依赖大模型、不需要提交每一次按键给 AI。自然语言生成语句可以后续增加，但应先展示可编辑表达式与范围，由用户执行。

| 光标上下文 | 建议内容 | 数据来源 |
| --- | --- | --- |
| `system_` | 指标名、说明、类型、单位 | 当前 Scope 下的实际观测目录 |
| `ra` / `sum` | 函数、聚合、签名及适用类型 | 与锁定版本对齐的语言定义 |
| `metric{` / `metric{sta` | 标签名 | 当前指标 + 来源 + 范围的 fields 目录 |
| `metric{state="` | 标签值 | 指标、已填写条件、范围与时间约束下的 values 目录 |
| `rate(metric[` | `1m`、`5m` 等合法窗口 | 语言定义与采样周期提示 |
| `sum by (` | 可分组标签 | 表达式上下文可解析时的标签集合；不猜测聚合后的字段 |
| 日志条件、Pipeline | Argus KQL 字段/值/受控操作符和阶段 | Argus Parser 能力 + 日志 Catalog |
| 链路字段、参数 | 只读 GraphQL 方法、参数和返回字段 | 构建时导出的固定 SDL + 受权服务候选 |

交互：输入自动弹出，`Ctrl/⌘ + Space` 强制触发；↑↓ 选择、Enter/Tab 插入、Esc 关闭、Shift+Enter 执行。Enter 在没有建议时换行。插入只替换当前 token，保留语句其余部分；标签值处理引号和转义，不能以字符串拼接绕过语法。

建议项展示名称、说明、类型/单位，按上下文合法性、前缀匹配和使用频率排序。先显示本地语法建议，动态建议 debounce 约 150–250ms、限制页大小、可取消；缓存 key 包含主体、企业、授权版本、Scope hash、时间、来源、指标及已输入条件。Scope 变化立即丢弃旧响应和缓存视图。候选不完整时明确提示“继续输入以搜索”，失败允许重试而不是悄悄扩大范围。

正式编辑器建议采用 CodeMirror 6 的语言扩展：PromQL 可参考上游 [`@prometheus-io/codemirror-promql`](https://github.com/prometheus/prometheus/blob/main/web/ui/module/codemirror-promql/README.md)，上线前核对与后端锁定版本的语法差异及依赖许可；KQL 只开放 Argus 子集；GraphQL 使用固定 SDL，不启用生产 introspection。编辑器 lint 是提示，最后仍由现有 Go 引擎做硬校验。

原型使用三类紧凑构造器 + textarea 上下文补全。构造器按当前配置生成语句；精确识别生成过的样例，允许往返，不识别任意手写语法。样例结果可按资源、日志级别/正文、链路状态/耗时/Trace ID 过滤，日志可计数。它不是生产语义引擎，未实现完整语法解析、语义诊断、远程目录分页、分组标签补全或复杂嵌套表达式补全。

## 7. 与当前架构的衔接及需要说明的边界变化

当前真实依据：

- [M10 Query Engine ADR](../adr/telemetry-query-engine.md)、[引擎锁定文件](../../deploy/query-parsers.lock.json)：Metrics=上游 PromQL；Logs=Argus KQL 子集；Traces=只读 SkyWalking 风格 GraphQL。保持三引擎职责，不退回历史 LogQL/TraceQL 方案。
- [ObservePage](../../web/apps/enterprise/src/pages/observe-page.tsx)：已替换原 ResourceTelemetry；从明确空范围和空白指标构造器开始，按面板独立取数。
- [TelemetryQueryEditor](../../web/packages/ui/src/query-editor.tsx)：语句模式已接入共享 CodeMirror 6 编辑器；PromQL 编辑语法固定为与后端相同的 0.314.0，GraphQL 构建时读取后端固定 SDL。
- [查询编辑与字段目录](../planv2/query-authoring.md)：已有 `/dashboards/catalog/query` 的 fields、候选查询、分页、scope/cursor 绑定，以及无损 Builder/DSL 转换。
- [现有对象查询授权](../planv2/object-query-authorization.md)与 [Plan8 身份契约](../plan8/02-domain-data-and-authorization.md)：显式资源授权、来源可信身份、Namespace 与应用范围继续有效。

### 7.1 可直接复用

查询引擎、范围解析、预算、取消、审计、凭证屏蔽、结果投影、Catalog 领域服务、来源版本注册、Dashboard compiler 与现有 ObservationPanel。查询不会新增存储进程、采集链路、额外 Prometheus 服务或“拥有菜单即可查全企业”的权限。

前端共享呈现进入 `@argus/ui`；API 契约进入 `@argus/api-client`；页面编排与 `i18n/observability.ts` 在 enterprise。复用 design tokens、FilterBar、Tabs、DataTable、资源选择器和现有结果组件。所有正式文件控制在 2000 行内，支持中文/英文、深色/浅色，验收范围为桌面 Web。

### 7.2 已实施的边界调整

**变化一：资源详情内查询变为单一全局工作台。** 原入口可通过旧路由状态转换或显式跳转迁移，但不丢资源身份、来源、时间与返回路径。导航和状态位置变了，数据权限边界不变。

**变化二：目录读取的功能能力门禁。** 新工作台通过资源查询身份调用 `/enterprise/telemetry/query/resources` 和 `/enterprise/telemetry/query/catalog`，沿用四类资源读取能力及显式数据授权。现有仪表盘目录继续要求 `telemetry.dashboard.read`；共享的是底层目录与范围解析，不是放开原仪表盘 API。纯转换增加应用、监控读取主体，保留 CSRF 与只转换不执行的语义。

**变化三：共享编排从仪表盘组件中解耦。** 当前临时查询依赖 enterprise 的 `QueryTargetEditor` 和 Dashboard Scope Provider。将纯语言编辑、补全、Scope 展示和结果呈现抽成共享组件；领域执行仍由各调用者的明确 Actor 负责，不把临时查询伪装成已发布仪表盘。

上述入口和编辑器调整已经实施；权限、查询编辑和 Query Engine ADR 已同步。原型中的固定数值与轻量语法匹配不进入正式模式。

### 7.3 服务契约补齐

已复用现有领域服务，新增面向资源的目录 transport；三信号执行仍使用原 HTTP 入口，新增结构化 `scope`，与旧 `resource_ids` 互斥。

需要明确的请求上下文：`ResourceRef[]`、来源选择、冻结时间、语言、查询定义、instant/range、step、预算和客户端查询 ID。每个执行结果记录自己的 Scope hash、绝对时间、单位、完整性与执行状态。

补全/目录除现有 `kind=fields` 外，需要验证 metric metadata、label values 与查询过滤上下文覆盖情况；缺失能力经统一 Catalog 扩展，并保留 stable cursor、`has_more / complete / next_cursor`。不由浏览器抓全企业标签再自行过滤。

临时面板编排可以在前端调用现有独立查询端点，每条请求冻结该面板自己的资源/来源范围，限制并发；不强制引入新的批量语义引擎或把所有返回类型压成统一 Envelope。服务端继续使用各语言原生结果与现有执行元信息。

## 8. 错误与无数据状态

- 尚未执行、正在执行、已取消、条件已变更、查询成功、当前范围无数据、语法错误、无权限、超时、预算失败分别显示。
- 无数据不补零；未观测不能显示健康。目录读取失败不等于没有指标。
- 区分引擎硬失败与支持的分页/截断：PromQL 预算失败遵循现有 ADR 报错；日志等已支持的 partial 必须显式说明截断范围，不能把失败包装成完整成功。
- 修改语句后显示结果过期；可选择保留带快照标识的旧图，或清空结果。原型选择清空，避免用户误读。
- 原型任意文本只提供编辑与提示，只有原型构造器生成的表达式与目录预置表达式能处理有界示例；未知表达式明确报“原型未执行”。不会对任意输入生成貌似查询成功的图。
