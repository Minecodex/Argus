# B09a 真实集群接入中的修正

2026-11-08，B09a 使用独立 Kind 集群和原生 Collector。正式门户沿用用户已经发布的 server 和 web 镜像。本次通过真实安装流程发现并修正了三个问题，更新范围为 direct-executor 使用的 worker 二进制。

## Kubernetes 直连目标

原执行器对 Kubernetes Collector 的完整 HTTPS 地址调用主机名解析，导致连通性测试成功后安装返回 `DIRECT_TARGET_DENIED`。协议分支现使用既有 HTTPS 解析器。客户端从冻结计划设置目标地址，保留证书、主机名和 IP 校验，并在新连接时重新核对 DNS。

回归覆盖正常 HTTPS、SSH 地址，以及 HTTP、嵌入凭据、回环和元数据地址拒绝。当前 B09a 的实际安装结果另见验收记录。

## 凭据租约并发事务

安装继续执行后，在租约事务中复现了 PostgreSQL `40001`。凭据服务在向消费者交付前，对序列化冲突和死锁执行最多八次事务尝试，使用已有错误分类和有界等待。失败尝试回滚租约与审计写入，清理已解密值，取消时结束等待。

实际 PostgreSQL 回归使用独立临时数据库。一个事务锁住 Secret，另一个事务进入发租约流程后释放冲突，验证最终一份租约和一条审计记录。测试库和专属容器随后清理。

## 候选校验中的 Agent 挂载

节点指标启用时，候选 Job 的 Agent 从 Gateway 模板复制，缺少实际 Agent 的 Kubelet CA 挂载，校验报证书路径不存在。候选现在复用实际 Agent 的卷挂载和运行身份，将所需卷加入校验 Pod。Gateway 校验继续使用临时身份状态卷。

回归检查实际 Kubelet CA 路径、只读挂载、验证命令及单写 PVC 隔离。原生二进制的最终验证由 B09a 正常配置流程执行。

## 独立集群网络

宿主机转发端口出现间歇性 TLS 超时。通过正常连通性测试和预览确认，将平台中的同一集群改为独立 Kind 节点的内部 API 地址，保留 Namespace UID。

原生遥测使用本地正式部署中的服务域名。B09a 通过带运行标签的专属 LoadBalancer Service 开放接收端 4317/4318，并在自己的 CoreDNS 中映射该域名。连接保留原生 mTLS。该 Service 列入本批资源清单，清理时核对 UID 后删除。

告警验证还发现 cert-manager 的续期时间已经过去，而 Secret 中证书已过期。重启证书控制器后完成续期，再重启告警 Worker 加载新证书。实际镜像、证书观测和回归证据见 [B09a 验收记录](./batches/B09a-review.md)。
