# B01 接入发现的默认仪表盘与查询问题

2026-10-26，使用本批两台真实 Linux 主机，经正式接入和原生 Collector 取数后发现。修正进入本地 `local-20261026-b01-defaults-v5`，全批次实际门户与告警验证继续单独记录，不由下述受控回归代替。

## 默认目录漏掉已配置的自身能力

原目录查询只登记四个早期自身指标 key，进程、systemd 等后续内置能力虽有实际采集和模板定义，却不会出现在默认仪表盘目录。

查询现在从 `builtincollection.All()` 取得当前内置能力 key，作为参数传给存储查询。原有企业、Host/Cluster 显式授权和活跃采集范围保留；能力目录成为唯一清单，不再平行维护固定四项列表。

真实 PostgreSQL 回归覆盖进程/systemd 默认项、未授权主机不产生目录入口、撤去主机授权后入口不可见。

## 模板分组标签与真实来源不一致

进程可执行文件名、systemd 单元名属于 OpenTelemetry Resource 属性，在现有查询契约中使用 `resource_process_executable_name`、`resource_systemd_unit_name`。旧表达式遗漏前缀，导致不同进程/服务聚合到一起。

统一模板源已更正，进程和 systemd 模板发布为不可变版本 2，生成的契约与前端模板数据同步更新。旧版本、已冻结查询和用户副本按原有生命周期保留。

## 已关联的受管默认项被资源列表隐藏

关联读取只检查普通 Dashboard 的显式授权集合，遗漏了系统受管默认定义已有的读取规则；关联成功后列表不可见，重复关联出现冲突。

资源关联列表现在复用 `RequireObject` 的统一读取判断。回归覆盖：受管定义可见、普通私有仪表盘仍不可见、撤去 Host 授权后关联入口拒绝读取。关联依旧是导航元数据，不授予监控数据或目标权限。

## 数值查询读取了不需要的宽字段

Gauge/Sum 查询原先同时读取直方图、Summary 和指数直方图列，以及未在扫描前充分过滤的载荷/排序字段。实际 B01 面板触发查询预算错误，不能把它解释成无数据。

查询现在从版本化序列元数据确定类型：全部为 Gauge/Sum 时仅读取数值所需五列；直方图、Summary、混合或未知类型保留完整读取路径。已选 UUID 与时间在读取大字段前过滤，原外部成员集合、来源条件和确定性顺序保留。现有预算没有扩大，图表表达式和监控数据没有删减。

受控 ClickHouse 回归将已选值 7 与同一 granule 中的宽直方图数据混合：原读取在 4 MiB 上限下失败，修正后约 178 KiB 返回相同值和资源身份。原有有界扫描、来源/Namespace 范围、重复来源、混合指标类型、PromQL 一致性和后缀族投影也通过。另用 B01 已实际采集的来源进行了只读取数探测。
