# 仪表盘与告警详情统一修正

本轮处理 B01 人工反馈中的所有仪表盘展示、查询预算、告警时间线和趋势布局问题。使用共享组件修正受管仪表盘、个人仪表盘、编辑预览、展开和明细入口。B01 的真实采集资源、用户、企业、策略与历史保留，人工验收仍待用户进行。

## 展示规则

- 标题旁的点击说明图标承载查询提示、采样口径、样本时间和完整性信息；不常驻来源技术副标题、说明横幅或“数据时间与完整性”按钮。实际失败与不完整状态仍可见。
- 单序列统计卡片仅居中显示数字和单位，多序列保留业务维度名称；去除图例中的 instrumentation/内部身份字段，完整标签仍保留在查询结果中。
- 图表使用可用宽高并显示数值坐标轴。告警共用图表的紧凑模式不再固定 420 像素或隐藏 Y 轴数字；告警表达式使用整个容器并在内部横向滚动。
- 告警概览与历史时间线复用同一结构化列表，展示事件名称、实际时间、执行人、触发值/阈值、等级和备注，默认不输出存储 JSON。

## 查询与停采

- 串行 Run 复用剩余总预算，按实际消耗扣账，失败消耗整份预留；总上限没有增加，不修改固定步长，不把失败伪装成空数据。
- 已选 UUID、时间和授权来源在读取负载列前过滤。Schema v5 为数值样本增加按来源/时间排序的投影，并为历史数据同步物化；来源授权、原始采样和冲突排序保持一致。
- 明确关闭所选范围所有资源的全部指标采集时，策略标记 `not_evaluated`，保留既有告警生命周期并重置持续窗口，禁止产生 NoData/恢复或重复通知。没有配置、意外断流及只停用部分资源继续正常评估，避免全局静默。

## B06d 复验中的显示修正（2026-10-29）

查询健康事件使用 `state.kind=health` 与触发时保留的 `labels.alert_health` 呈现原因。即使事件已恢复、当前 health 为 normal，标题仍能显示“告警查询暂无数据”等原始原因。列表与详情统一中英标题，恢复时间线显示“查询恢复”，不足一分钟的持续时间显示秒。

健康事件不再显示业务当前值/阈值、默认 `> 0` 或空趋势骨架，也不发出无意义的趋势查询。详情展示原因说明与关联策略快照中的查询；不据此推断具体失败规则或服务宕机。后端历史记录未重写。

共享 `@argus/ui` 图表对很小的非零值自动增加刻度、tooltip 的显示精度，极小值使用科学计数法，避免低负载 CPU 的所有刻度变成 0.00 cores。原始数据、查询、阈值和统计卡片小数位设置保持不变。查询健康说明复用现有组件、样式与双语注册。

实际 B06c 历史事件与 B06d Oracle 页面纳入六项真实门户 E2E（中英/明暗、1280/1920），共享图表有低值/零值/负值/百分比/非数值回归。最终部署与验收记录见 [B06d](./batches/B06d-review.md)。
