# B12 压缩后继续执行的受控对照

用户要求先在相同场景测试通用一致性机制的效果。本轮先验证原型，不修改正式 Agent Harness 或重放已完成的运维操作。

## 冻结场景与边界

使用 B12 原生查询的两份封存 manifest 和六个真实面板文件，经过正常鉴权 API 下载并核对字节/SHA。场景断点为 `query.get` 已完成、随后上下文压缩、模型继续读取文件和计算。使用同一条真实压缩快照和用户要求作为两组共同输入；候选组仅增加由程序登记、保留完整身份的引用索引。模型回复必须真实请求 APIMart，不回放旧回答。

这验证压缩断点恢复，不是对整个35次工具调用的完整端到端 A/B，也不是当前生产执行器已接入新机制。固定历史原始数据排除了实时指标随时间变化；此前18次失败中6次路径错误属于直接覆盖范围，另外12次发现/版本/证据/参数错误单独记录，不能按比例假定也已修复。

两组在同一临时 Namespace 的独立非特权 Pod 运行相同 Workspace 读/计算工具，无主机挂载、无 ServiceAccount 令牌、禁止网络、资源有界。正式 B12 会话、账号、数据、服务及原失败记录保留。

## 原型机制

`runtime/context-compare/context_references.py`：业务无关的显式引用登记、上下文边界、授权/Workspace 身份核对、内容 Hash 校验、整条引用预算、显式不完整状态及按 invocation 身份幂等的原型。它不从模型摘要或外部任意 JSON 猜测引用，不按 Host/Redis/面板名称做恢复分支。

本轮可信引用由测试适配器从原生已封存查询元数据提供，数值验收 oracle 独立从原件计算。原型尚未接入 Go 生产执行器，单位测试不代表生产撤权/幂等门禁已升级。

## 对照约束

- 同一供应商、模型和低思考档位，输出上限4096；每组共同任务、摘要、工具 Schema 和文件内容一致。
- 两组交替次序执行，保留全部结果，不只挑选改善样本。
- 最多24次新增模型请求、300,000实报输入输出 Token，按现有配置价最多0.10美元；未知用量或供应商异常停止，不扩大预算。
- 分别记录模型调用数、工具尝试/失败/重复、额外目录查找、输入输出/缓存 Token、耗时、费用、原件覆盖和最终数值正确性。
- 强制重复压缩、错误引用、篡改、跨 Workspace、权限版本变化、未知执行状态通过独立机制回归验证。模型实验结果与确定性回归分别报告。

### 路径错误的统计修正

最初只按 `read` 的 `WORKSPACE_FILE_NOT_FOUND` 统计，双方均为0。逐项复核实际 stderr 后发现，基线2有一次失败 Bash 调用，内部发生 **6次 FileNotFoundError**：模型将压缩摘要中的8位文件名前缀拼成了不存在的文件路径。候选组没有对应错误。

因此分别记录“路径错误工具调用数” **1→0** 与“文件打开失败次数” **6→0**。它部分复现了原故障模式，但不等同于原生产账本里的6个独立 read 失败。原始只统计原生 read 的汇总保留在 `initial-metrics-native-read-only.json`，最终结果以 `summary.json` 为准；增加了 Bash 多异常、read 错误和成功读取错误文本的统计回归。

同参数重复调用两组均为0；不能宣称降低了这一指标。减少的是本轮观察到的探索/纠错轮次。目录枚举统计包括用 glob 进行正常批量计算，不能一律称为无效探索。

## 预算、预试与证据

正式对照 **19次**实际供应商请求，均收到完整 provider 用量。此前预试3次：实验客户端按字符串切 SSE 时被 UTF-8 字节/Unicode 换行处理影响，第三次响应 JSON 解码失败；已停止该预试并清理环境，没有派发其未完成响应的工具。修正为字节级 SSE 分帧、UTF-8 解码后，才重新冻结正式对照；预试不计入两组性能指标。

总新增请求 **22次**，其中21次有可核算 provider 用量，合计 **190,435 Token**；1次预试用量未知，保留 unknown，不补零、不改成 provider。修正客户端后启动的是新的独立对照，不自动重放失败调用；未知预试按原请求大小及4096输出上限保守预留到总预算。计入预留后的 Token 上界 **213,146**；按既有配置价的可核算费用 **0.01629565美元**，加未知请求预留后的保守金额 **0.018715775美元**，均在本轮约束内。供应商实际账单未独立核实。

两组初始输入经过程序核对，除了候选增加引用索引外完全相同；模型、档位、工具 Schema、共同提示、历史摘要和文件字节相同。工具结果和模型回复都来自实际执行，没有用旧回复替换模型输出。缓存 Token 分别由 provider 返回并独立记录，服务端缓存、随机性及运行时延迟仍可能影响小样本结果。

机制/客户端/统计测试最终 **15/15**：包括模拟连续10次丢路径摘要下的引用保留、上下文边界、权限/Workspace 身份变化、同 ID 内容冲突、Hash 篡改、整条引用数量/字节预算、invocation 重试身份、未知执行状态、SSE 分帧和统计口径。这些是原型测试，不能当作生产撤权、幂等或完整 Compactor 已升级的证据。实验后补强了预算边界和防止误重跑的保护，重新计算的8项引用索引与实际送模索引完全相同，没有重跑模型挑选更好结果。

可复核文件：

- `source-code-freeze.json`：实际对照代码冻结指纹。
- `comparison.json` 与各运行 JSON：全部有效样本，不筛选失败轮次。
- `provider-usage.json`、`pretrial-usage.json`：完整收到的用量、失败与未知记录。
- `summary.json`：最终汇总、程序实际计算回执和范围限制。

- `cleanup.json`、`preservation.json`：临时环境清理和正式环境保留核对。

## 当前结论与后续范围

本次数据支持继续把通用引用机制接入正式 Harness 做端到端验证：小样本内纠错轮次、输入量及耗时减少，并复现了一组基线缩写路径失败。但生产接入、完整压缩器的新快照提交、真实权限撤销与重试链路、发现/条件版本/证据错误的修复，以及工具失败 UI **均不在本轮已交付范围**。

临时 Namespace 已按归属标签和 UID 删除，没有创建持久卷。正式 **13个 Deployment UID/容器配置、6个绑定 PVC** 保留；B12 **291条账本事件完全一致**，平台记录的原模型调用仍为50次。本次直接供应商实验用量独立记账，未伪造平台 ModelCall/费用记录，没有修改正式执行器或启动 B13。
