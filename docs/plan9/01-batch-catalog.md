# 分批场景、仪表盘与故障目录

所有条目都是待执行方案。默认仪表盘优先使用当前版本的受管模板；组合总览确有需要时通过正常创建/发布流程制作用户副本。下面列出的是应检查的内容，不保证上游不存在的指标能被采集。每批部署时把内容映射为实际模板 ID、查询、来源、单位和权限；缺能力明确记录。

每个子批次先保留一个健康对照目标，再对一个测试目标施加有界变化。健康/异常/恢复都记录绝对时间和实际数据。告警阈值以本批实测基线、指标含义及受限负载确定，创建后冻结；禁止为获得通过临时篡改样本或反复降低阈值。

## B01：Linux 主机与 Collector

- 环境：两台独立身份的 systemd Linux 测试主机 A/B；A 运行有界 CPU/内存/文件读写/网络负载，B 保持轻载。Docker 容器明确标记容器可见范围；需要独立内核指标时切换 VM。
- 接入：正式注册 Host/Connector，安装 Collector，配置主机基础、进程、Linux 服务和 Collector 自身采集，创建专属后台评估身份与资源授权。
- 仪表盘：主机概览、CPU/内存/文件系统/磁盘 I/O/网络、进程、systemd、Collector 收发/失败/队列等实际可得字段；A/B 筛选和单主机入口。
- 实际变化：低负载→受限负载→恢复；专用 systemd 服务 active→failed→恢复；独立停采/恢复；全关指标时 Connector/Collector 控制状态仍可查看。
- 告警：优先对本批专用进程或服务状态触发；基础资源阈值按实际观测口径设置。区分故障、NoData、主动停采和恢复。
- 用户查看：主机资产、安装/采集状态、图表曲线、单位、实时刷新、告警详情/历史和资源跳转。详见 [B01](./batches/B01-linux-host.md)。

## B02：Web/代理与网络探测

| 子批 | 实际环境和操作 | 仪表盘/页面 | 告警与恢复 |
| --- | --- | --- | --- |
| B02a | Nginx、Apache、HAProxy 和小型 HTTP 后端；实际请求、长连接、后端停启 | 三类默认视图、请求/连接、实际可得后端状态、采集实例 | 连接压力或实际后端状态；恢复后端后重新评估 |
| B02b | 独立 HTTP/TCP 服务、测试 TLS 证书、本批 DNS 服务与 ICMP 目标；真实探测 | HTTP、TCP、TLS、DNS、ICMP 各默认视图和执行位置 | HTTP 失败/端口拒绝/DNS NXDOMAIN/不可达；短有效期证书与正常证书分别测试，禁止修改系统时钟 |

Nginx 基础状态计数不提供的错误率、时延分位数不能补造；需要这些内容时从另行配置的真实日志/APM 获取并标明来源。ICMP 权限、证书信任和 DNS 解析从实际 Collector 所在网络验证，不能用开发机能访问替代。

## B03：MySQL 与 PostgreSQL

- 环境：独立 MySQL、PostgreSQL、Collector 主机和负载客户端；使用与正式 Argus 数据库无关的测试卷和测试业务库。
- 实际操作：通过数据库协议建立连接、建测试表、有限行数的插入/更新/查询、持有短事务和可释放锁；这是被监控业务活动，不是向 Argus 写监控数据。
- 仪表盘：两类数据库概览、实际可得的连接/事务/吞吐/缓存/锁/空间；同一 Collector 的两实例独立身份、启停和配置版本；数据库/主机指标不串源。
- 告警：连接数或可得锁/事务指标超过冻结阈值，结束客户端后恢复；另测一次错误采集凭据及修正。
- 用户查看：接入配置、凭据引用、采集诊断、数据库详情、默认图、双目标切换、失败后恢复。错误凭据只作用本批监控账号，不改业务/正式账号。

## B04：Redis 与 Memcached

- 环境：单实例 Redis、Memcached、专用 Collector 和客户端。
- 实际操作：SET/GET、TTL 到期、正常命中/真实未命中、在小容量测试实例中触发淘汰；数据量和总内存有上限。
- 仪表盘：缓存总览、内存、命中/未命中、连接、命令和实际可得淘汰；无请求时分母为零的展示。
- 告警：内存/淘汰等实际支持指标；释放或等待测试键到期后恢复。单实例停采时另一实例继续有样本。
- 用户查看：比例/速率/累计单位、空数据与零、多个实例区分、告警与目标跳转。不把分别采集节点称为 Redis Cluster/Sentinel 自动拓扑支持。

## B05：消息队列与协调服务

| 子批 | 实际操作 | 仪表盘/页面 | 告警与恢复 |
| --- | --- | --- | --- |
| B05a RabbitMQ | 真实生产/消费、暂缓消费、恢复确认；限定队列和消息上限 | 队列/vhost/节点、投递/消费/积压等可得字段 | 队列积压持续超阈值，恢复消费者后排空 |
| B05b Kafka | 实际 Topic、生产者、固定消费组；暂停消费后恢复 | Broker/Topic/消费组、消息与实际可得 lag | 固定消费组积压与恢复；记录 offset、生产/消费计数 |
| B05c ZooKeeper | 建立会话、读写临时测试节点、断开客户端 | 节点/连接/请求和原生可得状态 | 按实测连接/请求指标配置阈值；释放客户端后恢复 |

Kafka 的 lag 必须确有消费组提交位点；不从生产速率猜测积压，不通过外部 JMX/exporter 补齐本轮不支持的指标。单节点场景不声称验证集群选主/容灾。队列达到上限就停止生产，不能无限积压等待用户。

## B07：应用、APM 与 SDK 日志

- 环境：真实请求驱动的两个小服务（入口服务→业务服务），业务服务实际访问本批 PostgreSQL 或 Redis；负载生成器发出有界请求。应用环境唯一，服务由正式登记/发现流程产生。
- B07a 使用真实 SDK 经 OTLP HTTP 上报；B07b 独立验证 OTLP gRPC；B07c 使用实际 Jaeger 客户端/埋点产生调用，按当前支持的具体传输与认证组合验证。SkyWalking 保持暂缓。
- 仪表盘：应用/服务/实例/接口、请求/错误/时延分布、依赖、Trace、关联日志与依赖资源。适用指标必须由实际请求和观测数据得出。
- 实际变化：正常请求、服务端真实延迟、受控错误返回、数据库依赖等待、恢复；保留 request ID/trace ID 与服务日志对照。不得直接生成目标 OTLP 数值或预写 Span JSON 代替业务埋点。
- 告警：在当前支持的指标查询上配置延迟/错误阈值；如果某协议没有相应可查询指标，单列缺项并使用本批主机/HTTP 探测指标验证已有告警，不宣称完成该协议的 APM 告警。
- 用户查看：服务身份、环境筛选、跨服务链路、日志→Trace、依赖数据库跳转、共享资源整体口径、无样本与不适用提示。

## B08：Linux 文件日志与 Journald

- 环境：真实 Linux 主机和专用小服务；由进程实际写结构化日志、多行异常和 systemd journal，每条带本批 ID/递增序号/当前时间。
- 实际变化：正常/错误请求、文件 rename/create 与 copytruncate 两种轮转分开测试、Collector 重启、单规则停采/恢复；只处理专用日志目录。
- 页面：日志规则及版本/生效状态、日志探索器、字段/多行/时间、搜索、下载与来源跳转；配置应用归属和基础设施归属两条独立规则。
- 告警：复用本批服务/进程/探测指标故障；没有日志告警实现时不把一条 ERROR 日志直接算作告警事件。
- 用户查看：记录真实性、脱敏、重复/缺失/截断说明、轮转前后连续性、停采不补零。日志连续性按实际写入序号与查询覆盖核对，不能仅比较界面记录总数。

## B09：Kubernetes 监控与日志

- 环境：独立测试集群、专用 Namespace 和 Deployment/StatefulSet/DaemonSet/Job、Service、有限测试卷；正式 Argus 所在集群继续运行。集群自身不能只靠一份普通 Compose 冒充，创建脚本与清单一并交付。
- B09a：正式接入集群/Namespace，部署原生 Collector；实际 HTTP/CPU/文件读写与容器 stdout/stderr；Pod 重启与 workload 副本变化。
- B09b：逐一核验 API Server、Scheduler、Controller Manager、CoreDNS、etcd、Collector 自身；再按条件验证 Host/Node 身份绑定与 Claim、日志责任去重。只在本批独立集群处理权限和端点。
- 仪表盘：集群、节点/容器、Namespace/workload、组件与 Collector；实时 Pod 日志与持久日志两个入口分别验证。
- 告警：本批 workload 副本不足或实际可得资源指标；恢复副本/负载后恢复。Collector/控制面不可访问显示真实诊断，不能以抓取失败诊断充当目标样本。
- 用户查看：UID/Owner、Pod→日志、容器重启前后、Namespace 筛选、控制面不适用/不可达说明、无重复求和。
- 某组件既有端点缺失或不可达时，该项标 blocked/unavailable；若要正向验收则准备具备端点的本批集群，不自动修改正式控制面。

## B10：Kubernetes 工作台实际操作

每个子批重建自己的独立测试集群与依赖，通过 Argus 实际提交操作，随后直接核对 Kubernetes 对象和状态；客户端返回成功不等于工作负载就绪。

| 子批 | 真实操作及对象 | 重点界面 |
| --- | --- | --- |
| B10a | Namespace、Deployment/StatefulSet/DaemonSet、Service/Ingress、ConfigMap/Secret 的适用创建/更新/删除；扩缩容、重启、回滚、Pod 删除、日志/exec/端口转发 | 选择器、YAML 脱敏、差异预览、确认、任务状态、失败/冲突、对象详情和审计 |
| B10b | PVC 创建/支持时扩容/删除；PV/StorageClass 只读；Job/CronJob 暂停恢复/手动触发；HPA、NetworkPolicy | 存储依赖和数据影响、任务历史/日志、真实指标驱动的伸缩、实际网络探测 |
| B10c | Helm 仓库与 OCI 安装/升级/回滚/卸载；专用 CRD/CR；限定 RBAC；专用 worker 节点 cordon/drain/uncordon、标签/污点 | Chart/values/资源差异、权限拒绝、hooks、PDB 阻塞与恢复、集群级操作边界 |

只对本批资源操作，不 drain 正式 Argus 节点。NetworkPolicy 对象存在不代表网络阻断生效；实际通信验证失败就记录环境能力缺口。告警采用本批实际 workload 指标，并验证操作/恢复与告警时间对应。

## B11：堡垒机与远程连接

- B11a：测试 Linux 主机的真实 SSH/命令安装、身份注册和远程终端；执行 hostname、id、只读进程查看等，保留返回与审计。
- B11b：堡垒机＋内网成员，网络实际阻止成员直达 Argus；通过堡垒机接入、TLS Relay/数据路径、成员监控和人工终端。仅设置一个“内网”标签不算网络隔离。
- B11c：按现有支持路径验证 Executor Tunnel/堡垒机隧道、重连、凭据轮换、过期预览拒绝、断连恢复；精确记录实际使用的控制和遥测路由。
- 仪表盘/页面：堡垒机/成员列表、安装任务、主机/Collector 监控、Terminal Dock 的底/左/右停靠和缩放、会话状态、录像/回放、审计和适用文件能力。
- 告警：本批专用服务/探测指标触发，比较连接故障与数据失联诊断；不能用“堡垒机在线”证明成员监控在线。
- 人工会话、AI 远程工具、安装身份分别验收。未支持或未授予的文件/剪贴板能力必须明确拒绝，不能为演示开放更多权限。

## B12：真实模型聊天与操作闭环

- 环境：本批真实 Host＋中间件/应用＋已取数仪表盘＋已触发告警；有效真实模型配置、正常 Workspace。重新创建基础场景，不依赖 B01～B11 的旧数据。
- 部署前列明模型配置 ID/Provider/模型、最大轮次、调用/token/费用预算、超时与停止条件；优先使用企业现有已授权可用模型。未提供预算/凭据且无法从现有配置确定时再询问，不能用 replay/mock 模型代替。
- 对话顺序：①查询主机和真实指标；②读仪表盘并分析 Workspace 数据文件；③解释本批实际告警和证据；④提出有明确对象/命令的变更计划；⑤经过正常宿主确认真实执行；⑥重新取数确认恢复；⑦查看历史会话和产物。
- 页面：流式响应、工具分类发现、结果卡片/原始内容/查询参数、长内容展开、计划与确认、普通执行记录、文件树/报告/下载、错误与重试、模型用量。
- 负向：撤销/拒绝待确认操作不得执行；真实权限不足或模型错误显示实际失败。必要错误注入明确标注，不能把模拟 Provider 错误冒充真实 Provider 事故。
- 不要求模型照抄预定话术；核对结论是否与工具文件及时间/范围一致。最多有限次修复重跑，保留失败 Run；预算耗尽后停止真实调用并记录未完成项。

## B13：仪表盘、告警与权限组合验收

- 环境：两台本批主机、两个轻型监控目标、两个应用（不同环境，其中一项共享依赖）、专属测试成员和后台评估主体。
- B13a 范围：默认仪表盘、个人副本/编辑/发布、资源关联、全局筛选/局部条件、空范围、无权范围、时间范围/刷新、共享目标不重复计数、目标归档后的历史。
- B13b 告警：多指标规则、持续窗口、触发/确认/处理/恢复/历史、分组去重、静默/抑制、NoData/Error/停采区别；后台评估主体权限和通知路由分别配置。
- B13c 生命周期：实际撤权、已开页面/查询/下载/会话失效、资源与采集独立启停、凭据轮换、模板与个人副本独立、按产品生命周期删除/归档。
- 通知默认使用本批自建接收端/本地邮件收件器，只验证真实投递请求、载荷、失败重试和投递记录；这不等于钉钉/飞书/企业微信公网端到端成功。外部收件人、机器人群或邮箱须由用户明确指定并授权测试发送后单独验证。
- 如通知 URL 策略不允许本地接收端，不改全局安全策略或借私网绕过；记录前件，使用已授权的合规目标。无可用渠道时仍可完成告警实例/历史，通知项保持未完成。

## 覆盖与状态

[progress.json](./progress.json)逐项映射 Plan8 的 39 个集成候选和 12 项内置能力到本计划；包含暂缓项，避免只列成功的条目。历史支持证据只用于选型，所有 Plan9 项目初始状态均为未执行。子批可独立通过，主批只有全部适用子批经用户确认后才能通过；skipped/blocked 不按 passed 统计。
