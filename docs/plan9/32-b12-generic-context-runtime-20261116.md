## 正式实现与架构边界

`toolruntime.ContextFactProvider` 为可选的只读接口，CompositeFactory 校验当前主体并拒绝重复命名空间。每轮推理、入场预算和压缩恢复均经过现有工具工厂；没有新增业务调度器、模型调用代理或第二套权限系统。

- Workspace 在同一会话、企业、Workspace 和事件边界内读取至多65条登记，向模型提供至多64项/24KiB的完整身份索引。路径、UUID、Hash不截短；超预算按整项省略并明确不完整。源结果撤权或工作区失效时不给旧引用重绑定。
- `read` 完整读取返回实际 SHA256；`write/edit/publish_file` 在现有发布事务中登记实际保存文件。同路径变更产生新身份；旧交付和封存原件保持不变。已保存但登记未知时不指示模型重放写入。
- 同一 Run、授权 Scope、原生来源内恢复已完成发现/Describe，最多4个完整成对契约。恢复不产生新的调用事件，也不重放业务操作；新 Run 仍重新发现。Schema 属性名不会因包含 `api_key` 而被错误删去。
- 原生提供者可通过 `Result.ContextFacts` 声明只读任务/对象元数据。当前应用覆盖仪表盘版本、解析条件、查询任务状态及交付文件；核心按 `kind/id` 恢复最近状态，不识别 Host/Redis 名称。至多8项/16KiB，单项12KiB。最新项超预算时不回退更旧状态，明确标记不完整；客户 MCP 不能写入此事实通道。
- 查询的完整 manifest/定义仍留在不可变原件和文件中；模型投影提供紧凑状态、条件和准确文件引用，避免每次进度读取塞入整份重复定义。
- 条件版本冲突提供当前/期望版本及重读入口；证据校验提供具体字段、重复/无关路径及原文引用原因。不自动填版本0、不删除用户条件、不自动重放。UI 保留具体业务工具名和可公开错误，支持历史卡片及中英明暗。

模型仍决定何时取数、读文件、计算、纠错、发布或结束。登记不代表已读，任务完成不代表已经得出正确结论；程序不替模型生成业务报告。
