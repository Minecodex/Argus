# B11b 终端录像播放器布局与主题修复

日期：2026-11-14。保留当前 B11b，修复主机详情与远程会话中心共用的录像播放器。

## 现场原因

正常登录 `https://argus.dev` 打开 B11b 的真实终端录像复现：1120px 弹框内的单列 Grid 使用自动最小尺寸，被录像中的固定终端列宽撑到约 1945px；弹框正文 `scrollWidth=1961`、`clientWidth=1118`。录像画面 490px 高，原播放视口只有 420px，额外出现滚动。控制条随画面越界，时间和倍速移到弹框外。

播放器底色为深色终端，但重置、倍速和时间继承门户浅色主题的文字色，导致对比度不足。进度组件采用水平语义、纵向 Flex 排列，缺少主轴居中，进度条和按钮的中心线也不一致。

## 实现

- 在 `@argus/ui` 的 `TerminalPlayer` 保留录像的原始行列、ANSI 输出及换行。首版采用当前画面居中缩放，后续反馈确认这种方式仍会随 resize 改变位置和文字大小，现行行为见下节。回放历史由时间轴承载，终端回放不保留额外 scrollback。
- 正文使用可收缩的单列与 Flex 链。播放区域随弹框剩余高度缩小，控制栏固定可见，消除画面和控制栏制造的外部横向与纵向滚动；原始事件仍可正常滚动查看。
- 控制栏使用门户主题色，播放、重置、时间和倍速在同一中心线上。重置使用共享次级按钮；倍速使用分段选中状态。
- 共享 `RangeSlider` 使用细轨道、圆形滑块和主轴居中，终端与 RDP 录像共用相同的进度控件。
- 元数据集中为三列摘要。所有颜色、间距和圆角沿用 design token。播放器快捷键仅响应播放器本身，避免按钮 Space 和滑块方向键被父级再次处理。
- 资源读取、录像内容、访问权限、审计、存储和后端接口均沿用现有流程。

## 第二轮：固定位置与字号

用户再次反馈画面时而居中、时而靠右，文字大小不一致。首版几何测试只验证画面在视口内，未覆盖跨 resize 的固定原点和视觉字号，不能据此宣称播放体验完整正确。

现行显示契约：

- 默认 `100%`，所有录像使用统一的 13px 字号及左上角原点。播放、暂停、重播、seek、录制尺寸变化和窗口变化不自动改变字号，也不重新居中。
- 对超出视口的原始画面，可在画面内滚动或用键盘查看；内部隐藏滚动条，弹框与控制栏不随内容撑大。重播回到左上角，普通 seek 保留用户主动浏览的位置。
- 用户主动选择“适应窗口”才缩小画面。缩放比例根据整段录像的最大合法行列数计算，时间轴上的 resize 不改变比例；切换模式回到左上角。
- 原始终端仍按各时刻的录制行列解析输出，不使用显示宽度重新解释 ANSI、换行或光标控制。

同时修复事件顺序：xterm 输出是异步解析的，原先同步 reset/resize 与未完成的 write 可能交错。共享 `TerminalReplay` 按 write 完成回调串行处理输出和 resize；快速连续 seek 只保留最新目标，先等待单个在途写入，再重置和重放，防止旧内容污染目标画面。完成提示等待最后一段输出实际解析完成。
