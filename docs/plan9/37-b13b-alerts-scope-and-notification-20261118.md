## 通用修复

### 凭据级通知 CA

私网 HTTPS/SMTP 可能使用企业 CA，原通知只依赖系统根。为通知凭据 JSON 增加可选 `ca_pem`，仅供当前已授权通知租约的 TLS 连接：最多 64 KiB/16 个有效 CA，拒绝私钥、非 CA 和尾部垃圾。克隆原配置/根池，保留系统根、主机名/SNI、最低 TLS 与每次拨号的 EndpointPolicy；不修改全局信任、URL 安全策略、生产镜像根目录或任务权限。

回归确认一个凭据的 CA 不会泄漏到下一凭据/共享客户端，非 CA/私钥/过大材料失败且不泄露原文。真实本地 TLS SMTP 经正式 Secret/凭据/渠道及通知任务成功接收。本地测试不冒充钉钉/企微/飞书公网或真实邮箱联通。契约见 [Plan6](../plan6/02-architecture-and-contracts.md)。

### 静态标签进入实际路由

原 `PolicySpec.labels` 被保存和校验，却未进入观测、路由/分组/降噪。现在把元数据传入规则解码，真实指标维度优先，内部 `argus_*`、资源/策略身份、等级、metric/health 等保留标签不可伪造。健康事件也保留合法策略标签。OpenAPI 描述和生成客户端同步。真实通知只匹配 `plan9_run` 与允许的 phase，诊断探针不会落到其他全局渠道。

### 持久事实与展示投影分离

本轮静默复测暴露长期 Pending：评估事务写入失败，最初 SQL 报 `state NOT NULL`。检查显示两个相互放大的问题：

1. 降噪把 `instanceDTO` 的授权裁剪快照当完整状态写回，改变了私有策略/来源快照。
2. 评估先把 `PolicySnapshot` 指向共享 `policy.Spec` 再反序列化旧状态；`json.RawMessage.UnmarshalJSON` 复用缓冲区，较短的遗留投影覆盖共享策略前缀而留下尾部，形成无效 JSON。编码错误此前又被忽略，导致 NULL 写入失败。

修复从空状态反序列化，保存策略快照时复制字节。通知只更新 notification_state/noise_reasons/last_notification_at，其余存储事实及 Pending/恢复计时保持原样；公开投影仅用于读出。编码失败显式中止，不继续写 NULL。没有降低授权裁剪要求，也没有批量重写历史。

回归包括私有快照/计时不可被展示层覆盖，以及真实临时 PostgreSQL 中的遗留投影待触发状态：后续槽可推进到 Firing，输入策略字节保持不变。修复在相同实际主机、相同策略上重新通过静默、抑制和恢复，不是换空库或改阈值绕过。
