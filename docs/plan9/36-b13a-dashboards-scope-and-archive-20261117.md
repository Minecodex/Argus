## 本轮修复

### 受管缓存模板不能发布个人副本

Redis/Memcached v2 的命中率面板把完整 PromQL 用作标题，超过 240 字节。模板注册原来只解码、编译查询，普通草稿发布还验证标题，因此默认页能读，创建个人副本却在发布预览时返回 `DASHBOARD_INVALID`。

- 缓存模板升级 v3，命中率使用短标题，查询和指标语义保持原样。
- 公共模板注册复用正常仪表盘验证，阻止再次登记不可发布的模板。内部模型模板沿用既有专用验证，仍不能混入普通草稿。
- 新增所有公共模板可发布、超长标题拒绝的回归；同步模板 JSON 和生成客户端。
- 实际重新复制 v3、修改标题并预览/确认发布，检查副本拥有独立身份、原模板修订不变。此前失败的本轮临时草稿先留证，再通过正式草稿丢弃 API 清理。
- 组合大盘自己的命令速率单位输入也已通过新草稿修正为 `ops/s`，保留其余查询、来源和范围字段。

### 监控目标缺少独立归档动作

原有稳定目标已有 `active/archived` 状态、版本化更新、依赖计数和历史范围读取，但正式 mutation 未开放目标归档。不能把“采集已归档”冒充“目标已归档”。

- 正式 `/monitoring/commands/preview` 新增 `kind: target, operation: archive`，要求目标 UUID、当前 `expected_version`、`monitoring.manage` 与该目标的数据授权。
- 仅接受归档，不接受应用/采集/凭据等其他配置载荷。依赖现有预览、确认、执行、审计和版本冲突机制；不自动重放写入。
- 活跃采集、应用绑定或仪表盘绑定均阻止归档。操作者逐项解除依赖后重新预览，不级联移除业务依赖。
- 提交时在同一事务重新检查版本和依赖；绑定/采集引用目标时使用同一目标行锁，避免预览后新增依赖穿过归档检查。
- 只将目标状态置为 archived 并递增版本，稳定身份、来源登记和原始数据不删除。当前清单排除目标，授权历史查询继续使用原身份。
- OpenAPI 及 Go/TypeScript 客户端已生成。真实临时 PostgreSQL 覆盖完整预览/确认/提交、依赖拒绝、越权、旧版本、提交前新依赖及历史身份保留。
- 正式 API 中实际归档本轮 Memcached，归档前后同一绝对时间的 9 个面板原始数据完全相同。独立目标归档的门户入口与完整生命周期交互仍属于 B13c，不以本次 API 验证替代。
