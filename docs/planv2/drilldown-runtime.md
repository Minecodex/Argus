# 已发布下钻与完整链路执行契约

本页记录正式下钻的实现。生成、发布、HTTP API、正式页面及 Chat 查询工具共用同一已发布定义；真实来源/授权链路、日志前后文、文件交付和权限变化的非模型验收已完成，见 [2026-09-28 验收结论](./completion-review-20260928.md)。模型是否正确选择下钻和分析结果仍按用户要求暂缓验收。

## 生成和编辑

`POST /dashboard-drafts/{id}/drilldowns/generate` 按统计图的来源、图型和 QueryTarget 生成标准定义，检查个人草稿版本后保存。该操作不发布、不弹发布确认；最终仍与其他修改一起进入 PendingAction 预览、确认和发布。再次生成不会覆盖已生成或已编辑的同名定义。

每条下钻包含 `origin_query_ref`、`detail_query_ref`、输入字段映射、范围策略及可选时间裁剪。展示与详情分别是 QueryTarget，每条只保存一种 Builder / DSL 来源，并统一遵循 Panel 的编辑模式。详情自己的信号和来源明确保存，不增加导出配置。整图转换与正式编辑规则见[查询编辑契约](./query-authoring.md)。

当前标准定义包括：

- Metrics/Logs/Trace/APM 的同查询展开，保留原查询的聚合、步长、字段及显式限制。
- APM 服务、实例、接口和拓扑节点到 Trace 列表；RED 点位额外裁剪到该时间桶，并与原时间窗口求交。默认列表明确配置 100 条结果限制。
- Trace 详情、显式完整链路、Span 关联日志；日志到关联 Trace 列表及日志前后文。
- 构建器和可安全派生的单根 GraphQL DSL 都保留原业务条件。原生查询结构不满足派生条件或缺少 Trace 身份字段时返回明确原因，不丢掉约束后假装完成生成。
- 同一来源类型支持目标信号时可明确复制该绑定；否则必须在 `signal_sources` 选择跨信号来源，不能从同名服务猜测。

映射使用 JSON Pointer，从同一条实际结果记录取值；不能把不同记录的 Trace ID、来源和资源拼成一次选择。配置校验覆盖字段映射、参数类型、详情信号/来源、时间裁剪和完整链路定义。没有选定记录时，预览把详情标记为“配置有效、样本需要选择记录”，不宣称详情数据已经验证正常。

## 执行上下文

普通执行返回签名上下文，冻结已发布 Revision、绝对时间、有效变量/局部条件、授权资源和来源集合。上下文绑定企业和主体，有效期 15 分钟，最多连续下钻 16 层，不包含结果数据。新执行仍读取最新发布版本；原上下文不会因后来发布而混入新定义。

`POST /dashboards/{id}/drilldown` 只接受上下文、已发布下钻引用和声明的选择值，不能提交替代查询。需要选择记录的下钻会重新执行原查询核对选择，保留原有聚合、limit 和条件；数据变化导致无法匹配时要求刷新。输入核对、锚点验证、元数据与详情执行共用累计预算。

上下文是完整性凭据，不是授权凭据。每次读取都重新验证 Dashboard、资源权限与生命周期；撤权后不能靠旧上下文继续读取。过期上下文和已变化的选择使用独立错误码，便于页面提示刷新。

持久文件查询现已复用相同的下钻准备器。它从封存的父文件验证选择，继承父版本并保存依赖与深度；同一 Run 内可以继续，跨 Run 必须先重新取得最新发布版。文件上下文不依赖浏览器 Token；完整协议和验收边界见[查询任务与结果文件](./query-files.md)。

## 范围与完整链路

普通详情继承签名范围，不加入新资源或新采集来源。完整链路必须使用 `authorized_trace` 策略、单一 `queryTraceGraph` 定义，并显式传入 `expand_authorized_resources=true`。

服务端先验证选中的 Trace 确实存在于原资源/来源中，然后重新解析当前用户另有授权的资源及同一来源类型，将扩展集合冻结到本次详情。扩展只影响详情上下文，不修改 Dashboard 顶部选择；时间约束继续保留。相关日志等后续下钻继承详情上下文，并持续重验权限。

Trace Graph 先去重，再从选定来源片段遍历明确的父子关系。跨来源匹配必须属于同一已知来源类型且唯一；缺失、歧义、循环及未连接片段分别标记。`observed_connected` 只表示当前范围内已接收的片段连通，不代表全量遥测完整或系统正常。未授权片段不参与匹配，也不返回其明细。

## 日志前后文

受控 KQL 新增末尾阶段 `context "event-id" before N after N`，每侧最多 200 条；不能接在聚合、sort、limit 或 unwrap 后面。返回按 timestamp / event_id 稳定排序，锚点不存在时返回空结果。

前后文始终保留授权资源、冻结来源、原时间窗口及该详情定义的条件，并匹配锚点的资源、来源安装身份、服务、scope、规范化 stream labels，以及实例、Pod、容器、环境和日志文件身份。它不会跨到另一个文件或未授权资源。标准上下文是单独发布的查询，允许查看相邻日志级别；需要继承的自定义条件应在该目标中明确引用。

同一多信号来源（例如 OTLP）的 Span→Logs 和 Logs→Trace 标准查询同时保留行上的来源身份，避免重装后同资源、同 Trace/Span ID 混入另一安装代次。作者明确配置的跨来源路线保留目标绑定，不等同不同来源的 ID。生成器更新只作用于重新生成并预览发布的配置，不改写历史 Revision。
