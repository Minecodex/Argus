## 推荐结论

使用独立的统计图编辑页：**同屏预览与查询，右栏按“图型 / 样式 / 交互”组织；从常见场景开始，复杂设置按需展开。**

常见指标的第一屏只需要理解四项：数据来源、指标、跨资源计算、拆分曲线。名称在顶部直接编辑。单位、数据类型、默认步长和合理显示值由目录与结果形状提供默认值；对应高级能力保留。

数据查询修改后明确显示“待运行”，保留上次结果；点击运行或 Ctrl/⌘ + Enter 后更新。样式修改即时作用于已有结果，不消耗一次新查询。编辑图只加入个人草稿，最终统一预览并确认发布。

## 重构前界面的具体负担

分析依据是当前正式源码的结构，没有把旧 Demo 当成生产页面，也没有声称完成了用户可用性研究。

| 观察 | 实际代码 | 使用上的影响 |
| --- | --- | --- |
| 图的编辑集中在长抽屉中，基础信息、查询、局部过滤、显示和下钻在同一容器 | `panel-editor.tsx` 的 FormDrawer，依次包含 QueryTargetEditor、LocalFiltersEditor、DrilldownsEditor、DisplayEditor | 用户需要不断纵向寻找相关设置 |
| 图编辑器没有接收执行结果或同屏预览 | PanelEditor 的输入为 initial/spec/isNew/onSave；样本执行在 dashboard-editor-page.tsx 的 sample 流程 | 配置与检查结果之间需要切换，发现错误较晚 |
| 指标类型、range/instant、步长策略和目标点数在查询编辑区域出现 | query-target-editor.tsx | 系统可提供默认值的技术概念仍占据常见操作路径 |
| 来源选项主要使用内部类型名，分组使用逗号输入字符串 | panel-editor.tsx、query-target-editor.tsx | 需要知道 receiver 和字段名称，发现性较弱 |
| 变量编辑同时涉及 ID、显示名称、信号、来源、字段与参数映射 | variables-editor.tsx、parameter-bindings-editor.tsx | 创建一个简单环境过滤项也要理解查询契约 |
| 已有部分折叠，但显示设置默认展开，下钻可继续进入查询编辑 | display-editor.tsx、drilldowns-editor.tsx | 折叠没有完全解决跨任务配置混在一起的问题 |

核心问题是信息出现的顺序和配置层级。能力本身应保留，日常路径应让用户先选数据、看到结果，再调整外观。

## 同类产品对照

以下流程来自公开官方文档；表中的取舍是针对 Argus 的判断，没有把各产品的所有版本视为界面完全相同。

| 产品 | 官方编辑流程中的有效做法 | 适合 Argus 的借鉴 |
| --- | --- | --- |
| Grafana | 编辑器把可视化预览、数据查询、显示选项分成区域；按查询结果形状推荐可视化 | 保留可见预览，让查询与显示设置有固定位置；提供兼容图型推荐 |
| Datadog | 图形编辑流程依次选择图型、指标、过滤、时间/空间聚合、函数和名称；指标选择能显示单位、类型等信息 | 把查询拆成语义清楚的控件，用目录帮助选指标；高级能力延后出现 |
| Kibana Lens | 从字段出发，通过点选或拖放选择维度、聚合并生成建议图型 | 帮助用户从数据开始，减少空白配置；不将其 Elasticsearch 数据模型或语言直接搬入 Argus |
| SigNoz | 从面板类型进入编辑器，查询与右侧面板/显示配置分别管理；提供常见仪表盘模板入口 | 以常见场景起步，并按图型显示适用的配置 |

官方来源：

- [Grafana Panel editor](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/panel-editor-overview/)。
- [Grafana Query and transform data](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/query-transform-data/)：该页的新查询编辑器截图注明为 public preview，本提案未将其全部新能力当成一般版本已有功能。
- [Datadog Querying / Graphing editor](https://docs.datadoghq.com/dashboards/querying/)。
- [Datadog Widget configuration](https://docs.datadoghq.com/dashboards/widgets/configuration/)。
- [Elastic Lens visualizations](https://www.elastic.co/docs/explore-analyze/visualize/lens)。
- [SigNoz Manage Dashboards](https://signoz.io/docs/userguide/manage-dashboards/)。

本提案采用 Grafana 的编辑区域划分、Datadog 的查询语义步骤和 Lens 的数据驱动建议。没有新增 Argus 不支持的 SQL、跨来源自动合并、公式引擎、告警或导出能力。

## 推荐操作路径

1. 在仪表盘点击“添加统计图”，先选 CPU、内存、错误日志趋势、日志检索、慢链路或服务概览等常见场景。
2. 进入专用编辑页。大区域持续显示预览，下方查询构建器设置数据；右栏默认只展示推荐图型。
3. 常见配置完成后运行预览；有需要再展开高级查询、切换语句模式、调整显示或编辑下钻。
4. 点击“加入草稿 / 完成编辑”返回仪表盘。继续调整其他图和布局，刷新后恢复个人演示草稿。
5. 一次预览本轮变更并确认发布。普通查看使用已发布版本；发现基线冲突时先比较和整理，不能直接覆盖。

不建议将所有字段简单塞入“高级”折叠，也不建议把整个编辑过程变成必须反复下一步的向导。预览、当前查询及主要操作应持续可见。

## 信息放置

| 内容 | 推荐位置与默认行为 |
| --- | --- |
| 名称 | 顶部直接编辑，按场景提供初始名称 |
| 信号 / 来源 | 创建场景选择推导信号；查询区明确展示人能理解的来源名称。正式候选来自已授权、已注册的来源目录 |
| 指标 / 查询条件 | 查询区主路径，支持目录搜索与字段候选，不要求先手输内部路径 |
| 图型 | 右栏“图型”，优先推荐当前结果能承载的类型；其他图型可发现，不兼容类型说明原因 |
| 单位 / 数据类型 | 默认读取目录与结果元数据，保留覆盖入口；详细列表不强制展示不适用的数值设置 |
| 聚合与显示计算 | 查询区解释跨资源聚合；统计值的“最近值/时段平均”等显示计算放在样式，不混淆两种计算 |
| 时间 / 资源 | 顶部通用过滤，约束所有适用图；编辑预览的时间更改不等于修改仪表盘默认时间 |
| 自定义变量 | 独立“管理过滤项”入口，选择候选字段、显示名和明确的消费者；不默认影响整板 |
| 采集实例 / 厂商字段 | 按来源能力提供局部筛选；内部安装身份与配置版本由系统维护 |
| range/instant、步长、点数等 | 合适默认值；与信号相关的高级区域中仍可调整，不暴露无效控件 |
| 参数名和映射 | UI 为明确选择生成结构化绑定；跨来源映射仍需作者确认；高级编辑器可以检查完整定义 |
| 下钻 | 默认启用平台标准详情，随图预览发布；编辑完整定义时进入专门的高级编辑器，复用查询组件 |
| 布局 | 仪表盘内拖动和调整大小，支持键盘，不填坐标和宽高表单 |
| 保存 / 发布 | 编辑内容存个人草稿；最终一次预览确认发布 |

## 既有决策继续适用

- Metrics 保持 PromQL、Logs 保持 Argus KQL、Traces 保持只读 Trace GraphQL；现有构建器能力与后端执行引擎保留。
- 变量使用构建器；统计图只有一种有效编辑来源。转回构建器需服务端完整、无损解析，失败时保留语句。
- 顶部时间/资源、明确引用的共享变量及图内局部过滤保持各自范围；不因字段同名自动跨来源合并。
- APM 的统计口径仍是已接收样本，不能推算全量。
- 配置硬错误与样本执行状态分开。无数据/暂不可用明确显示未验证或警告，不显示整体正常。
- 发布仍走个人 Draft、不可变 Revision 和现有 PendingAction；版本、对象生命周期、权限与预算校验仍由后端负责。
- AI 创建与分析继续在 Chat，使用同一契约；Dashboard 没有数据导出按钮或 AI 分析区。
- Host/K8s 绑定仍在资源入口管理，承担导航，不改变数据权限。

## 正式实现的必要改动

1. 将现有 PanelEditor 拆成专用编辑页和清晰分区，复用 `@argus/ui` 的 ObservationPanel、DashboardGrid、过滤与详情组件。不要新建业务侧平行组件库。
2. 接入 Catalog 的名称、单位、指标类型、字段及来源能力，提供可解释默认值。来源或结果形状未知时不能伪造已识别、已验证状态。
3. 对草稿预览支持按 Panel/Target 执行，减少修改一张图时反复查询整板。保持草稿版本、冻结执行上下文、累计预算和取消；不让前端直连底层 Query Service 绕过授权。
4. 将不适用的控件按能力隐藏或说明。完整高级编辑应可达；语句转换依赖服务端解析，不能用前端字符串猜测替代。
5. 用任务级 E2E 验证候选失败、未运行改动、迟到预览、无数据、语法/类型错误、草稿恢复、模式转换、版本冲突、发布和两层过滤。

上述是已确认的落地要求。草稿按图样本与草稿下钻接口已实现并完成已选真实验收；尚未满足的交互与覆盖项以复核清单为准。

## Demo 使用与验证

在浏览器直接打开 `demo.html`。全部资源在本地，沿用 Argus design tokens；CSS、JS 和 HTML 分文件，每个文件低于 2,000 行。仅使用示例数据，保存到独立 localStorage key `argus.planv2.editor-ux-demo.v1`，不访问正式业务 API。

可以实际点击：添加常见图、编辑查询、运行预览、切换图型/样式、查看数据表格、筛选、变量多选与消费者、语句往返/保留复杂语句、草稿刷新恢复、已发布查看、发布确认、版本冲突、日志/Trace 详情、网格拖动/缩放及中英文/深浅色。

“演示场景”是原型测试控件，可切换无数据、暂不可用、硬配置错误以及并发发布场景；它不属于正式产品配置。原型的简单格式检查和示例绘图不替代真实解析、权限、预算或统计正确性验证。额外查询、完整下钻编辑、完整变量依赖/候选分页等能力在本原型中仅展示推荐位置，正式实现仍沿用既有契约。
