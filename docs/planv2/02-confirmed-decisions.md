# PlanV2 决策记录：Q1～Q42

## 1. 使用规则

本文件记录本轮讨论形成的最终结论，并映射到主设计与实现任务。讨论中较早的提议若被后续回答修正，以本表的最终规则为准；“已确认”表示产品决策已确认，不表示代码已实现。

Q34 仅确认多来源接入方向；原问题中的采样统计口径仍待澄清，未把此前推荐的指标优先级写成已确认规则。

Q37～Q42 已确认并同步主设计和 Task。Q40 明确重新取数使用最新发布版；已生成文件保留原版本和查询条件，单次执行冻结配置，兼容的明确条件才跨轮继承。

Q34 后续澄清及 Q35/Q36：Trace 按采集插件/厂商分别组织展示；各 Panel 可分别绑定来源，顶部通用过滤与图内厂商过滤分层。厂商功能与交互对齐，Argus 样式和对象权限保持统一，见 [专项设计](./04-collector-plugins-and-source-views.md)。

主要修正：

- Q15 修正 Q8 中“统计图也只用构建器”的早期结论：变量用构建器，统计图支持构建器或底层查询语句。
- Q10/Q11 修正早期“分析 Dashboard 当前页面视图”的提议：AI 分析仅发生在 Chat 中，不获取或修改 Dashboard 页面状态。
- Q16 确定未指定对象先让用户选择仪表盘；Q19 补齐选择后的统计图覆盖规则。
- Q12 明确本期只绑定 Host/Kubernetes Cluster，下级对象的细节后续再考虑。
- Q20/Q21 将权限收敛到对象访问与编辑，不按三信号或配置字段分权。
- Q23/Q24 改为结果落入 Workspace 后由 AI 使用文件工具自行分析判断，不用固定摘要或必填阈值替代。
- Q26 的数据范围保持：默认交付已发布查询完整结果，额外明细须有明确的已发布查询。按后续界面澄清，文件导出仅是 AI 数据查询工具内部行为，Dashboard 不提供导出入口或导出来源配置。
- 本轮界面澄清修正 Q22：自定义变量当前选值在新时段/条件候选中消失时自动回退“全部”，对象授权和系统资源范围仍然有效。
- Q27 修正前一轮将日志体验等同于更换 LogQL 的提议：保留 Argus KQL 和 ClickHouse，扩展查询能力与展示交互。Q29 确定完整 APM 目标；Q28/Q30 的 OTLP 入口方向保留，但采集、协议转换、存储和 APM 分析不能视为同一项现成功能。
- Q39 补齐标准下钻闭环：展示 Target 保持本图来源/信号，已发布下钻可显式声明其他目标信号/来源。统一权限与发布流程不意味着日志关联 Trace 时仍强制使用 Logs 信号。

## 3. 必须随实施补齐的工程事项

这些是代码核查发现的能力缺口和一致性要求，不是额外的产品范围：

- 当前 Dashboard 领域、数据发现目录和整体查询编排需新建，现有 Collector Catalog 不能代表实际观测字段。
- 目录结合信号、已绑定采集来源与实际指标/字段/值，Trace Panel 的来源绑定是执行范围；没有可靠来源时不得猜厂商，也不能把插件安装目录当成观测数据目录。
- 当前 KQL/Trace 能力及字段存储并未天然覆盖首期构建器矩阵，需通过真实三信号测试补齐。
- 系统资源过滤与自定义变量分开，空授权范围不得退化成全量查询。
- 变量按各自原生语言适配，不做统一字符串替换，不将 GraphQL 原生参数误识别为依赖。
- 发布使用 base_revision_id，并将个人草稿、冻结预览与不可变发布版区分。
- 缓存包含主体、有效对象范围、查询信号/语言、统一数据处理版本和授权版本；不同主体版本号相同不能共享不同权限结果。
- 总预算覆盖目录、Panel、明细导出、文件分片和 Workspace 空间；查询覆盖、导出完整性和实际分析覆盖分别记录。
- 大结果复用 Workspace 来源校验和 IO 边界，通过流式/有界分片交付，补齐稳定分页、读取边界、续传、去重、取消和恢复。
- 服务端保留不可变来源、查询身份与原始 Hash；本地文件可修改，派生结果不能自证为原始查询。
- AI 文件分析复用已有 Workspace 运行、容量、来源撤权和明确删除规则，不开放 Sandbox 网络。
- 结构化 Dashboard 引用、用户列表选择、Skill 显式激活与 Run 恢复是新增工作。
- Gateway 需接入 Dashboard 分类/名称映射；Action 分派不能把 Dashboard 误路由为 Collector 操作。
- 分析执行冻结服务端发布版本，但每次读取和查询都重新检查当前授权。
- 只支持桌面 Web 验收，保留双语、深浅色和可访问性要求。
