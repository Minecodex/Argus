# Chat 条件继承与累计预算

本页描述 Task 02 已接入的服务端行为。真实模型自然语言效果及正式部署 E2E 仍以 [实施状态](./implementation-status.md) 为准。

## 条件事实与发布兼容性

每个会话、每张仪表盘分别保存显式覆盖条件；每条新消息将当时的条件复制为独立 Run 基线。不存在明确覆盖时继续使用该仪表盘当前发布版的默认值。不会把默认值、临时 Panel 选择或某次查询的全部有效参数反写成用户条件。

| 条件 | 继承与变更 |
| --- | --- |
| 相对时间 | 保存区间长度；每次解析成新的绝对端点，随后冻结 |
| 绝对时间 | 保留明确的起止点；get 提供服务器时间和企业时区，供解释日期 |
| 资源 | 保留明确 ID，或明确选择的 All；空 IDs 且 All=false 拒绝，不扩大为全部 |
| 自定义变量 | 只更新明确变更的键；null 表示恢复当前发布默认值 |
| 局部筛选 | 按 Panel ID、筛选 ID 独立保存，不按名称跨来源合并 |
| Panel IDs | 本次查询的分析选择，不作为长期条件继承 |

用户消息仍是自然语言。context.resolve 要求每个变更提供本轮原消息中的精确引用，服务端核对消息归属、引用、参数类型、资源权限和版本。引用证明解释的来源，不证明模型理解的语义必然正确；存储的 origin 明确为 message_interpretation，不能把模型推断伪装成人工结构化输入。歧义仍须询问用户，真实模型测试不能由这些确定性检查替代。

保存的变量契约指纹包含稳定 ID、候选定义、来源、类型/多选、显式值映射、规范化查询使用方式及前置依赖。布局、标题或默认值变化不改变已有明确选择；同名变量换字段、来源或映射、依赖含义变化或变量删除会返回 DASHBOARD_CONDITIONS_INCOMPATIBLE。用户可针对冲突项重新指定或恢复默认，系统不静默丢弃旧条件。

## 工具流程

1. get 返回最新发布定义、analysis.condition_version、已有条件、不兼容路径、server_time 和 timezone。
2. catalog.resources 读取授权 Host/Cluster 名称及 ID。资源目录按页取元数据，超过单次执行范围的企业仍可选择较小范围；重名不能自动合并。
3. context.resolve 继承条件并应用明确变更。无变更使用 changes={}、evidence=[]；有变更须提供 expected_version 及对应消息引用。
4. 值不明确时，用 context.candidates 读取该上下文中已发布变量或局部筛选及其前置依赖。不能提交自由目录语句，不执行统计图，不保存预览回退。
5. query/v2 使用同一 Run 的 context_ref 及可选 panel_ids 发起新根查询。下钻使用已发布 drilldown 引用，不携带替代条件。

示例变更片段：

~~~json
{
  "changes": {
    "time": {"kind": "relative", "seconds": 1800},
    "variables": {"env": {"all": false, "values": ["prod"]}}
  },
  "evidence": [
    {"path": "/time", "quote": "最近半小时"},
    {"path": "/variables/env", "quote": "生产环境"}
  ]
}
~~~

示例只是字段关系；实际 ID、变量和值须来自用户选择及对应的发布配置/候选，不能直接套用示例值。

context.resolve 的结果是不可变数据库记录，同一工具调用重放复用同一记录。query 会核对当前发布版、条件版本、主体、会话和 Run；旧 Context 不能跨 Run 使用，也不能使新根查询执行已经被替换的发布版。已入队任务保持其原始定义、绝对时间及条件。

完整候选查询或精确成员检查证明选值消失时，查询准备器将其改为 All。在查询入队的同一事务中，仅将这些显式选值的实际回退写入 Run 和会话条件，标记 candidate_reset。分页、查询失败、无权的系统资源不触发扩大范围。旧并发准备过程不能覆盖更新的条件；同一查询的幂等重放仍返回原任务。

候选工具返回 complete、selected_exists、would_reset、preview_only 等状态；为模型裁剪过的候选列表必须标记不完整。其结果不能当作参数已经保存的证明。

## 一个 Run 共用一个预算

复用扫描、返回行数、样本及结果体积限额，并为目录读取、候选发现、指标元数据、展示/下钻查询及不可变文件行证据建立持久预算。分页、换仪表盘、重建 Runtime、Worker 重试或任务恢复均不会重新获得额度。用户的新 Run 获得独立预算。

| 维度 | 当前上限 |
| --- | --- |
| 扫描字节 | 256 MiB |
| 结果与行证据字节 | 8 MiB |
| 返回/候选/行证据行数 | 50,000 |
| 已加载 Metrics 样本 | 5,000,000 |
| 目录、取数及行证据调用 | 256 |

原来的单次执行预算、每个 Engine 的 Series/超时上限、文件分片限制和 Workspace 容量限制继续生效；累计预算不会放宽它们。HTTP 人工查看没有关联 Run 时仍使用原单次执行限额。

- 每次取数先在 PostgreSQL 锁保护下预留，并将受限额度交给真实 Engine。
- 完成后按可核实的扫描、行数、样本、序列化大小结算，剩余额度只返还一次。
- 在途预留造成暂时不足时有界等待；取消会终止等待。
- 失败、进程中断、响应丢失或预留过期时，不能证明未消耗的部分不返还。
- 已超过预留额度的后端结果被拒绝，并停止本 Run 的后续取数；迟到结算不能重新开放已超限 Run。
- 文件行证据在读取首个分片前按完整文件尺寸预留，分片不各自获得新限额。
- budget.get 与服务端 Run 事实提供剩余额度。文件交付状态、数据完整性和实际分析覆盖仍分开记录；预算不足不代表其余统计图健康。

## 存储和验证

migration 00007 引入 dashboard_parameter_states、dashboard_run_parameters 和不可变 dashboard_analysis_contexts；00008 引入 dashboard_run_budgets 和 dashboard_budget_reservations。新建和恢复的服务/Worker 使用同一数据库事实，未新增查询引擎或授权体系。

真实 PostgreSQL 回归覆盖条件继承、选择性重设、两张仪表盘的独立默认值、候选回退、同名语义变化、旧 Run/Context、重放、跨主体，以及并发额度、重复结算、未知/过期预留、超限后拒绝和新 Run 的独立额度。另复跑真实 ClickHouse/MinIO 的已有展示、下钻和文件任务回归。自然语言模型效果、真实 Collector/Kafka、Workspace PVC 和正式镜像的整体链路仍需独立验收。
