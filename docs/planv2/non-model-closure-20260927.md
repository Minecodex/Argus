# PlanV2 非模型收尾

用户本轮要求仅完成不依赖实际 AI 模型的剩余内容。模型的自然语言生成、条件理解、全覆盖分析及结论质量暂不执行；确定性的 Chat、Gateway、发布确认和 Workspace 协议仍须验证。Replay 只是测试协议驱动，不是模型效果证据。

**最终结论（2026-09-28）：非模型范围完成。** 页面证据为 `-f` 26 项通过 + `-g` 定向 6/6 通过；`-h` 的全部 Runtime、六项故障和确定性工具协议通过，最终退出码 0，归属清理与原有资源核对通过。完整矩阵与边界见 [验收结论](./completion-review-20260928.md)，以下保留过程及失败修复记录。

## 本轮实现

- 共享 Logs 组件采用完整正文、时间/级别、可选摘要字段、完整字段和当前结果搜索/分页；关联查询仍使用原始行及已发布标准下钻，不增加 Dashboard 导出入口。
- 来源清单显示资源、来源身份、安装代次、配置版本和注册时间，区分当前安装与历史安装。状态表示执行时的注册快照，不声称采集持续在线。历史来源不从查询候选中删除。
- Trace 详情显示来源身份。同一 OTLP 来源的 Span→Logs、Logs→Trace 标准下钻固定 source_id，避免同一主机重装后的相同 Trace/Span ID 混入另一代日志；作者明确配置的跨来源路线保留其绑定，不强行等同两个来源 ID。
- Trace Catalog 增加来源/资源身份候选，仍按时间、授权和来源过滤。
- 新增临时集群场景：真实跨批次/重复/迟到 Span，缺失父节点、Events/Links、旧 Collector 卸载与公开确认重装、冻结来源、新旧来源局部筛选、跨厂商同名服务及显式映射、授权链路及撤权、关联日志与前后文。
- 新增真实 Worker/PVC 故障场景：取数中崩溃、部分文件交付后崩溃、在途取消、真实对象分片损坏、真实磁盘配额耗尽、归档后已交付文件拒绝读取及恢复。
- 新增 64 张小型真实查询和双 Query 副本测量、正式 Chat 选择/刷新/退出/创建模式，以及确定性 Gateway 创建与多仪表盘文件工具流程。
- 2026-09-28 正式页面回归补到三项问题：`@` 搜索支持含空格的名称；窄统计值面板增加具名键盘滚动区域；KQL 前后文改为一次日志流关联后按侧排名，避免 ClickHouse 展开 UNION/CTE 导致重复扫描。

故障控制点仅编译进 `m4e2e` 镜像，且需临时 Worker 显式启用。控制表由隔离验收创建，没有生产 HTTP/Tool 入口；查询、存储、租约、Workspace RPC 和文件字节均走正式实现。测试只操作本次 release 的 Worker 和已验证前缀的对象。

`p2-depth-20260927-b` 的真实 Collector 摄入、自监控及来源停采/重装/冻结已通过；整体验收在替换 Query 副本后的容量检查失败，不能标为整体验收通过。原因是 Deployment 状态短暂仍指向旧 Pod，查询 RPC 尚未恢复；Harness 已补等待两个新 Pod 和真实查询就绪，再进行测量。此前 `-a` 在构建镜像时与契约生成目录替换重叠而失败；恢复生成产物后完整 `contracts check` 已通过，后续构建与检查串行。

`-c` 的 64 图实测通过：冷查询 943 ms、全量缓存命中 504/501 ms、替换两个 Query 副本后 928 ms。真实三信号文件/PVC/Hash 和审计核对通过，Server 保持同一 Pod、零重启和 256 MiB 硬上限。浏览器 18 通过、11 失败、3 因同组失败未执行，尚不通过整体验收。失败包括上述三项产品问题，以及测试把单选按钮当多选框、下钻请求遗漏必填字段；持续自监控产生的测试流量还使后续拓扑超出预算，现将自监控的验收样本时间固定，保留生产预算和真实 partial 语义。故障测试因 Core Worker Pod 不携带 release label 而在中断前安全停止，已改为校验已归属 Namespace 及 Pod→ReplicaSet→Deployment 的实际控制器 UID 链。该轮资源清理完成，10 个原 PVC UID/Bound 和 4 个外部 OpenSandbox 对象未变，40 个原运行 Pod Ready。

Harness 支持 `--suite planv2 --planv2-runtime-only` 定向复验 Runtime、文件故障和工具协议；明确输出 `scope=runtime_protocol_faults`、`browser_executed=false`，不能单独替代浏览器验收。仅在相同产品代码已有浏览器证据、后续变化仅涉及验收脚本时使用；实际模型不在该范围内。

`-d/-e` 在固定采样窗口后的自监控前置检查未通过：18 张图均返回成功，但没有收到 OTLP 服务端 ERROR 样本。核对项目使用的 `otelgrpc` 实现后确认，HTTP 解析拒绝和 gRPC `ResourceExhausted` 都不能保证产生服务端 ERROR；不能把预算拒绝强行算入系统错误率。Harness 后续改为核实本次 Namespace 归属后短暂停止 Query，执行真实请求取得 HTTP 503，再恢复原副本数及真实查询就绪，最后固定窗口。没有改写遥测状态或生产错误率口径。

`-f` 的真实 503 样本、采集来源和容量检查通过；浏览器 **26 通过、6 失败**。两项 Chat 失败在完整选择/刷新/退出/创建流程走通后，发现纯文本消息区缺少键盘入口，已补具名 region 和焦点样式。两项 Trace 场景已通过日志前后文和新旧来源展示，失败于测试遗漏局部筛选器名称中的 Panel 前缀；两项跨厂商场景已通过同名隔离、映射、无数据和局部刷新，失败于测试混用 innerText/textContent。已修正测试，未放宽产品断言。

该轮取数崩溃重试、已交付文件崩溃恢复、约 1.1 秒取消、分片损坏恢复和真实满额恢复均取得预期行为/Hash 证据，但清理复用了跨会话幂等键，因此五项用例整体仍标失败。已改为按会话生成删除键，并跳过从未创建 Workspace 的取消场景；同时修复 Workspace 等 PlanV5 HTTP 入口把幂等冲突误报 500 的统一映射，返回 409 和既有 `IDEMPOTENCY_CONFLICT` 契约。归档测试补齐公开契约必填字段，并保证异常退出也释放测试控制点。此前被遗留控制点阻塞的两个工具查询任务未完成，因此工具协议尚不标通过。

`-g` 使用 `--planv2-browser-grep` 定向复验上述 6 个页面场景，同时重跑全部 Runtime、文件故障和工具协议；结果将明确记录 `scope=selected_browsers_and_runtime` 和筛选表达式。必须结合 `-f` 的另外 26 项证据，不把该轮本身写成 32 项全量重跑。

`-g` 页面 **6/6 通过**，结合 `-f` 的 26 项已覆盖 32 个正式页面场景。前五项故障及清理通过，取消约 1.087 秒；最后的归档查询正确返回 `409 DASHBOARD_ARCHIVED`，测试原误期望 403，已修正。组合检查还定位到后台文件交付套用了模型工具的活跃 Run 限制，造成工具提交任务后回合成功结束，交付却报 `TOOL_CANCELLED`。现仅对受信任的内部查询文件导入允许回合结束后继续；普通工具仍禁止结束后的 Run，企业/用户/会话归属、取消与来源授权保持校验。外部 Dashboard 来源的归档/撤权/不存在在组合入口映射为 Workspace 文件禁止访问，避免把领域拒绝报为内部错误。

`-h` 仅重跑 Runtime、故障与工具协议，明确记录 `browser_executed=false`。页面证据保留为 `-f` 26 项 + `-g` 6 项，不能把 `-h` 称作页面重跑。
