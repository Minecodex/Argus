# 查询模式转换与下钻编辑

## 契约

`POST /dashboard-spec/convert-panel` 接收完整 `panel` 和目标 `mode`（`builder` / `dsl`），需要仪表盘管理权限与 CSRF。返回 `converted`、`panel` 和 `issues`。此接口只转换配置，不保存草稿、不执行查询、不代替发布校验。

- 转换覆盖同一 Panel 的全部展示与详情 Target。任何一条不支持转换，返回原 Panel 和具体问题路径；不返回半转换状态。
- 每个 Target 只保留一种 `source_definition`；整张图使用同一 `authoring_mode`，不维护隐藏的旧 Builder 配置。
- 保留来源、变量/局部/行输入及跨来源映射、instant/range、步长、下钻范围与时间窗口。转换后重新编译并检查结果类型。
- 原生参数名仅是查询内部别名。GraphQL 同一输入用于不同原生类型时可以生成类型化别名；仍绑定同一个输入和映射，不冻结为当前选值。等价检查按输入身份和原生类型核对，不依靠样本值相等。
- 转回 Builder 后再次生成原生定义，比较完整的语言结构。格式、参数别名和不影响语义的字段顺序可以规范化，查询条件、类型、返回结构和限制不能丢失。

CompilerVersion 已更新为 `argus.dashboard_compiler/v2`。旧编译版本的待确认发布需要重新预览，不沿用旧验证结论。

## 首期可表达范围

| 信号 | 支持的 Builder 转换范围 |
| --- | --- |
| Metrics | 命名指标与标签筛选；value、sum/avg/min/max、counter rate、受控 error_rate、Top N、经典桶 P95；时间和步长独立保留 |
| Logs | records、count、单字段分组计数、时间桶计数、日志前后文；条件值与同字段值集合；显式 limit |
| Traces / APM | Trace 列表、单条详情、关系图、服务/实例/接口、RED、拓扑；标准投影与参数、属性集合条件 |

反向转换采取保守规则。例如受控错误率以外的 PromQL 算术组合、without、offset / @ / 子查询，KQL parse/unwrap、自定义排序、跨字段 OR / NOT，以及 GraphQL 自定义返回投影、别名、片段、命名操作或独立常量变量对象，会保留语句模式。完整支持这些查询语言写法不等于 Builder 能表达它们；不会为完成切换而简化查询。

显式日志 limit 已纳入 Builder，并保留原有聚合/排序阶段语义；日志上下文继续使用独立 before/after 限制。JSON 数字与数字字符串不能互换。

## 受控请求错误率

`error_rate` 对同一个 Counter 使用同一窗口、公共筛选与分组。`error_filters` 是最多 32 条固定标签分类条件，额外约束分子；变量、局部条件及跨来源映射放入公共 `filters`，同时作用于分子和分母。服务器验证 Counter 元数据，不能把 Gauge 当作计数器。

结果是 0–1 比例，配合 `percent_ratio` 显示为百分比。分母为零、没有请求样本时不填零；有请求但没有错误子序列时按零错误展示；已经观察到错误子序列但窗口内不足两个点时，该分组留空，避免以零错误冒充可计算结果。这里使用独立 Counter 的接收值，不与 APM 的已接收 Span 样本统计混用，也不推算未接收数据。

查询由原生 PromQL 的 rate、sum、or、比较及 unless 组成。反向转换只接受能重新生成完整结构的同 Counter 比例，包含零分母和采样不足保护；改变分母、分组、匹配规则或保护条件后，继续保留语句模式。

## 字段目录与探索

`POST /dashboards/catalog/query` 新增 `kind=fields`，复用现有 Catalog gRPC、来源注册、资源授权、限额与取消链路。返回 `fields[{name,type}]`、`has_more`、`next_cursor`、`complete` 和查询元数据；没有单独字段权限。

- 从指定来源、资源、时间和目录筛选内的实际记录发现 Metrics 标签、日志原生字段/结构化元数据/资源属性、Trace 原生字段/Span 属性/资源属性。无记录时返回空目录，不根据接收插件配置凭空宣称有字段。
- 字段类型是存储类型（string / number / datetime）；OTLP 属性当前规范化为字符串，不能根据看起来像数字的几个值宣称数值类型。字段名须在当前语言可寻址范围内。日志正文经 parse json / logfmt 产生的阶段字段仍由显式 KQL 定义，本次不通过采样推断它们。
- 字段与候选值都支持搜索和稳定分页；游标绑定来源、授权版本、资源、时间及条件。搜索或非首页不宣称是完整集合。失败不视为没有字段或选值，不触发变量回退。
- 正式查询编辑器（展示和详情共用）可以展开字段探索、搜索/翻页/读取值，构建器可将支持的字段值加入条件。探索固定仪表盘默认绝对时间或打开时解析的相对时间，覆盖当前有权且匹配来源的资源；范围明确显示。原始字段目录不套用当前展示查询的条件或处理管道，添加条件后才影响查询执行。
- 修改来源、指标或默认时间会重建探索上下文；关闭组件取消请求，旧响应不会进入新上下文。UI 不复制原生查询解析器；最终配置仍由服务端硬校验。

## 正式界面

- 统计图和详情查询共用 `QueryTargetEditor`；详情可编辑来源、查询、参数映射、行字段路径及时间裁剪，随个人草稿和发布流程生效。
- 保存详情只更新所在统计图的暂存配置；完成统计图编辑后保存个人草稿。嵌套表单的提交不会触发外层统计图提交。
- 删除入口会整理其失去来源的后续入口，保留被其他入口使用的查询和无关暂存配置。
- GraphQL 常量变量对象与多值集合使用共享 JSON 字段。无效输入保留在编辑器中并阻止提交，不能悄悄提交上一次有效值。
- 查看查询展示已发布的展示与详情定义、参数与步长；没有增加数据导出配置或 Dashboard AI 分析区。

mock 只提供无参数基本指标的转换演示，不运行额外原生解析器；其他转换明确要求真实服务。真实转换仅由 Go 领域层实现，后续 AI 工具应调用同一契约。

## 验证边界

单元测试覆盖常用操作往返、参数身份与 All、多值及跨来源映射、混合原生类型、别名碰撞、拒绝有损转换、整图原子性，以及 DTO 非空集合约定。

独立临时 Kubernetes PostgreSQL / ClickHouse 中，三信号与 APM 的固定范围执行经“Builder 发布 → DSL 发布 → Builder 发布”后结果保持一致，转换后的标准 Trace 详情继续执行。数据通过测试直接写入存储，不包含 Collector/Kafka 摄入链路。

浏览器覆盖保留不支持的语句、模式往返、嵌套详情保存与刷新恢复；使用 mock API。此证据与真实存储测试分别记录，不视为真实后端浏览器或 Chat 全链路验收。
