# 原生工具描述前件与参数校验顺序

2026-10-24，依据 R76 的真实模型与数据库记录修正通用网关。

R76 敏感表单场景已创建监控并实际取得 MySQL 样本。后续模型先搜索 metric 分类，却在获得 overview 的描述前用猜测的 `start/end` 参数调用。网关在业务参数校验处拒绝，未进入实际业务执行；但返回 `TOOL_INPUT_INVALID`，掩盖了更前置的描述要求。模型随后获取描述、用正确参数调用并完成核验。原验收断言只允许明确的 `TOOL_DESCRIPTION_REQUIRED` 拒绝后重新描述／成功调用，因此本轮保留失败，未将其豁免。

## 统一顺序

模型工具的外层消息结构仍由 Tool Runtime 校验。对已识别的原生工具，网关依次检查当前可见性与授权、只读限制、当前 Run 中更早模型轮次的成功描述，之后才解码和校验业务参数，最后进入业务注册表。未知、隐藏或未授权工具仍不可见。描述必须匹配主体、Run、分类、工具名称和版本；同一模型批次、别的 Run 或失败描述不能代替。

未描述的业务请求统一收到正确前件错误，引导模型先取得契约；描述成功后，参数错误仍严格拒绝。描述记录存储不可用时拒绝执行。不放宽参数、授权、确认或实际数据要求，也不修改发现顺序的验收判定。

## 证据

`artifacts/plan8-r76-secure-form-discovery-diagnostic.json` 和 `artifacts/plan8-r76-secure-form-error-code-diagnostic.json` 保留实际顺序与错误代码。`tool_calls.dispatched_at` 表示外层工具代理已调用，不等于原生业务已执行；原代码在进入注册表前返回，受控测试也验证业务执行计数为零。

新用例在旧代码上复现前件错误被参数错误覆盖；候选代码通过：未描述／错误参数、描述后仍错误、未授权、描述记录故障、描述后合法调用等分支，其他分类与监控选择器的描述门禁保持通过。候选完整网关包回归通过。独立验证保持原断言：明确前件拒绝后实际恢复允许通过，模糊错误、只有拒绝或真正未描述的成功调用仍拒绝。
