# 有界重试、故障报告与数据缺口

状态：正式源码已实现，Collector 统一为 `0.3.2-plan8`，上游仍锁定 `0.159.0`。三平台构建、原生真实五分钟故障与认证负面验证通过；完整部署、全部容量门禁与统一发布仍未完成。

## 已确认的交付口径

2026-10-21 用户选择每批最多重试五分钟，并明确告警与数据缺口。出口及文件、Journald、K8s 容器日志接收配置均设置 `max_elapsed_time: 5m`，发送队列仍有界、满时背压。该参数限制批次重试窗口，队列等待另计，不能解释为端到端五分钟交付 SLA。上游在重试耗尽后会结束该批次，持久队列也不能保证耗尽后继续保存它；本地原始日志仅用于受控范围的重采，不自动重新注入已过期批次。

此实现复用原生 Receiver、Exporter 和内部统计，不 fork 资源采集插件，不启动 exporter 服务。平台身份扩展新增控制健康报告；用户关闭自身指标采集，不会关闭故障报告。

## 报告与授权

身份扩展每 15 秒读取仅回环监听的原生内部统计，将最终发送失败、接收拒绝和入队失败按日志、Span、指标点分别累计。接收和入队拒绝可能包含重试次数，不能直接等同于唯一丢失条数；共享出口也不能确定每个受影响目标和样本精确时间。页面、通知与 Agent 结果均保留此区别，控制故障不发起虚构的指标查询，不展示假阈值曲线。

本地账本使用稳定报告身份、单调序号和累计值，原子保存后经现有 mTLS 身份上报。只允许身份服务相同 HTTPS authority 和固定控制路径，不接收平台 Cookie、Bearer Key、目标指定字段、未知协议或无限重试声明。服务端从证书解析 Collector 和企业，拒绝撤销证书、计数回退、序号冲突或跨企业写入。正文、Trace 数据、目标认证和原始错误消息不进入报告。

报告和待告警标志在同一 PostgreSQL 事务保存。Worker 通过有界 Outbox 派发到已有告警中心；仅在告警实例、历史与通知事务成功后清除待处理标志。活跃任务不重复创建，任务失败耗尽后保留意图并冷却重试。Ingest 不获得私密 Agent 任务表的读写权限。受管故障策略配置只读，事件继续使用既有确认、分配、屏蔽、授权和通知路由。

本地观察预算为 2 MiB 响应、4,096 个计数序列和 768 KiB 账本；回环 HTTP 不保留闲置连接。报告只有已观测的原生计数，进程在观察前退出可能留下未观测窗口。K8s 容器日志 Agent 使用原有节点 HostPath 保存游标、队列和报告账本；Gateway 当前使用 Pod 生命周期内的存储，跨 Pod 的严格持久交付仍不能由本次容器重启测试证明。剩余队列满、磁盘、网络/TLS、32 目标和正式接入容量门禁继续保留。
