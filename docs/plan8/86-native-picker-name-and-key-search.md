# 真实选择器的名称与标识搜索验收

R60 的原生 SDK／选择器浏览器观察中，归档后的目标应用 `PickerMeta 031` 已从授权列表移除，搜索 `031` 却仍命中另一条应用 `PickerMeta 010`。共享应用列表按名称或应用标识进行子串搜索；夹具使用随机 UUID 作为标识，其他合法应用的 UUID 也可能包含 `031`。把所有搜索结果都要求为空，会将正确的标识搜索当作归档失败。

修正仅涉及验收数据及断言：为 `PickerMeta 010` 设置确定性的 `picker-identifier-match-031` 标识，明确验证短关键字 `031` 仍能显示这条合法应用；随后使用完整名称 `PickerMeta 031` 检查归档目标不可见且结果为空。权限撤销、跨应用隔离、稳定 ID、80 个应用／80 个服务分页、草稿保留和过期响应隔离的断言保持不变，生产搜索继续支持名称和标识。

候选采用真实 PostgreSQL、API、原生 SDK 采集链路与四种语言／主题浏览器模式，已在 `artifacts/plan8-r60-picker-search-candidate.log` 通过；额外的确定性碰撞并未替换 API 响应或制造监控数据。它只证明候选修正，合入后使用新的源码指纹验收，R60 的原失败保留。
