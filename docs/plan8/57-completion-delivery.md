## 本轮契约变化

Namespace 指标仍使用原来的 Cluster 物理存储根。来源键可由受信范围解析器产生 `source-id:revision@namespace-uid`，只在服务端授权后加入 UID 条件，不能由客户端把 Namespace 退化为 Cluster 范围。观测范围版本为 `argus.observation_scope/v3`，内部查询为 `argus.telemetry_query/v6`，目录为 `argus.telemetry_catalog/v4`；旧执行端明确拒绝新协议。

固定 K8s 集群/节点指标使用原生 `k8sattributes` 补齐 Namespace UID，摄入再核对可信元数据。后台同步通过接入身份读取分页快照；未完整读取不退役目录，租约或接入版本变化时事务回滚，晚到快照不能覆盖较新的前台读。新增后台任务只更新元数据，不授予用户资源权限。

对话表单的认证输入只存在于门户宿主内，模板 iframe 和模型均不接收。更新凭据时固定表单打开时的对象版本，仍调用现有监控预览与确认；独立 drain 取消复用门户的同一事务逻辑，明确已发出的驱逐可能完成、Node 不自动恢复调度。

APM 依据受信应用/服务身份汇总，保留 `sourceIds` 和去重观测数量；`sourceId` 是集合中的代表来源。跨来源服务下钻不误缩成代表来源。仅按确切 Trace/Span 身份去重，不猜测不同 Span ID 是否来自双重埋点，也不合并未具备受信应用服务身份的旧来源。

## 完整驱动发现与修正

首次 59 组重跑发现锁定的 `k8sattributes` v0.159.0 不支持 `k8s.namespace.uid` 提取项，不能用配置/查询单测通过代替实际进程验证。已删除无效提取项，保留原生 Pod 身份增强；新增 Migration 48，在现有可信资源读取接口核对 Namespace 世代后，仅保存 Pod/工作负载/PVC 的 UID 关联。摄入通过不可变对象 UID 查询当前有效 Namespace，不按名称推断。无对象 UID 的原生名称指标保留 Cluster 范围，不赋予 Namespace 行权限。

该变更没有 fork 或新增资源 Receiver。原生采集仍由官方 Receiver 完成，Argus 仅补齐已有目录和数据授权边界。实际 Collector 已重新采样成功，真实 Pod 与 Namespace 重建隔离检查通过；名称替换不会接管旧 Pod UID。旧配置失败日志保留。完整驱动运行期间生成 sqlc 曾使一个构建读到中间生成物，该项单独重跑，不能将原运行记为全绿。
