# 监控列表筛选与仪表盘工具栏

2026-10-26，根据正式门户截图修正监控列表与仪表盘筛选区域的排版，并补齐采集实例筛选。

## 交互与范围

- 监控列表沿用共享 `FilterBar`、`Select` 和 `DataTable`。筛选区域与表格之间保留设计 token 定义的间距。
- 名称搜索可以与类型、配置状态、采集健康、数据状态、期望启用状态组合，各条件使用 AND。
- 类型包含服务集成及主机、Kubernetes 固定自身采集类型；固定类型的名称随门户语言切换。
- 启用状态筛选表示期望配置，配置生效状态、采集健康及数据新鲜度独立表达。筛选后的空列表提示调整条件。
- 改变条件后回到第一页。服务端先授权和筛选，再执行游标分页，避免只过滤当前页。
- 仪表盘的时间、应用、资源类型、资源范围及刷新周期使用统一字段布局，控件底边对齐，刷新操作靠右。
- 从监控列表打开默认仪表盘时传递实际 `target.kind`，例如主机使用 `host`。继续执行原有资源授权。

## 统一契约

`GET /monitoring/collections` 新增 `desired_enabled`、`apply_status`、`health`、`freshness`，沿用原有 `integration` 和 `search`。

`desired_enabled` 省略表示不限；`false` 明确筛选关闭实例。状态字段使用枚举并拒绝未知值。新筛选字段进入游标绑定，改变条件后不能复用旧游标。

新鲜度沿用现有规则：没有样本为 `no_data`；最近样本距离当前时间超过采集周期的三倍与两分钟的较大值时为 `stale`，否则为 `fresh`。一次请求的 SQL 筛选和返回投影使用同一个观察时间。采集周期由原有写入路径规范化保存。

OpenAPI、生成客户端、真实适配器、隔离 Mock 与 Agent 采集列表工具采用同一组字段。其他目录不增加无关的采集状态筛选。此次调整不需要数据库迁移。
