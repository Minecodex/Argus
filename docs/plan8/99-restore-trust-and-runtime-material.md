# 恢复时保留信任根与运行时密钥

2026-10-24。本文规定恢复材料契约；实际验证与发布状态见 `progress.json` 和 [交付记录](./57-completion-delivery.md)。

R77 的完整业务、支持矩阵及前 75 项门禁已通过，但发布演练的实际快照恢复暴露了正式恢复路径的缺陷，不能据此前通过结果宣布发布。

## 实际失败

- `artifacts/k8s-e2e/p8rollback-plan8-release-e8139203` 保存了恢复后的失败报告。Direct Executor 和 action Worker 因挂载 Bundle 与数据库 epoch 1 不一致退出；PKI Controller 报告新目标服务证书不能链到恢复数据库中的原 Bundle。恢复前安装生成了新的根 CA，而数据库恢复带回原有信任状态。
- 同一报告记录了只读 `local-unseal` 容器读取 `argus-bootstrap.json` 时权限被拒绝。恢复程序以 UID/GID 1000 原子写入 0600 文件，读取容器的用户不同。此前仅由高权限测试进程执行解封，未覆盖真实共享组读者。
- 原环境已恢复核验通过，耗时 67.14 秒；原业务部署未升级。R77 的失败报告和各次演练驱动修复保留，不改写为通过。

## 恢复边界

加密备份采用 `format_version: 3`：除数据库、对象存储、OpenBao 和配置外，必须包含稳定 PKI 的 Bundle epoch、Issuer generation、公共 Bundle、受管根密钥，以及幂等、游标和 PendingAction 使用的运行时密钥。缺少必要材料的旧格式在创建目标前明确拒绝。

受管根私钥仅存在于受权限保护的加密备份与目标 `cert-manager` 的不可变受管 Secret 中，不进入公共 Bundle，不下发到 Connector 或 Collector。客户自有 ClusterIssuer 模式仅保存公共信任材料；恢复目标必须提供可签发同一信任链的 Issuer，绝不读取或导出客户根私钥。

备份要求根轮换已稳定，并在采集其他组件前后核对信任材料及运行时密钥一致。恢复使用新的 release 和命名空间，在签发目标叶证书前写入经过验证的原根材料及 epoch；现存但不同的根或密钥不覆盖。新叶证书按新域名和命名空间重新签发，仍接受完整证书链、用途和身份检查。

OpenBao 恢复文件保持原子替换，使用写入者与 Pod 共享组可读、其他用户不可读的权限；只读挂载保持只读。验证需覆盖实际不同 UID 的共享组读者、无关读者拒绝，以及重启后解封和原密文解密。

## 验证要求

- 旧失败路径的定向复现，完整恢复材料的缺失、篡改、错误密钥和所有权拒绝。
- 不同 release 恢复根 CA、Bundle epoch、Issuer generation 和运行时密钥的独立验证；客户 Issuer 不导出私钥。
- 真实 OpenBao 不同 UID 读者的读取、重启、解封及解密；真实 cert-manager 叶证书链验证。
- 新版本冻结后完成适用回归与实际发布演练，特别核对恢复后的运行时健康、用户、MFA、凭据和最终升级。

这项修复改变备份材料契约，不放宽 TLS、权限或发布门禁。最终实现、验证和发布状态以新的冻结记录为准。
