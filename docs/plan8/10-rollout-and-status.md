## 迁移策略

项目开发阶段允许替换旧 Profile/Scope 契约，不要求长期双轨兼容。实施时先选择有明确证据的迁移或受控重建路径；不得把“可清理历史兼容”解读成删除所有业务数据的授权。

1. 盘点当前企业、Host/Cluster、Collector/Source/Claim、凭据、Dashboard/草稿/绑定、告警/后台主体、会话/Workspace 和租户遥测表。记录版本、ID、数据量、关系和共享依赖。
2. 划分可直接保留的基础设施身份、需要显式应用映射的业务来源、可按拥有者重建的测试配置和必须保留的业务数据。
3. 先准备目标 Schema、权限/用途与资源映射，再升级生成配置、Ingest/Writer/Query/Server/Worker/Connector 和门户；能力握手阻止不兼容版本互通。
4. 对已有主机/K8s 固定 Profile 生成等价内置实例。不能自动依据 service.name/IP/显示名把旧数据绑定到新应用或扩大授权。
5. 旧业务来源不能可靠映射时明确停止/隔离其旧写入路径，使用经过核对的映射或针对明确测试对象的重建方案；不能保留一个绕过新授权的旧查询入口。
6. 不修改聊天、审计、旧查询文件和历史告警来伪造新身份。历史文件保留原来源快照，重新取数使用新契约。
7. 删除/重建必须列出精确对象、所有者、影响和恢复前件；保留非目标业务、Git、LFS、测试证据及共享中间件数据。

数据库迁移序号、ClickHouse schema version 和内部 RPC version 在 T01/实施时按实际仓库状态分配。本计划不预占尚不存在的序号，也不把文档中的示例结构当最终 DDL。

## 切换与回退

- 切换前封存源状态与加密材料的恢复前件，完成测试环境迁移和备份恢复演练。
- 新类型/字段先可识别，再写入，再开放查询/门户能力；节点缺失支持时 fail closed，不能丢字段后按 Host 全量接受。
- 旧配置被新版本替代后停止旧写入/协调者，明确 active epoch，避免双版本控制同一 Collector。
- 回退不是只换旧镜像：若旧版不识别新身份/Schema，必须阻止旧版读取新数据，按演练恢复兼容快照或修复后前进。每个阶段记录可回退条件和不可逆点。
- 配置回滚、数据库恢复、Collector 回滚和用户 Dashboard 模板回退分别演练；恢复监控凭据引用/版本不能丢失加密密钥或恢复已撤销 Key 为有效。

需要缓解资源压力时，可在用户已有授权范围暂停正常部署；先记录工作负载副本、HPA/定时任务状态、服务健康、PVC/PV UID、持久数据和共享依赖，再执行可恢复暂停。测试失败也要恢复原状态；不能通过删除共享卷、共用中间件或其他项目资源来腾空间。

每个环境报告区分：已验证、受控测试、未验证、实际阻塞。Linux 容器不能替代真实 Windows/IIS；Windows 11 不能替代 Windows Server；API/Pod 可用不能替代 Collector 收敛和真实遥测；受控模型重放不能替代真实 Provider。

1. 全部平台任务及支持组合 required 门禁完整，39 候选的专用采集选型结论齐备，无合格专用内置采集方案的缺项附证据；外部前件无未验收必需项。开发/测试分批，最终统一发布。
2. 冻结源码、生成物、后端/门户镜像、Collector 发行版、配置目录和模板版本，测试结果绑定同组指纹。
3. 完成相关 Go/前端/契约/生成检查、real 构建、权限/故障和临时环境完整 E2E，既有 CI 门禁不能被绕过。
4. 在目标部署上核对实际版本、迁移、健康、身份、授权、配置生效、真实样本及至少一次应用→日志/Trace→关联目标→仪表盘/告警闭环。
5. 保留并核对非目标业务数据、会话、凭据、卷和工作负载；记录清理/恢复和回退条件。
6. 报告完成范围、真实模型/真实目标/发布结果与仍受限能力。未通过项不能用其他版本或环境结果替代。

全部纳入支持的组合与平台功能完成后统一发布。中间可内部评审，不分批上线。用户已明确允许官方及有充分维护/使用依据的社区均无合格内置Collector方案的类型/模式暂缓，必须保留检索证据并在最终缺项表说明；这不等于任意删减第二批。存在可用方案但缺真实环境、未开发或测试失败仍为未完成，不能套用缺项豁免。

本地部署成功不自动意味着生产 Profile、容量或灾备就绪；沿用现有安全/运维 readiness 门禁，与 Plan8 功能交付分别报告。

## 状态维护规则

- 任务 `implemented` 只表示代码/契约完成，`verified` 需要任务自己的验收证据；计划 completed 还需完整组合与目标发布核验。
- `integration.status`、每个版本/平台/拓扑和五个子门禁分别维护，不能用总 supported 覆盖失败组合。
- selection_status 与验证状态分开：pending/selected/deferred_no_eligible_embedded_component。所有候选保留 ID；required 支持组合数在选型冻结前为 null，不能用 0 表示已经审查完。
- 失败轮次、缺前件、skip 与修复记录保留；最终汇总从逐项证据计算。
- 文档变更同步到决策、Schema/接口、API Client、门户说明、Agent 分类指南和验收器。
- 证据文件包含路径/Hash/范围，不保存真实认证输入。可恢复配置与记录不能只存在 Redis 或单次模型上下文中。
