# 仪表盘、统一范围、模板与联动

## 已实施的查询边界

内部执行请求升级为 `argus.telemetry_query/v5`，数据目录为 `argus.telemetry_catalog/v3`，概览请求为 `argus.telemetry_overview/v2`。Server、Worker、Query 必须一起升级；版本不匹配返回 `QUERY_PROTOCOL_VERSION_UNSUPPORTED`，不回退 Host-only 或无来源过滤模式。

授权资源以类型＋UUID 传递，来源查询同时匹配 `resource_type` 与 `resource_id`。RPC、缓存及查询快照同时绑定主体、授权版本、资源类型、来源配置版本和 ScopeSignature；资源版本、关联版本与仪表盘 Revision 分别保留。概览也按冻结 source_key 过滤，空来源不扩大为所有来源。Native HTTP 查询在范围内没有可查询来源时返回明确的 `QUERY_SOURCES_EMPTY`，Dashboard 空筛选仍保持空范围。

下钻沿用父结果的不可变定义，保存派生资源和关联版本；返回前重新检查资源类型和授权。相关验证见 [T03](./task-03-scope-and-authorization.md) 与[实施记录](./14-implementation-log.md)。Namespace 遥测行级约束和完整 APM 关联仍需后续实现与验收。

## 一个服务端范围解析器

应用页、资源详情、临时查询、Dashboard、告警、原生工具、结果导出和 Workspace 使用同一 `ScopeResolver`。门户只提交类型化选择，不在浏览器拼授权资源全集或把可见第一页当查询全集。

```text
当前企业/主体授权
 ∩ 已发布查询与时间范围
 ∩ 应用/服务及面板声明的当前关联资源关系
 ∩ 环境归属与目标集合
 ∩ K8s 对象/采集实例/来源约束
 ∩ 面板支持的信号/类型/维度与局部条件
 → 冻结目标、授权根、来源版本、关系版本和参数 → 执行 → 返回前复验
```

### 参数契约

| 条件 | 输入/语义 | 失配行为 |
| --- | --- | --- |
| 时间 | 绝对范围、时区、步长、预算 | 范围/预算错误明确拒绝 |
| 应用 | 明确 app IDs；All 是单独模式 | 未授权显式 ID 拒绝，不静默返回其他应用 |
| 服务 | 已登记/发现的 service IDs，环境继承应用 | 上层变化导致失配时保持空，不按同名替换 |
| 关联依赖 | 面板声明应用自身或关联资源，选择应用后自动解析对应当前关系 | 无需用户额外开启依赖开关；仍求交独立目标权限，资源指标标明共享口径 |
| 环境 | 每个应用唯一环境；多应用关系可能得到环境集合 | 未关联不当生产，共享关系不等于独占归因 |
| 资源类型/子类型 | Host/Cluster/应用服务/数据库等语义类型 | 不兼容面板显示不适用；不借 Receiver 名决定类型 |
| 目标集合 | all_authorized 或显式 IDs | 显式空列表为空；用户选了无权目标返回拒绝 |
| K8s 对象 | cluster＋namespace＋kind/UID＋container | 控制面 Cluster 指标不支持 Namespace 时显示不适用；不能忽略条件 |
| 采集来源 | integration/collection/source/版本与安装代次 | 停采仍解析保留期历史；不能把新增来源加入已冻结查询 |
| 面板局部条件 | 受控字段、操作、实例等 | 仅继续收窄本面板，不能修改全局授权 |

区分两种收窄：All 模式自然只枚举当前授权对象；用户显式请求未授权对象则整体拒绝，不把少量成功结果伪装成完整集合。应用关联可在界面标明依赖存在但不可读，不能通过名称、计数或错误泄露未授权目标细节。

候选游标、范围 Hash、预算、缓存、后台结果、分析文件均包含企业、主体、授权版本、资源/来源/关系版本、时间和参数。角色切换或撤权后不可复用旧缓存/游标/下载授权。

## 类型适配与共享资源

- Host 过滤只选被监控主机；其 Collector 远程采集的数据库不会自动进入 Host 查询。
- K8s 同时解析 Cluster 与 Namespace 授权，实际指标/日志按 UID/Owner/namespace 过滤；仅 Namespace 授权不包含控制面全局指标。
- 数据库实例可以关联生产应用 A 和测试应用 B；查询 A 的生产范围只能使用 A 的关系分支，不能拿 B 的环境补匹配。
- 一个共享目标只进入范围一次。依赖关系边可以多条，遥测不按应用复制或重复求和。
- 构建器、原生 PromQL/KQL/Trace GraphQL 和下钻必须执行同一约束；不通过字符串拼接实现权限过滤。
- 面板声明 supported resource kinds、signal、source capabilities、required dimensions 和 filter mapping。没有必要字段返回 capability unavailable，不用虚假空图或 0 混淆。

## 默认仪表盘模板生命周期

每个 IntegrationDefinitionVersion 关联一组 Argus 原生模板：总览、实例/节点/队列等详情、适用日志/APM 下钻与告警建议。内置组件开关启用后提供对应默认仪表盘入口。

模板与用户 Dashboard 分离：平台模板版本不可变，受管默认入口在兼容版本验证通过后自动指向新版，用户自动看到更新；保留版本记录和回退。用户副本/草稿独立，提示可用更新及差异，不覆盖修改。运行中查询固定旧模板 revision，缓存和新分析按新版本失效，不中途改公式。资源关联不授予权限或限定 Dashboard 的全部可查询集合。

应用关联资源面板默认按当前关系查询保留期内目标指标，包括关联建立前的数据；显示关联时间及共享资源整体口径。业务日志/Trace 始终按观测时应用身份；已冻结结果、历史告警与导出不随当前关系重写。

集成删除/停采保留模板可读历史；目标归档、来源失效与无数据有明确提示。复制/发布模板校验目标类型与真实能力，不产生一批永远取不到数据的默认图。

### Grafana 参考的使用

以 [42 条参考表](./grafana-references.md) 为初始研究清单，逐项记录源 URL、ID、revision/commit/hash、原始数据源/exporter、变量、Recording Rules、依赖和采用范围。该清单来自本轮已核对资料，不代表最新兼容版本，实施时锁定具体版本。

原始Grafana模板列出的exporter仅用于理解来源，不能据此部署独立exporter。暂缓资源不开放可用的默认仪表盘入口；查询必须映射所选专用采集组件的实际指标，无法等价得到的面板标能力缺口或暂缓，不伪造字段。

转换流程：

1. 取得原模板配置并列出每个 Panel 所需指标/标签/单位/函数/变量。
2. 与本集成真实采集样本及版本化字段目录对齐，区分 Counter/Gauge、速率/累计、Histogram 和采样统计。
3. 复用可映射的公式；不等价字段重新设计查询。Recording Rule 需在 Argus 实现受控等价方案或改写，不能假定已存在。
4. 转为 Argus Dashboard Schema、shared UI 与来源绑定；日志查询采用 Argus KQL，Trace 采用已有引擎。
5. 真实取数比较数值/单位/范围/无数据行为，并测试中英/明暗、下钻与权限。
6. 将已验证模板、查询能力、集成支持状态和发布制品绑定到同一版本。

不以“JSON 能导入”“页面有图表”或“PromQL 能解析”当作模板验收完成。复用外部配置时记录来源及其适用的许可证/Notice，具体复制内容在实施时核对。

## 应用 APM 与探索

应用页提供服务/实例/接口/依赖、Trace/日志、默认仪表盘和接入配置。其查询复用已发表的能力/受控定义，UI 组件进入 `@argus/ui`，不复制另一套图表和查询编辑器。

保留已接收样本口径、实际时延分布、Coverage 和未知状态。日志→Trace、Span→日志、应用→共享数据库、工作负载→Pod/日志等下钻显式映射目标信号、身份、时间与权限，不能根据名字任意跨源。

## 告警与 Agent

复用 Plan6 后台主体、策略版本、多规则评估和通知机制。监控目标、应用与新来源进入相同 Scope；共享聚合必须按完整参与资源授权读取。

- 配套默认规则为建议/可预览配置，创建监控不自动发送外部通知或自行开启生产告警。
- 主动停采、采集失败、没有数据和目标健康异常分开；停采关联策略按明确策略进入 suspended/not_evaluated，不能误发 NoData/恢复。恢复采集后按新样本与持续窗口重新评估。
- 单实例停采只影响其实际贡献的来源/信号覆盖；仍有其他有效来源时按冻结查询能力继续判断。跨目标聚合缺少成员时记录不完整/不评估，不能剔除停采目标后输出伪健康结果，也不能把所有关联策略一律静默。
- 资源关联变化不静默改写已冻结告警结果；后台周期冻结当次成员及版本，保存审计和事件快照。
- 本计划优先扩展既有指标告警。完整日志告警、Profiling、SLO、自动处置等不因新增应用入口自动纳入。
- Agent 使用同一选择/范围契约，工具取数落 Workspace 并保存来源，不根据 UI 状态或采集开关自行断言业务健康。

Namespace 的查询选择与存储身份已分开，应用/运维日志在聚合与候选查询前按已登记来源过滤；当前实现和验证层级见[Namespace 日志范围](./16-namespace-log-query.md)。查询协议不会把 Namespace UUID 自动当 Host 或 Cluster UUID。

受管默认仪表盘属于系统提供的只读定义：具有仪表盘读取能力的企业主体可以查看这些定义，不需要为固定系统定义逐人补发 Dashboard 对象授权。该规则仅适用于由平台登记的 managed 实例，普通仪表盘继续使用显式 Dashboard 授权；任何数据查询仍要求当前资源/应用/Namespace 与信号来源权限。编辑默认项创建独立个人副本，默认项不接受用户发布、归档或重写；数据库同时保护该边界。
