# 真实选择器与逐集成配置准入

大列表测试已纳入正式 native SDK 浏览器驱动，不再依赖 overlay。先执行原来的应用只读浏览器检查，再临时授予本轮选择器所需权限，结束后只恢复本轮新增权限和精确的 Host 授权，最后继续 SDK 撤权与轮换检查。

实际 PostgreSQL 中创建80个应用、80个声明服务；声明服务的 first_seen_at/last_seen_at 保持NULL，没有伪造监控观测。四种中英/明暗桌面组合验证：每页不超过30项、实际游标与搜索请求、跨页选择、取消不污染父草稿、服务分页、环境不出现独立输入、真实POST只序列化稳定应用/服务/Collector ID。通过延迟实际服务响应并等待响应释放完成，验证切换应用后没有混入旧服务；撤权和归档后候选消失，其他应用仍拒绝读取。

这部分使用受控会话、授权及归档夹具，验证实际API与浏览器行为。预览请求在没有凭据与采集运行时的API夹具中明确返回503，保留父草稿；没有确认或新建监控。正式采集创建仍由已接入Collector的完整部署门禁负责，不能把这条错误路径当作部署通过。

`artifacts/plan8-picker-official-r2.log`：原应用页面4项与选择器4项均通过，完整实际SDK三信号、应用只读权限、撤权和轮换继续通过，67.85秒。选择器逐项JSON和截图保存在 `artifacts/plan8-picker-official-r2/`。先前定位过程中测试选择器、请求路径和缓存预置错误的记录保留，不列为产品缺陷或通过。

逐服务部署准入另增加真实配置负向探测：以相同有效凭据和执行Collector提交非法间隔，要求明确MONITORING_INVALID、没有目标/采集残留、Collector期望版本不变、私有草稿不增加，然后继续正向配置、真实数据、默认视图、授权与独立启停。失败实例会先校验精确名称、类型和Collector，再停止本实例，保留历史Receiver诊断后清理自有测试目标；不能让已删除目标的活跃采集污染后续组。此扩展已实现，下一正式部署复验后才计入CONFIG门禁。

完整部署还加入独立门户门禁：沿实际已认证会话读取应用、监控、主机、Kubernetes、仪表盘及告警六类页面，四种语言/主题组合检查真实域API、页面标题、桌面溢出、运行错误，并分别保存截图与结构化收据。仅执行读取，浏览器trace关闭；这项新增门禁尚待完整部署实际运行，不以驱动编译通过代替页面通过。
