# 源码冻结与状态报告版本

验收原先将整个工作区连同 progress.json、完成记录和入口索引一起计算源码摘要，导致写入验收结论本身就改变“已测版本”。这会形成完成状态无法记录的循环，也使单纯的状态更新要求重复执行不变的二进制。

现采用 `argus.plan8_source/v2` 摘要输入。代码、测试、生成物、依赖、构建配置、三个 Collector 制品、模板，以及原始验收合同和设计文档仍严格进入实现摘要。只将下列三个状态/导航报告单独保存文件摘要与 report_fingerprint：

- `docs/plan8/progress.json`
- `docs/plan8/57-completion-delivery.md`
- `docs/plan8/README.md`

它们的修改记录仍保留在验收前后快照；既不作为通过证明，也不改变已测实现的身份。`09-acceptance-matrix.md`、`api/contracts/plan8-acceptance.json` 和其他设计文件未被豁免，改变实际范围、断言或实现必须重新验收。旧摘要不自动映射到新摘要，不将历史结果改写为当前证据。

回归验证三个报告各自更新时，报告摘要变化而实现摘要不变；更改验收矩阵或未提交代码仍改变实现摘要。源码/制品不变、精确物料校验、具名断言和完整发布门禁继续独立成立。新规则已经实现和组件验证，最终同版本完整验收仍待执行。
