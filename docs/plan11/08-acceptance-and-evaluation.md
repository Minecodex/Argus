# 验收矩阵与真实模型评测

状态：候选实现、隔离数据链路、浏览器矩阵和真实模型验收已经执行；完整部署轮次仍有失败，尚未整体放行或正式部署。具体通过范围、失败和重跑见 [实施记录](./implementation-status.md) 与 [进度](./progress.json)。实现任务必须把下面每项关联到实际证据文件、源码版本与执行时间。

## 1. 六层证据

| 层次            | 验证内容                                             | 不能替代                 |
| --------------- | ---------------------------------------------------- | ------------------------ |
| L1 注册/契约    | 生产目录、Schema、元数据、版本、公开/隐藏边界        | 真实业务授权和数据       |
| L2 领域/存储    | 当前主体、显式资源、来源、分页、状态与持久化         | 实际采集/浏览器/模型     |
| L3 真实数据链路 | Receiver/SDK → Collector → Ingest/队列/Writer → 查询 | 模型自主选工具           |
| L4 Chatbox E2E  | 真实工具响应、封存结果、SSE、模板/宿主、导航         | 全类型采集支持和结论质量 |
| L5 真实模型     | 自主分类/定位/查询/分析、用量及业务 Oracle           | 正式部署和稳定运行       |
| L6 发布/恢复    | 不可变制品、运行版本、数据保留、健康、回退           | 未通过的前五层           |

每项状态只用 passed/failed/not_run/blocked/not_applicable，并保留理由。首次失败及重跑分开，不删除失败或把 skipped 当 passed。

## 4. 真实模型比较

### 准备

- 明确用户当前已配置且允许使用的模型、真实 CLI/API 调用路径和本轮预算；不从文档猜凭据，不静默切模型。
- 冻结基线/候选源码、模型版本与采样参数、工具版本、资源/来源版本、问题、时间窗口和语言。
- 以第 04 篇 S01～S25 为任务池；按有前件的场景记录适用性，不能删除难例来改善成功率。
- 每个关键路由场景至少 3 次独立会话，不复用工具描述和历史答案；中英分别记录。
- 预先定义物理/领域 Oracle：真实负载、预期异常、查询范围、实际操作结果与已知无数据项。模型无法从提示读取答案。

### 指标

| 指标               | 计算与候选目标                                                                    |
| ------------------ | --------------------------------------------------------------------------------- |
| 首次能力定位正确率 | 首次有效分类/对象/来源匹配任务；候选目标 ≥95%，同时比较旧方案                     |
| 任务完成正确率     | 对象/时间/来源/查询语义/结论/交付全部符合 Oracle；候选目标 ≥90%                   |
| 关键任务           | 每个正式支持类型至少一次完整成功；失败类型不列为已验收                            |
| 无效调用           | 参数错误、错误分类、重复 Describe、无效来源、错误模式分别统计；新方案应较基线减少 |
| 发现成本           | 得到第一份有效证据前的模型轮次、工具次数、输入/输出 Token、端到端耗时 P50/P95     |
| 总成本             | 所有尝试、修复、失败和压缩的实际用量，缺失用量单列，不估计为已报告                |
| 用户负担           | 必要与多余澄清/确认次数；同名资源应澄清，精确身份不重复询问                       |
| 结论质量           | 每个关键结论有证据，时间/覆盖/假设明确；无数据/部分结果未误判健康                 |

以上质量阈值是候选门槛，T10 建立基线前登记后冻结；调整必须保留原因与失败结果。权限泄漏、隐式范围扩大、伪造数据、未知写重放等硬门禁要求零违规，不能靠平均成功率抵消。

对照至少比较：直接按领域工具、observe 目录路线、匹配仪表盘优先路线。不要在真实模型提示中写死必须调用的工具序列；协议回放可以验证固定序列，但不是自主路由证据。诊断类结论需要实际读取 Workspace 文件，不能仅依据卡片摘要。

## D44：聚焦元数据语义的真实模型复验（计划）

新增仅显式启动的plan11-metadata阶段，保留真实Host/Collector、Workspace、当前生产后端与API前件。复用现有真实Go SDK→Collector→Ingest/Kafka/Writer→查询验证，仅选择OTLP HTTP协议，关闭SDK Key模型交付子任务，防止隐式增加付费调用。原SDK阶段的密钥撤销/轮换/端点关闭证据保持；后续通过正常Preview/Commit重新启用该端点并等待收敛，使用无采集实例但有实际SDK接入与先前真实样本的应用。

声明两类任务各中英3次，共12独立会话，每项供应商调用验收上限32、合计384，兼容性探测单列。SDK-only任务核对应用的已配置接入、信号和当前状态，判断采集实例为空能否推出无监控，必须实际读取当前授权端点/来源事实，不能把空节扩展成全应用否定。采集活动任务给明确采集实例ID，仅查配置并区分本次有无遥测查询与历史数据是否已核对，禁止探测、写入、发布与遥测样本查询。

它验证D43两处已发现的通用语义缺口，不重跑已签收A08的12项身份矩阵，不从组件通过预判模型正确。真实模型答案仍作独立正文检查，不要求抄完整证据JSON；必要的少量断言只用于自动Oracle。阶段只增加开发验收能力，不新增产品工具、权限或查询引擎。

## D54：独立高分辨率证据路径验收

开发验收器可显式启用--plan11-high-resolution，仅允许plan8/plan11-compare、candidate-only及delivery_summary_v2。默认60秒、旧strict/旧新对照和历史评分不变；这是开发验收参数，不是Search/Describe/Invoke输入或新增业务工具。

独立功能批次为指标、目录、仪表盘三种问题各中英一次，共6项、最多192次验收模型调用，兼容探测用量另计。固定同一实际Host/来源/UTC窗口；原生指标1秒步长，已发布仪表盘仍保持自身冻结步长。目录任务要求原始CPU利用率全部state，不允许用子集/缩放/offset代替；最终报告选中的原件必须实际超过32768字节且由独立下载原件验证，不按调用次数或未使用的大文件替代。只有最后所用原件的请求步长正确才通过。

Collector在冻结前追加一分钟真实采集，不注入样本；若实际数据仍不足大原件门槛，本项如实失败，不称大结果验收通过。模型需读取/离线处理完整原件，投影裁剪不可当完整数据；保持全部实际返回序列、原件Hash、真实点数与min/max/单位。Manifest原字节与各面板均通过同一Workspace授权下载和封存Hash/大小检查；manifest不当作数值面板计数。新证据v2的not_requested/verified状态需要实际模型正确解释。此批次是新路径功能补证，不冒充完整18项质量或旧新对照通过。

## 业务发现与范围闭环独立批次

plan11-workflows只运行既有真实Host/Collector/Workspace/API前件和五项明确模型任务：中英文仪表盘类型/信号/集成筛选各一次，以及普通诊断、仅仪表盘分析、同会话退出限制三项。每项上限32调用/600秒，兼容探测另计。另一个已授权但无来源的Host仅作元数据适用性对照，不表示实测空数据；其授权在模型任务开始前通过正常数据授权API完成。

两项真实作者的样本与发布预览必须都保持显式单Host范围及正确百分比单位。取消后的新幂等键确认请求，既有Action服务以HTTP409/PENDING_ACTION_INVALIDATED拒绝；资源动作也有ACTION_STATE_CONFLICT映射。验收仅接受这两种明确拒绝，不把任意409当成功，并继续核对数据库无重复发布。不得为符合测试字面值改变确认或授权规则。每组语言/主题预览即时落盘；两个独立草稿的取消与确认用例允许分别完成，任何失败仍使整轮失败。原R69失败与确认未执行保留，不重新评分。
