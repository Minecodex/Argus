# 实施任务、依赖与完成条件

本计划正在实施；当前进度见 [progress.json](./progress.json)。每个任务应在实现后补本任务证据，再进入后继任务。文档存在、Schema 已生成或 mock 测试通过均不等于真实业务闭环完成。

## 1. 阶段和依赖

```text
T01 基线/统一注册与默认发现
  → T02 元数据与契约版本
    → T03 资源发现 → T04 能力发现
    → T05 数据目录
T03 + T04 + T05 → T06 三信号与仪表盘筛选
T02 + T06 → T07 诊断范围与恢复
T03～T07 → T08 Chatbox 业务入口与视图
T01～T08 → T09 完整契约/覆盖/隔离 E2E
T09 → T10 真实模型、业务验收与发布准备
```

有独立条件的模块可以分批开发，但不能把某一模块通过作为后续链路通过。修改范围始终覆盖领域服务、工具注册、OpenAPI/JSON Schema、生成客户端、Agent 上下文、展示、测试及文档。

## 2. 任务明细

### P11-T01：统一基线与生产注册

- 复核 130 个当前工具、三元入口、Provider 条件、公开/隐藏边界与生成目录。
- 将 Server/Worker 的业务注册及关键依赖配置收敛为可复用构造路径，避免测试构造一份、生产又一份；不把启动网络/数据库的整段 app 函数抽成巨型工具模块。
- 修复默认仪表盘发现差异，确认仅资源授权主体在两条路径的结果一致；私有模型治理继续排除。
- 工具标签、展示声明和夹具生成使用相同登记事实；专用宿主交互允许独立交付方式。
- 主要位置：internal/app/{server,worker,component}、internal/toolgateway、internal/dashboard、scripts/tool-labels、internal/tooltemplatefixture。
- 完成条件：真实 PostgreSQL 的门户/Worker 差异用例先复现后通过；目录一致性、隐藏 Commit、条件开关测试通过。

### P11-T02：导航元数据与版本

- 定义四项字段类型、枚举和覆盖规则；完整标注现有业务工具及新增 observe 工具。
- 更新 tool-discovery/tool-manifest Schema、mcp.Discovery、Gateway Manifest、Search 投影、双语分类导航和工具版本签名。
- 三元工具只增加 observe 枚举，不引入资源/信号输入筛选；更新 protocol revision 及失效测试。
- 主要位置：api/schemas/agent、internal/{mcp,toolgateway,toolruntime,agent}、生成契约。
- 完成条件：静态注册拒绝缺失/未知元数据；Search 仍完整列举；Describe/Invoke 顺序、撤权、上下文容量及缓存隔离通过。

### P11-T03：资源定位工具

- 扩展共享资源目录的类型、家族、集成、名称过滤与服务端分页；保证授权/筛选在分页前执行。
- 注册 observe/resources.list，复用 typed refs；应用服务与 K8s 子对象通过父级身份及现有领域工具解析。
- 补结果 Schema、双语说明、Presentation 和真实资源字段测试。
- 完成条件：五类查询引用、同名对象、多页、跨应用依赖、撤权、Namespace 重建均通过；无对象不能解释成无权限或全企业空目录。

### P11-T04：能力与来源导航工具

- 注册 observe/capabilities.get，有界组合采集事实、来源、仪表盘适用性与工具引用。
- 每节权限、状态、观察时间、分页和失败语义独立；不触发目标探测或无界遥测扫描。
- 仪表盘适用性规则实现为领域共享函数，供本任务和后继 T06 使用，不维护两个匹配算法。
- 完成条件：配置与采样状态不混同，部分依赖失败可解释，敏感字段不泄漏，最大批量与后端调用数有测量。

### P11-T05：数据目录工具

- 注册 observe/catalog.query，复用 ObservationCatalog 与 Recipes；普通资源读者无 dashboard.manage 也可发现自己的指标。
- 校验来源/版本/单位冲突、字段/值上下文、游标、时间、observed_only 和完整性。
- dashboard.catalog/catalog.resources 保留旧入口的场景与授权，收敛公共领域逻辑而非直接替换权限。
- 完成条件：实际 Receiver/SDK 数据目录与门户一致；支持但未观测、空样本、扫描预算失败不能被伪装为成功空列表。

### P11-T06：统一查询与仪表盘筛选

- 修改 metric/query、log/query、trace/query 以复用 QueryScope，严格与旧 resource_ids 互斥；保留现有查询语言和 APM 子视图。
- 修改 dashboard/list 的类型/对象/集成/信号筛选及适用性元数据，默认模板与自定义定义采用确定性匹配。
- 所有查询/目录/列表返回可信范围、来源、时间、版本和完整性；查询结果继续封存和 Workspace 交付。
- 完成条件：门户与模型参数/范围/实际数据一致，跨来源/Namespace/应用隔离通过；不同单位不会被无声合并。

### P11-T07：综合诊断与仪表盘任务范围

- 在开发前更新并评审 task_scope、已获取仪表盘、工作模式、access_mode 四者的契约，记录 D06 影响。
- 调整准入、Acquire、恢复、模型可用工具过滤、执行授权和预算，不仅修改一处 Policy。
- 普通诊断可使用仪表盘后继续三信号/告警；专门分析与创作保持限制，旧 Run 不自动扩大。
- 主要位置：internal/dashboardcontext、internal/conversation、internal/agent、必要 SQL/迁移、HTTP 与客户端。
- 完成条件：模式矩阵、输入后范围变化、重启/压缩/撤权恢复、模型试图自改范围等用例通过；真实任务不出现看图后卡住或越过用户约束。

### P11-T08：Chatbox 类型入口和共享业务视图

- 扩展 @、会话资源汇总、结果链接和 typed refs 的传输；资源选择按服务器分页，未知/撤权如实显示。
- 为三类 observe 结果提供共享视图；补应用/监控目标/来源的关键业务列、状态和导航。
- 明确实际查询条件与结果内筛选；复用图表、宿主表单、计划与操作确认，不新增平行组件库。
- 主要位置：web/apps/enterprise/src/components/{chat,observe,monitoring}、web/apps/template-runtime、web/packages/{ui,api-client,design-tokens}、internal/presentation。
- 完成条件：中英文×明暗×桌面尺寸、键盘、长名称/大量条目、刷新、重连、部分失败、实际路由跳转均通过。

### P11-T09：统一覆盖与隔离 E2E

- 生成“业务工具×交付方式×资源/来源×场景”的矩阵，自动比较生产注册与测试覆盖，修复当前 6 个缺失绑定。
- 先构建受控协议回放验证所有分支，再在临时 Kubernetes namespace 使用真实 API/采集链路、存储和浏览器测试。
- 录制新旧视图与当前源码版本，不能更新截图基线掩盖缺失状态。
- 完成条件：第 08 篇的协议、权限、对象、展示、恢复和数据链路门禁通过；专用临时资源归属清理、保护服务恢复验证通过。

### P11-T10：真实模型评测与发布准备

- 先用旧方案建立同样资源、问题和数据的基线，明确模型/版本、参数、语言、成本预算与冻结源码。
- 对照新方案的定位、正确查询、结论、用户交互和成本，保留失败与重跑，不以强制脚本调用顺序代替模型自主选择。
- 根据证据调整 capabilities 默认内容、路由提示和分类粒度；不能降低权限/证据门禁来提高成功率。
- 更新上游设计与所有执行指南，记录支持/暂缓/未验收矩阵，准备候选发布、回退与数据保留方案。
- 完成条件：硬门禁全部通过，质量门槛达到；部署仅在另行明确发布范围后执行。未部署时标记候选已验证，不写已上线。

## 3. 每项提交必须交付

业务实现、契约/生成文件、领域与鉴权测试、必要前端/真实 E2E、用户文档与证据索引。单个前后端源文件不超过 2000 行，模块高内聚低耦合。UI 只使用统一组件、token、模块 i18n；real 模式不回退 mock。

文档和状态变化不自动触发生产重建、正式数据清理或 Plan9 批次推进。开发期可不保留未发布协议的冗余兼容层，但实际运行/业务事实、撤权、历史封存和授权边界必须正确处理。

## 4. 验证命令的使用

盘点可复用 `go run ./scripts/tool-labels --catalog`。代码实施后按修改范围运行 Go 包测试、contracts 生成/检查、前端类型/i18n/style 与 Playwright；具体 argus-dev suite 及环境变量应从当时 CLI 帮助和 docs/ci.md 核对，避免把本计划中的候选名称当成已存在命令。

真实数据库、ClickHouse、对象存储、Receiver/SDK、Worker 和模型测试必须记录真实执行结果；skip 单独列出。纯文档变更只检查链接、格式、JSON、数量与差异；本轮包含业务代码，须执行对应分层验收。
