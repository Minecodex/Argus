# Chatbox 对象、业务视图与交付

## 1. 用户体验目标

用户描述“生产 Redis 内存升高”即可启动诊断，不需要理解 category、Tool ID、PromQL 或 Receiver 名称。对象歧义时询问业务对象；参数选择和执行范围以可读方式展示。工具调用详情保留技术信息供核查，不把内部路由步骤变成用户必须填写的表单。

用户可以自然语言提问，也可以 @ 对象提供精确身份。@ 不是必需前置操作，不授予权限；同名对象和失效引用必须重新校验。支持桌面 Web、中英文、浅色/深色；不增加移动端验收。

## 2. 对象入口与导航

| 对象                | 选择/汇总目标                              | 详情导航与限制                                      |
| ------------------- | ------------------------------------------ | --------------------------------------------------- |
| Host                | 现有能力保留，统一类型化引用               | 主机详情；控制在线与采集健康分开                    |
| KubernetesCluster   | 补 @ 选择，保留会话汇总                    | 集群详情                                            |
| KubernetesNamespace | 补 @ 选择与汇总，显示所属集群              | 当前集群/Namespace UID 页面；同名重建不能复用旧授权 |
| Application         | 补 @ 选择与汇总，显示固定环境              | 应用详情；服务名通过应用内授权候选选择              |
| MonitoringTarget    | 补 @ 选择与汇总，显示集成/网络域等公开信息 | 监控目标详情或现有监控页的精确目标入口              |
| Dashboard           | 保留选择与汇总，显示适用类型/模板标识      | 仪表盘详情；仅引用不隐式切换整个任务范围            |
| Connector           | 保留控制面引用                             | 保持代理详情/所属主机入口；不塞进遥测 QueryScope    |

增加共享的资源引用解析/显示适配器，统一 Composer、会话汇总、结果导航和来源标识。复用业务 API 与实际路由，不复制成第二套资源状态缓存；每次读取执行原权限。被删除/撤权时显示不可访问，不继续展示缓存中的敏感名称。

选择器支持服务端分页和名称过滤。分页接近底部时继续加载，保持搜索/类型/环境筛选交集，不以首屏候选当成全部资源。多词名称、中文、同名、长名称和键盘焦点需要覆盖。传给模型的是经宿主提交的结构化引用，不能只拼接一个名称字符串。

## 3. 新增/调整的结果视图

| 结果                     | 首屏主要内容                                        | 展开/交互                                                 |
| ------------------------ | --------------------------------------------------- | --------------------------------------------------------- |
| observe/resources.list   | 名称、资源类型、集成、环境、父级、返回数量/完整性   | 授权详情链接；本次封存结果筛选/分页                       |
| observe/capabilities.get | 对象、已配置/期望/生效/健康/新鲜度、状态时间        | 来源、适用仪表盘、不可用原因和缺少前件；不显示凭据        |
| observe/catalog.query    | 指标名、业务说明、类型、单位、来源/版本、观测状态   | 字段/标签值、推荐表达式及依赖；与 Plan10 使用相同数据语义 |
| 应用/服务                | 名称、环境、服务身份、实际信号状态                  | APM/日志/来源及授权关联信息                               |
| 监控目标/采集            | 集成、目标、采集责任、期望/有效版本、健康、新鲜度   | 配置公开字段、来源与采集诊断；敏感修改交给宿主表单        |
| 三信号查询               | 实际对象/来源/时间、查询状态、完整性                | 共享趋势/表格、日志详情、Trace/APM 图表及证据             |
| 仪表盘查询               | 名称、模板/发布版本、实际条件、成功/失败/未执行面板 | 冻结布局，面板独立状态和同一 Attempt 的结果               |
| 操作/计划/文件           | 目标、实际影响、确认状态、进度/文件信息             | 保持宿主确认、Markdown 计划与真实下载，不复制新的提交按钮 |

目录类型大多是 DataTable + FilterBar + 详情区，不为每个数据库建立平行 Card 系统。页面与模板共用 @argus/ui 的纯视图，Portal API adapter 与封存 Bridge adapter 分开。模板源码决定字段/布局；result_kind 只描述语义，不允许模型通过该字段选择任意 HTML。

## 4. 查询边界的可见性

每次查询显示服务端实际生效的资源、来源、时间/时区、筛选、采样/聚合口径、部分结果与数据时间；不得把模型请求值原样回显后当成实际执行范围。

“本次结果内筛选”只影响当前封存集合。更改时间、来源或对象需要新业务调用、新结果卡片，不能由只读 iframe Bridge 隐式发起。若增加“按这些条件继续查询”入口，只能提交明确的新会话意图并经现有 Agent/授权链路处理。

任务范围以业务文案显示：综合诊断、仅分析已发布仪表盘、创建/编辑仪表盘。普通会话不增加常驻切换栏或必选模式；用户主动限定时在本轮摘要显示限制。范围改变与执行/计划、请求审批/完全访问分开；不增加相互覆盖的模糊模式。用户能知道当前为什么无法继续某类查询。

## 5. 状态和错误

| 状态                            | 展示/模型含义                                    |
| ------------------------------- | ------------------------------------------------ |
| supported/candidate/deferred    | 产品能力与当前准入；不表示目标已有数据           |
| configured/desired/effective    | 配置与实际应用进度分别显示                       |
| healthy/degraded/failed/unknown | 既有采集状态，注明观察时间                       |
| observed/no_data/stale          | 指定范围内实际数据状态，不能与健康混为一谈       |
| partial/truncated               | 保留实际覆盖与上限，不显示成完整结果             |
| unavailable                     | 后端、运行时或目录暂不可用，提供原错误的安全说明 |
| forbidden                       | 使用现有权限错误；不得给出越权对象的详细信息     |

查询取消、Run 停止、Worker 重启、页面刷新、延迟结果抵达和查询条件变化都应保留事实来源。恢复仅显示原封存 Attempt，不重新执行查询冒充恢复。

仪表盘结果的部分成功说明在实际参数之后、面板之前直接可见，面板详情继续保留各目标的执行状态与错误。空 Span 详情和空拓扑使用共享组件的空数据说明，不显示一张空白图或把零条观测当作零耗时。该展示修正不改变查询、授权、冻结参数或原封存数据；模板内容 Hash 随实际源码更新。

## 6. 覆盖机制

生产注册目录生成 Tool Label、Schema 引用和交付声明。template/trace/file/action/interaction 各有对应测试，不要求所有工具都有图表。专用监控表单在可信宿主之外不出现输入凭据的平行表单。

每个模板用实际生成源码、公开 DTO 和边界数据校验；每种图型与不同结果结构单独覆盖。当前六个缺失绑定必须补齐，workflow.plan.propose/request_user_input/connect 走已有宿主测试路径。不能通过固定一个旧工具数量断言来声称覆盖当前注册。

## 7. 非目标

不把 /observe 临时面板保存成聊天查询组，不增加自动查询历史实体，不把后台页面嵌进结果 iframe，不让 AI 获得人工终端票据，不把客户 MCP HTML 作为自有展示。模型治理仍使用专用门户授权路径。

## 真实撤权后置验证

plan11-revocation 复用已有真实 SDK、同会话前后查询和源文件撤权路径，撤权期间用现有认证态运行四组中英文/配色门户检查。检查实际 @ 目录不返回撤权对象、保留另一对象可选，以及旧文件返回拒绝。组件回归另外模拟重新读取期间的缓存，验证旧详情/候选隐藏且下一页行保留；不能把页面重新打开后的实际 API 检查冒充同页跨撤权缓存测试。临时授权恢复沿原流程保证。

## 业务摘要与证据交付（D20）

默认将完整机器证据放在封存查询、工具结果视图和不可变报告中；最终消息简述已观测结论、范围/限制并引用实际交付。用户明确要求在最终消息提供 JSON 时，仍提供完整且经校验的结构。该分工复用既有 Workspace、发布文件、会话工具卡和下载能力，不新增工具、自动发布或对象选择表单。旧 strict_json_v1 失败不改写，delivery_summary_v2 另记验收版本；完整事实仍逐原件独立核验。

2026-11-01 用户已明确选择“业务摘要＋证据卡片/报告，完整 JSON 按需查看”。此项由此前的推荐假设转为确认的产品交付偏好。最终摘要保留实际资源、查询时间、来源和限制，引用真实卡片/报告；不要求重复抄写证据 JSON。明确请求完整 JSON 的会话继续按上述完整性规则处理。

## 引用的当前授权与重新读取（D26）

五类观测引用的候选、详情、汇总统一查已授权资源目录。管理后台能够读取对象元数据，不代表能在本次观测上下文继续解析其名称与导航。重新打开或重新检查时，旧名称和链接先隐藏，当前检查完成后再展示；检查失败显示不可访问。仪表盘/Connector 候选也按当前功能权限与读取状态隐藏缓存选项，私有治理不进入候选。该行为不声称在尚未收到状态更新或发起重新读取时能感知任意外部撤权；服务端每次读取/执行继续做当前授权。

目录续查的内部签名游标保留在原始参数及模型结果中，业务条件不直接展示长 Token；显示续查说明、实际筛选和结果完整性。共享模板与观测目录使用同一字段选择规则，避免重复区域漏处理。已有封存历史仍按原始不可变模板读取。

客户 MCP 的返回内容可作为文本和证据阅读，不能通过 display 字段声明为自有确认卡、模板或交付。快照、历史事件与实时事件使用同一来源校验；只有服务端记录为 argus 的自有调用使用原生展示控制。部分实时事件沿已有调用来源，不从工具名猜测归属。后端提交仍依赖原授权与确认链路。

压缩状态读取后端标准 estimated_tokens_before/after 并明确标注估算。统计缺失显示不可用，不能伪造为 0；后端明确返回零才显示零。压缩执行与生产预算策略保持独立，界面仅显示当前事件提供的公开统计，不显示内部摘要或提示。

D40 候选的能力详情用中英业务标签显示配置/生效采集器和归属待授权核对；Collector不是新增@类型或查询根。两ID可以不同，卡片不将其合并或推断Host/Cluster。12项三桌面宽度×中英明暗可见性验证已通过，仍不表示真实模型或正式部署已完成。

D41 候选：能力卡片根部显示本次未查询遥测样本的中英说明；该请求活动与采集配置、健康和历史数据严格区分。12项可见性检查通过，尚不表示真实模型复验已通过。

D45 候选：来源节区分本页来源数与版本项数，完整选择器保留；当前Collector代际不显示为SDK启用或健康。中英明暗三宽度可见性验证通过，长详情沿现有滚动展开机制。

仪表盘目录统一使用共享表格展示适用性、资源类型、信号、集成和版本；当前筛选及“未执行面板采样”提示可见，空列表不解释为没有遥测。目录条目缺少spec时展开元数据，不渲染虚假的空仪表盘定义。中英/明暗/三桌面宽度使用同一模板。task_scope仍显示在相应用户消息徽章中，刷新后保留历史限制；显式综合诊断仅改变后续任务范围。
