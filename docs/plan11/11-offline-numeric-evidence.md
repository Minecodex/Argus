# Workspace 数值证据助手

真实模型复核发现了三类问题：把首点当最小值、把 GB 的数值标成 GiB，以及手工转换时间戳出错。数值计算统一由标准 Workspace 镜像中的 `argus-metric-evidence` 执行，模型选择已授权数据并解释结果。它通过已有 `bash` 工具使用，业务注册目录仍为 133 项。

输入为已经交付到 Workspace 的原始数值型指标查询文件。`--unit` 使用实际指标目录中的源单位；助手依据文件计算输入 Hash、返回点数、首末评估时间、原值最小/最大值、显示单位换算和每条序列的标签与统计。

```sh
argus-metric-evidence /workspace/queries/metrics/QUERY_CALL_ID.json \
  --unit By \
  --expected-sha256 SEALED_RESULT_HASH \
  --json-out /workspace/results/evidence.json \
  --markdown-out /workspace/results/report.md
```

默认换算：`By` 除以 `2**30` 得到 GiB，其余单位保持原值。`1` 只表示无量纲，HTTP 状态码等也使用它，不能自动判断为比例。已经确认含义为比例时显式使用 `--transform percent`；比例可大于 1，例如负载比 2 显示为 200%。CPU idle 比例可显式使用 `--transform invert_percent` 计算 busy，此时全部序列必须为 `state=idle` 且观测值处于 0～1，混合状态取反会被拒绝。逐集成原值任务统一显式使用 `--transform identity`，字节也可保留 By。助手保留各序列标签，解释时仍须区分不同状态和设备。

该入口处理直接数值型 metric vector/matrix。混合指标名、缺少原指标名的变换表达式、Histogram、非有限值或超出有界大小的文件会返回明确错误，由对应分析方法继续处理。源单位来自调用方选择的授权目录，验收器仍独立核对其来源。输入查询文件不会被输出参数覆盖。

报告可在生成的 Markdown 证据之外补充能力、目录与分析说明，保留程序生成的 JSON 证据块。返回点评估时间与连续原始采样覆盖分别解释；趋势原因需要独立证据，缺少证据时写成待验证假设。旧或自定义 Workspace 镜像没有此命令时，按同样边界使用标准库计算。

验证包括本机标准库测试、Workspace 镜像构建中的测试，以及真实原件复算。`r11` 保存的内存查询被正确计算为 6 个评估点、2026-10-30T07:15:11Z、223526912～13445595136 By，即 0.2081756591796875～12.522186279296875 GiB；没有沿用模型误写的 10 月 25 日。

2026-10-31 的 v3 增加原件一致性校验。提供 `--expected-sha256` 时，必须与已封存结果的 Hash 相同；输出明确记录是否执行了这个校验，不把仅计算当前文件 Hash 当作封存证明。存在 `argus_meta.returned_rows/returned_points` 时，行数、点数和首末评估时间必须与文件数据一致；loaded_samples 是原始加载样本量，不参与求值点数等同判断。读取上限仍为 16 MiB。

r22 暴露了先查询六个内存状态、再复制并筛选 used 状态，却沿用原件元数据的情况。v3 会拒绝这种副本；需要只分析 used 时应在查询中选定标签，或另存明确保留父 Hash、选择条件和总体统计的派生分析，不能称为原查询总体。原 v1/v2 报告保留。新增校验的 13 项标准库回归及 23 份已封存原件的离线兼容复核通过；新版本的真实模型闭环另记轮次。

原指标和每个仪表盘target的程序证据新增可选evaluation_window，schema_version为argus.evaluation_window/v1。first_offset_seconds=首个返回评估时间减请求起点，last_offset_seconds=末个返回评估时间减请求终点，比较枚举before/equal/after分别表示早于/相同/晚于；正数晚于、负数早于。requested_duration_seconds与returned_span_seconds分别表示请求窗口和返回首末点的时间差，后者不是采样覆盖时长。不同UTC偏移与纳秒小数在标准库计算中按同一时间线比较，正文表格中英文一致。
