# Markdown 计划、命令授权与普通会话执行

日期：2026-10-18。状态：本轮实现、验证与本地部署完成。当前发布 `markdown-plans-20261018-r03`，Helm revision 40，schema 19，健康检查 20/20。

## 当前行为与架构

本页替代第 15 篇的“计划仅为指导”规则。计划是一份可下载的 Markdown 文档；用户确认该版本，同时批准其中明确绑定的远程命令。执行继续由 Harness 发起普通 connect 调用，记录按会话事件顺序展示，不强制附着或移动到计划下方。

- plan.propose 接收 markdown 与 command_bindings。服务端在展示前用 Markdown AST 提取明确的顶层代码围栏，格式为 bash argus:step_id 或 powershell argus:step_id；每个完整代码块对应一个命令批次。普通示例不授权；未闭合、重复标识、引用块和绑定不一致均拒绝。
- 冻结脚本、目标、接入身份、解释器、输入文件、顺序和上下文前件。平台解析的目标与账号补入文档，不能只相信模型的描述。批准事务同时保存确认消息、切换执行模式、创建实施 Run、激活授权并通过 Outbox 派发。
- connect 引用 approved_step_id，由服务器读取原始命令；该引用不能携带替换脚本或目标，且只绑定对应实施 Run。每步只执行一次，重复引用返回已有请求。前序未成功、上下文变化、撤权、资源／身份变化或停止均不能继续使用原授权。
- 新增或改变的命令按当前请求审批／完全访问规则处理。计划授权不会绕过账号权限、MFA、企业审批、输入来源授权和实际派发复核。确认来源区分 user、access_mode_policy、plan_approval。
- Migration 19 新增 plan_command_authorizations，并关联 PendingAction 与唯一远程请求；普通远程协议继续复用，不新增 Connector protobuf 字段。已确认文档不改变；旧计划不会自动获得新命令权限。
- 已执行的失败或未知结果保留事实，禁止自动重放。新方案重新授权。只创建过预览、从未开始远程操作的会话回收后，可以通过新预览取得新代次；旧授权随之失效。

输入快照只覆盖 Workspace 专用 input 中由平台封存的文件，不声称冻结了整个远端文件系统或能通过脚本解析证明风险。每个 Markdown 代码块是独立 connect，ARGUS_INPUT_DIR／ARGUS_OUTPUT_DIR 逐批更新；同一会话的变量、函数和工作目录延续。跨步骤文件保存首次生成的绝对路径变量，或使用明确批准的固定路径，或导入 Workspace 比较。该规则同时进入计划工具、connect 和 Harness 的说明。

## 展示

计划使用 Argus 的 Markdown 文档组件，描述和代码块全部展开，支持下载 plan-vN.md；不放执行输出、stdout 标题或停止按钮。未确认修订仅显示最新版本，已确认计划独立保留。确认和修改意见继续位于输入框面板。

普通命令只在待审批时显示完整目标、命令、输入文件和确认／取消按钮。确认后替换为一条可展开的工具执行记录；命令、输出、错误、退出码和文件在详情中显示。等待 MFA／企业审批保持真实等待状态。全局停止留在输入框。

connect 的受信 display 元数据关联待决动作和执行记录；旧事件使用平台记录的 action_ref 引用恢复关联，客户 MCP 输出不参与。只合并同一命令的重复成功预览；没有生成动作的失败准备调用仍保留独立失败记录。计划、问答摘要、工具及文件沿用相同聊天内容列。
