# 共享资源会话、隧道与文件传输

日期：2026-10-15。Q15 已确认改为：支持一批指令，整份计划及连续 connect 调用共享同一资源上的 shell／PowerShell 会话。此前「片段间不共享隐式状态」的建议已被用户替代。

共享会话、Q19 隔离范围、Q20 自动目录交换、Q21 暂停恢复、Q22 空闲回收和 Q23／Q24 仅模型上下文的并发感知均已实现并完成本轮验收。不同聊天同资源不做业务排队，不增加人类可见的并发提示。正式契约以 Schema／OpenAPI／protobuf 为准，实机范围与证据见[验收报告](./09-acceptance-report.md)。

## 1. 三层抽象

| 层 | 对 Agent 提供什么 | 平台负责什么 |
| --- | --- | --- |
| 资源会话 | 资源引用、会话引用、真实平台／解释器、当前状态 | 资源／身份绑定、活跃 shell/runspace、串行队列、会话代次与生命周期 |
| 执行批次 | 描述、一批完整命令、已有批准或待确认引用 | 冻结内容、确认、派发、输出分帧、完成回执、停止和未知结果 |
| 文件传输 | 按约定准备 Workspace 专用 input、将远端结果写入 output（Q20 已确认） | 自动清单、内容封存、权限、路径、大小／Hash、传输重试、完成发布和来源审计 |

对模型仍只有 connect 这个远程能力入口，具体操作可在其结构化参数中表达。底层并非只有一个不受约束的字符串执行函数；会话、命令、文件有独立职责、状态与执行记录。

平台封装 SSH 地址、跳板／隧道路由、编码、凭据、传输工具与重连细节。模型主要生成目标会话中的原生命令，不需要用本地 Workspace bash 拼接 ssh、scp、WinRM 或 kubectl cp 才能搬运文件。

## 2. 共享范围（Q19 已确认）

会话键包含当前企业／用户、Conversation、稳定资源 ID、接入身份、解释器，以及 K8s 必要的 Pod UID/container 定位。同一聊天内的排查与计划复用匹配的会话；跨聊天、跨身份或不同目标不共用。

「整份计划共享」在单一目标上对应同一个解释器上下文；跨机器计划按目标分别持有上下文，并串行调度。不能将十台机器描述成共享一个物理 shell。再次回到同一目标时，可继续使用其仍有效的原会话。

Kubernetes 必须区分集群命令执行环境与 Pod 内 shell：前者是受控的 Kubernetes 客户端执行上下文，后者固定到具体 Pod UID/container；集群本身不是一台可以直接登录 shell 的主机。具体适配方式在 T03 固化，不把两种身份和文件系统混在一起。

目录、变量、函数、别名、模块、PowerShell 对象等可跨获批批次延续。一次调用可以包含多条命令，但新批次仍须确认；会话持续不产生工具级、参数级、前缀或 24 小时免确认。

## 3. 上下文也是批准前件

同样的命令在不同目录、别名、函数或环境下可能具有不同效果。批准不能只绑定脚本文本，还要绑定它预期使用的会话和上下文版本。

建议分开保存：

- connection_epoch：当前传输连接的代次，沿用现有 Connector 围栏基础。
- session_generation：实际解释器实例的代次；重建解释器不能冒充原实例。
- context_revision / completed_sequence：已执行批次导致的上下文推进事实，不承诺完整序列化 shell 内存。

这些是概念字段，正式名字由 T01 固化。计划开始时校验当前上下文前件；获批计划连续运行期间，同一资源会话不得插入另一批命令改变上下文。单计划及同会话输入都串行，不因模型并行提出多个 ToolCall 而并行写同一个 stdin/runspace。

预览应显示资源、实际身份、解释器、已知目录、上下文代次及相关前序批次，支持查看有效公共参数。不得将有限上下文摘要当成完整语义安全证明，也不能把敏感环境内容直接送入模型。

当前实现把计划准备时的 `known_directory`、`interpreter_version`、`previous_request_id` 和 `previous_sequence` 作为服务端生成的冻结字段；模型输入不能指定这些字段。缺少获批执行观察时明确显示未知。目录是计划开始前的已知位置，后续片段可能受本计划前序命令影响，不承诺其在整份计划内保持不变。前序批次详情通过现有会话权限读取，不触发确认或执行。

## 4. 隧道、会话与执行结果

可以复用现有 Connector 主动 mTLS 长连接，但应新增 AI 执行会话与批次协议，而非让模型领取人工 RemoteAccessSession 票据。

传输需要：

- 可验证的会话／批次归属、帧序号、连接与会话代次。
- 控制消息、stdout/stderr 与文件数据的明确边界、限额和背压；大文件不能阻塞心跳和停止信号。
- 来自受信执行监督端的批次开始、完成、退出状态与停止回执。普通命令输出中的标记文字不能伪造完成或授权事实。
- 对未收到确定回执的批次进入未知状态并对账，不重新发送命令碰运气。
- 连接恢复后先核对原解释器是否仍存在及其已完成序号；传输恢复不等于进程上下文恢复。

共享 shell 不等于任意交互式键盘输入。模型只能提交完整、语法边界明确且已经批准的命令批次；不能利用未闭合输入、后台 stdin 读取等吞入下一份尚未批准的请求。解释器退出、上下文不可信和当前命令取消都必须产生可见状态。

## 5. 约定目录与自动传输（Q20 已确认）

2026-10-18 更新 Workspace 侧落盘：AI 在远端 output 内组织业务相对目录，平台收集到 `/workspace/results/<业务相对路径>`。请求／步骤／资源等 ID 只进入集中派生索引 `results/meta.json`，不再组成 Workspace 目录名。远端临时 input/output 仍按请求隔离；详见[结果目录契约](./19-workspace-results-and-metadata.md)。

采用固定逻辑 input/output 目录代替 AI 显式枚举文件：模型在 Workspace 专用 input 准备本次输入、编写命令并把需带回的结果写入远端 output，平台自动扫描、生成清单和传输；不要求每个文件都在 connect 参数中显式声明。

建议结构如下，不是已上线接口或最终物理路径：

~~~text
当前 Workspace 的专用输入暂存目录
  → 本次输入清单与不可变快照
  → 用户批准本次执行
  → 目标 <temp>/argus/<session-id>/<execution-id>/input/
  → 共享 Bash／PowerShell 命令进程执行
  → 目标 <temp>/argus/<session-id>/<execution-id>/output/
  → 执行结束后自动收集至当前 Workspace 的本次结果目录
~~~

「执行单元」为一次独立 connect 请求，或整份获批计划在某个目标上的执行；同一计划的各段使用同一个 input/output，而不同获批执行不得混入旧文件。输入只取当前 Workspace 的专用 input，不同步整个 Workspace；正式目录命名由 T01 固化并通过工具说明告知模型。

Linux／容器使用实际可用且经授权的临时根，Windows 使用实际执行账号的临时根；均创建受控、唯一的子目录。工具向模型提供本次实际路径，可通过 ARGUS_INPUT_DIR／ARGUS_OUTPUT_DIR 等约定变量表达，正式变量名由 T01 固化。Bash 与 PowerShell 的变量语法各自遵循原生规则。

新的执行单元不能为了换 input/output 就偷偷 cd 并破坏已确认的共享目录状态。平台冻结实际路径，采集器不跟随脚本改写的环境变量转而扫描任意目录。缺少路径权限或空间时明确失败，不改投其他目录。

自动传输作为本次命令／计划批准内容的一部分：卡片由平台显示输入摘要、可审查内容和 output 收集规则；不新增逐文件确认。批准后才创建远端目录和上传，不能以「约定目录」为由在确认前修改目标。输出最终内容尚未产生，不能提前伪造文件清单、大小或 Hash。

### 输入冻结

- Workspace 路径是可变副本。准备预览时复制到独立不可变对象，冻结内容 Hash、大小、来源权限与目标路径；执行不能重新读取同名可变文件。
- 脚本文件必须可审查，不能只显示「执行 file.ps1」而隐藏该文件的批准内容。
- 传输只改变物理通路，不授予目标账号原本没有的文件权限。

### 输出收集

- 用户批准本次目标、受控 output 目录及收集限额；目录内具体文件由执行结束后的实际扫描产生，不要求 AI 逐文件声明。
- 完成后记录实际字节数、Hash、资源、会话／批次、采样时间和完整性，再导入 Workspace。
- 来源授权在字节进入 Workspace 前登记，派生文件继续遵守既有来源依赖，不能靠复制文件洗掉授权。
- 成功后统一收集；失败／停止时可收集已完成的获批输出并标为部分结果。仍在写入、超限、消失或校验失败的文件应明确报告，不能把命令已结束等同于所有文件完整。

### 可靠性与路径

- 分块、校验、可恢复的传输状态与限额独立于命令状态；文件重传不能导致业务命令重跑。
- 远程输出与普通上传在受校验的字节流中采样识别媒体类型，文本扩展名不能覆盖二进制特征；未知二进制使用 `application/octet-stream`。平台查询文件保留 JSON 契约。文件卡片优先使用明确媒体类型判断预览能力，二进制仍可下载，不因 `.txt` 后缀尝试文本预览。
- 自动搬运仅覆盖当前执行单元的 input/output；不隐式写入生产配置路径，不用全局共享目录混合不同聊天或批次的数据。对业务目录的后续修改由已展示的命令及原有权限约束。
- 中间文件与完成文件分开；校验通过后再原子发布，避免命令消费半个文件。符号链接／Windows reparse point、路径逃逸和跨卷限制须在适配器里处理。
- 同一逻辑文件传输规则适配 Linux、Windows 和 K8s；不假设目标一定有 tar、scp、Python 或同样的路径语法。缺能力时明确不可用，不静默安装依赖或临时启动高权限辅助资源。

Kubernetes 官方说明 kubectl cp 依赖容器中的 tar，见 [kubectl cp](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_cp/)。这说明平台不能把「生成一条 cp 命令」当成完整可靠的文件能力。

## 6. 让模型生成短而准确的命令

会话应提供真实能力说明：平台、解释器及版本、执行身份、工作目录、文件根与可用程序／模块、编码、会话状态及传输限制。来源必须是已有可信资产事实或获批初始化得到的结果；未知字段不能编造，也不能为准备说明而运行未批准的任意探测命令。

按 Q20，模型使用工具告知的 input/output 路径或约定变量；上传下载由目录规则和平台自动清单完成，无须逐文件声明，也不需要重复写凭据、网络地址、Base64 或传输重试代码。

统一的是资源引用、文件输入输出、命令提交和结果结构。Bash 与 PowerShell 语法、Linux 服务与 Windows 服务操作仍有实际差异；平台应提供准确环境信息，不将一种语言静默翻译成另一种后执行。Windows 可参考 [PSSession 的共享状态概念](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pssessions?view=powershell-7.5)，但这不要求本计划新增公网 WinRM 或让 AI 管理 PSSession 凭据。

## 7. 暂停、分析恢复与续执行（Q21 已确认）

这里的「解释器」是实际执行命令并保持当前目录、变量、函数等状态的 Bash／PowerShell 程序。后续面向用户称「共享命令进程」。网络通道只是传递命令和结果，通道断开不必然意味着这个程序退出；程序退出后新建进程也不会自动找回原内存状态，磁盘上的既有副作用则可能保留。

执行时区分：

1. 仅控制链路短断、原解释器仍存活：核对身份、代次和批次状态后重连；不重放命令。
2. shell/runspace 已退出、目标重启或 Pod 被替换：旧上下文失效，停止剩余执行；新解释器使用新代次，不能标为原会话已恢复。
3. 用户停止／超时后上下文状态不明确：先标记不可信并阻止继续使用，不能把「停止请求受理」当作会话仍可安全续跑。

共享命令进程失效后暂停的是远程派发，不必禁止 Agent 思考。AI 可以使用已保存的命令、输出、文件、计划步骤、上下文记录和当前允许的平台查询，在 Workspace 中分析如何恢复。新的远程取证仍须 connect 确认，不能借「恢复」绕过按次授权。

### 恢复流程

1. 记录失效／不可信的会话代次，暂停剩余执行，保留原批准、原计划和实际结果。
2. 从持久事实分开列出已成功、结果未知、尚未执行的步骤；磁盘和业务副作用不会因命令进程退出而回滚。
3. 分析继续任务所需的目录、显式变量、模块、输入文件和其他前件；区分可从记录重建、需要重新读取及无法直接恢复的状态。不自动导出或保存全部敏感环境和进程内存。
4. 生成关联原计划的新恢复版本，包含必要初始化、当前状态核验、上下文验证和后续步骤；已成功的修改不默认重做，未知结果先对账。
5. 用户确认新增远程批次／恢复计划后，在新的会话代次执行。原批准不能直接迁移到不同的命令进程。
6. 验证必要上下文和当前资源前件后，只继续仍需完成的步骤；若恢复失败、证据不足或前件变化，再暂停并提出新的方案。

恢复的是足以安全继续任务的、可验证的上下文，不承诺原 PowerShell 对象、句柄或任意 Bash 内存能完全还原。可以重传已经批准且内容固定的文件，但文件恢复不得变成业务命令的自动重放。

原计划保持历史事实，新版本通过 recovery_of 等关联表达恢复来源，字段名在 T01 固化。用户主动停止／取消不触发自动恢复执行，只有用户再次要求继续才进入恢复流程。关闭页面本身仍不取消后台任务，与 Q18 保持一致。

## 8. 生命周期与跨聊天并发（Q22／Q23 已确认）

Q22 允许无活动执行时闲置回收共享命令进程和受控远端暂存目录，执行中不因闲置回收。任何清理都必须核对会话、执行与路径所有权，不能使用卸载清理删除用户业务文件；Workspace 已取回结果沿用现有持久规则，尚未收集的唯一输出不能仅因闲置被删除。回收后的新会话使用新代次，不能冒充旧上下文；默认闲置时长、最大保留量和异常清理策略由 T01/T03 明确。

Q23 允许不同聊天的独立资源会话同时操作同一 Host／Cluster，不因资源上已有任务而排队或取得资源独占锁。同一计划和同一个共享命令进程仍串行；Worker 领取租约、会话围栏、幂等和容量上限仍需保留，它们不等同于资源级业务排队。

Worker 的 remote_execution 队列默认每进程 8 个有独立租约标识的消费者，避免单个长命令阻塞其他聊天。停止未知结果的任务进入独立 remote_execution_control 队列，默认 2 个消费者，且该队列只接受 stop，不能借其派发命令。其余 Agent／Action／Compaction 队列维持原并发设置。Helm runtime.remoteExecutionWorkers／remoteControlWorkers 分别映射 ARGUS_REMOTE_EXECUTION_WORKERS／ARGUS_REMOTE_CONTROL_WORKERS；前者范围 1～64，后者 1～16。这是运行容量限制，不引入按 Host／Cluster 独占的业务队列，也不放宽单计划／同 shell 串行与批准前件。

### 仅模型上下文中的并发活动感知

1. 建立以 enterprise_id＋稳定资源 ID 查询的平台执行活动投影，来源是受控 Execution／Plan／CommandBatch 的持久事实，不读取其他聊天正文作为数据源。
2. 内部字段包括获准读取的资源／执行引用、正在执行的命令或摘要、阶段、最新状态及 observed_at，必要时包含获准使用的发起者引用；按当前权限过滤，不自动纳入他人聊天、完整脚本、文件内容、输出或私有凭据。
3. 预览、派发、步骤完成和执行状态变化更新服务端活动事实；Agent 下一次模型请求组装时读取最新快照，注入独立的只读上下文块。该块表达「当前资源还有执行 X 正在运行命令 Y」，不是面向人的提示。
4. 同时启动的任务可能先取得旧快照，再收到对方开始事件；必须保留时间和完整性说明。未知、更新延迟、权限过滤不能显示成「确定没有其他执行」。
5. 并发本身只提供信息，不自动增加确认、暂停、修改命令或阻止另一任务。权限撤销、会话失效、资源前件不满足等原有停止规则不变。
6. 并发摘要中的目的和命令属于不可信业务数据，不能变成系统指令或本次批准。修改本计划仍生成新版本并确认。
7. 不生成聊天可见消息、ToolCall/ToolResult、卡片、徽标、通知或并发活动面板；现有本次任务的批准／执行进度 UI 不受影响。内部投影与来源可以审计，但不通过普通聊天 DTO/SSE 内容泄露。
8. 不在历史中不断追加旧并发提示；每次模型请求按当前状态构建有界快照，过期／结束／无权内容不继续作为当前事实注入。未发生新的模型回合时，不宣称 AI 已完成主动评估，也不要求模型机械复述提示。

该投影表示 Argus 已知的受控远程执行，不能代表机器上的全部进程。人工会话、客户 MCP、外部控制器或直接登录的动作只有取得独立可验证证据时才能标为已观测，不能推断不存在。

现有 Conversation/ToolResult 的所有者隔离、Execution／PendingAction 的读取权限与资源裁剪并不完全相同。必须建立专门的活动投影服务、统一当前授权校验并验证各入口，不直接转发既有完整 Preview 或其他聊天的结果。

## 9. 当前可复用与缺口

- [Connector Connect 流](../../api/proto/argus/connector/v1/connector.proto)已有 mTLS、命令、结果、凭据与人工会话帧；尚无本计划的资源执行会话／文件传输契约。
- [人工会话](../../internal/app/connector/remote_session.go)可连续输入同一进程，但其授权、回执与重启恢复不足以证明 AI 按请求批准的共享会话已实现。
- [命令执行回执](../../internal/app/connector/client.go)及[未知状态对账](../../internal/connector/gateway.go)可复用；完成缓存不是任意副作用 exactly-once 的保证。
- [Workspace 文件交付](../../internal/workspace/files.go)可封存真实字节；[来源授权](../../internal/workspace/source_authorization.go)可复用到取回文件。
- 现有 Artifact 相关下载／安装通路不是任意 Workspace↔远端传输；需要新增正式文件操作、路径、批准和完成状态。

T01/T03/T04/T05/T06/T08/T09 必须覆盖这些新增边界；不能只完善 Prompt 或复用人工终端 UI 就将目标标为完成。
